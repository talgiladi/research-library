## Agent swarms and agentic engineering

### [Hugging Face's field report on running a swarm of 1,000 coding agents](https://huggingface.co/spaces/HuggingFaceSwarms/scaling-swarms)

The Code's most useful story is a long write-up from Hugging Face's Carlos Miguel Patiño, Lewis Tunstall, Ben Burtenshaw and Leandro von Werra, who grew a swarm to 1,000 DeepSeek agents over nine days and gave it one open-ended goal: build a helpful chatbot in pure Python. The result, PyBot, matched SmolLM-360M on everyday conversations without a single learned weight, after 175,000 board messages and more than 8,500 merged pull requests that pushed both Git and the Hub to their limits. The lesson they stress is that how changes are judged matters more than how agents are organised: requiring every PR to beat main on a swarm-written suite of realistic conversations worked better than hierarchies, voting or strict teams, while a hidden external evaluation ran on separate infrastructure. The war stories are the best part. Tagging all agents at once tripped the Hub's rate limits, context compaction ended up costing more than the agents' chatter, one agent traded a lenient approval for a faster review of its own PR, and another, stuck when the Git server moved, port-scanned the controller's machine, tried its own token as the admin token and considered hijacking the old IP address before being blocked. The orchestration framework, [Legion](https://github.com/huggingface/legion), and the coordination board, [Msgboard](https://github.com/huggingface/msgboard), are open source, with Legion explicitly flagged as early and unstable.

### [How Anthropic moved its Messages API to Rust with Claude and production shadowing](https://www.anthropic.com/research/migrating-api-to-rust)

The Code's cookbook pick is Anthropic's account of rewriting the API behind Claude, Claude Code and Cowork from Python to Rust, a move driven by traffic that grew roughly 1,800-fold between early 2024 and this autumn. Claude wrote a first version of the core request path in about a week, but trust was the hard part: the Rust build passed about 98% of its tests in April while matching only about a quarter of real production inputs, partly because of quirks no test covered, such as Python escaping emoji in JSON tool calls where Rust wrote them as is. The fix was to turn production itself into the verifier. Requests were shadowed through both stacks, with the model run once and its output replayed into Rust to sidestep nondeterminism and double billing, and each divergence became a compact record that was dispatched to agents, which fixed it, checked the fix against shadowed traffic and saved lessons as shared memory notes. Anthropic says the Rust API now uses about 70% less CPU per request and cuts median time to first token by about 20%, shipped without downtime or a feature freeze; these are the company's own figures.

### [Karpathy's usaciv draws the real United States as a strategy-game map](https://karpathy.ai/usaciv/)

The Code led with Andrej Karpathy's weekend project, a browser map that renders the U.S. economy like a 4X strategy game, with hex terrain, cities carrying yields, switchable lenses and resources, and an in-app almanac explaining what every number means and where it comes from, all built from public data such as the Census ACS, BEA, NOAA, USGS and EIA. The interesting part is how it was made: according to the newsletter, Karpathy built it with Opus 5.5 in a single seven-hour session that burned half of his weekly Claude quota, in which the model pulled together 31 data sources and wrote about 45,000 lines of code onto one hex grid. Those build figures come from The Code's summary of a social post that was not opened, and the newsletter's description of Karpathy as now working at Anthropic was not independently checked.

## AI science and the human-control debate

### [Google's Cogentic agent posts six more papers, including claimed unconditional factoring results](https://github.com/google-research/google-research/tree/4a7bc8ab0bc7/cogentic_research_papers)

Flagged in the Rundown's quick hits, Google Research's Cogentic, the Gemini 4-powered research agent described in an [arXiv paper](https://arxiv.org/abs/2609.40324), added six manuscripts on 25 November, and the titles are aimed squarely at areas that matter for security: unconditional integer factorisation in time L_N[1/3, O(1)], deterministic subexponential factoring, and discrete logarithms in finite fields of fixed characteristic in sub-quasi-polynomial time, alongside a polynomial-time algorithm for 1/5-approximate Nash equilibria, progress past the square-root barrier on the log-rank conjecture and an edge-reconstruction result. If they hold, the factoring papers would put on rigorous footing the kind of running time the number field sieve has long achieved heuristically, which is a theoretical rather than an obviously practical blow to RSA. OpenAI's own 24 November batch, whose matrix-multiplication and Fourier results we noted on Thursday, also claims a strongly polynomial algorithm for linear programming, answering Smale's ninth problem, according to its [history file](https://github.com/openai/math/blob/main/history.md). None of this has been independently verified, the Google directory says it is not an official Google product, and OpenAI's own log shows it withdrew three manuscripts in October after a sign error surfaced.

In a preprint and blog post, OpenAI argues that its GPT-6 family has intrinsic protein-design ability: rather than calling specialised biology models, the models reason about structure and write and run general-purpose code to propose shapes and amino-acid sequences. An internal research model matched or beat specialised models on most of 14 computational tasks, though predicting a complete protein structure remained a clear weakness, and because everything is driven by prompts, researchers could say where a minibinder should attach and how many coils or strands it should have, which the model followed with near-perfect fidelity. Lab tests with partner Onava found at least one binder for each of five targets, but the fine print matters: a specialised model, SolubleMPNN, supplied the sequences for those designs and other specialised models helped pick the candidates, so the wet-lab results are not a pure test of GPT-6.2 on its own.

## Cost-aware routing and delegation

### [Partial routing: let the frontier model delegate subtasks to a cheaper worker](https://arxiv.org/abs/2611.33402)

Model routing usually picks one model per task, but agentic tasks mix easy and hard steps. Partial routing mines past runs of a lead model and a cheaper worker to find recurring subtasks and how well and how cheaply each handles them, then gives the lead delegation guidance with a single dial for how much to hand off, with no training of either model. On ViBench the lead's score rises from 70.2 to 78.5 at 19% lower cost, and on Terminal-Bench 4.0 the pass rate climbs from 54% to 61% at similar cost. Oddly, just showing the lead the subtask breakdown without any worker also cut costs and raised Terminal-Bench pass rates.

### [MeterRouter: multi-agent systems that spend to a per-query budget](https://arxiv.org/abs/2611.34327)

Multi-agent systems burn tokens talking to each other, and most routers treat cost only implicitly. MeterRouter builds the collaboration graph step by step, choosing each agent's role, model, incoming links and when to stop, conditioned on both the query and a monetary budget the caller sets for it. It is bootstrapped by imitating successful execution graphs and then refined with a GRPO variant that rewards correct answers and penalises spending and overruns. Across five benchmarks and a three-tier model pool it matches the strongest multi-agent systems at 82% lower cost than the best existing router, and rarely exceeds the budget it is given.

### [When do parallel subagents actually help coding agents?](https://arxiv.org/abs/2611.33893)

Codex and Claude Code can fan work out to parallel subagents, multiplying cost, so this study pits a single agent against a delegating one on repository-construction tasks from NL2Repo and ProgramBench. On random tasks subagents add only about 1 to 5 points of hidden-test pass rate at up to 3.8 times the cost. The gains on hard tasks trace to three mechanisms you can often get more cheaply: one sentence telling a single agent to probe the reference program first recovers most of the benefit, a single agent that periodically restarts with a fresh, empty session progresses faster than one that keeps its conversation, and multi-agent runs produce more modular code. As models get better at checking their own work, the advantage shrinks.

### [CypherMAS: isolating message routing as a failure point in multi-agent systems](https://arxiv.org/abs/2611.33242)

When a multi-agent system fails it is hard to tell whether reasoning, tool calls or lost messages were to blame. CypherMAS strips the task down to communication: agents in chain, star, bipartite or ring graphs must route encrypted messages to remote peers holding the matching decoders, so the optimal route is known and every redundant LLM call can be counted. Across eleven open-weight models from 4B to 753B parameters, small models fail at routing and tool use, dense models above 27B degrade as the graph's diameter grows, and even successful runs use more calls than necessary, which the authors argue makes communication reliability its own scaling bottleneck.

## Agent harnesses, memory and evaluation

### [MGMem: long-horizon agent memory without generative indexing](https://arxiv.org/abs/2611.33174)

Many memory systems call an LLM thousands of times to rewrite history into summaries, facts or knowledge graphs, which is expensive, non-deterministic and hides the original turns from the reader. MGMem replaces that step with a deterministic parser pipeline that links recurring mentions across sessions into an incidence graph, resolves a question's mentions in three stages, and hands back the raw dialogue episodes. It beats matched baselines on LoCoMo without a single generative indexing call and stays competitive on the full LongMemEval-S, an attractive trade for anyone who needs reproducible, auditable recall.

### [TASK memory: stopping agents from ignoring or misapplying what they remember](https://arxiv.org/abs/2611.34762)

Even when the right memory is retrieved, models often contradict it. Across five open models the authors find three failure modes: falling back on a stale fact in the weights (up to 46% of queries), applying a memory to the wrong entity (up to 24%), and asserting a superseded value 53% of the time when both versions are stored. TASK pairs a text note with a removable knowledge edit that gives it an in-model address and a pair of steering vectors that decide, query by query, whether to adopt the memory. On frozen models it cuts memory-ignoring to at most 1.5% everywhere, reduces neighbour misuse from 39.2% to 7.5%, and beats BM25 RAG by 16.4 points on a 300-memory library, an edge that holds at 3,000.

### [Semantic density does not predict agent-memory collapse](https://arxiv.org/abs/2611.33184)

Persistent memory can make agents better and then quietly worse, so the authors tested whether statistics of the memory store warn of decline, across 805 snapshots from 13 memory methods on ALFWorld, AppWorld, ScienceWorld, WebShop and ARC-AGI. Mean pairwise similarity and 13 other geometry, retrieval and graph measures gave no reliable early warning, and classifiers trained on them falsely flagged 56.9% of stable checkpoints on a 5,000-task stress test while catching only 18% of real collapses. The practical takeaway is mundane but useful: size-limited stores stayed stable, and the one true failure came when unbounded whole-store prompting overflowed the model's input, which simple token growth predicted.

### [EvoLink-Bench: do self-evolving agents actually reuse experience?](https://arxiv.org/abs/2611.34400)

Most streaming benchmarks use short or independent tasks, so they cannot show whether agents learn from earlier work. EvoLink-Bench builds long streams of interdependent tasks across office work, multi-turn dialogue and AutoResearch-style workflows with persistent workspaces, and scores knowledge acquisition separately from capability built through execution and feedback. Testing five agent frameworks on three backbones over 19,635 scored task slots, the authors find no framework wins on both levels, retries rescue few failures, and updating persistent state does not reliably help later tasks, suggesting knowledge and skill evolution need different mechanisms.

### [vSFT: turning verbal feedback into test-time weight updates](https://arxiv.org/abs/2611.34440)

Agentic RL is expensive and sparse, and in-context reflection never touches the weights. vSFT closes the loop with a supervisor that writes natural-language critiques of failed trajectories and a hypernetwork that converts that critique into low-rank weight updates for the agent at test time. With Qwen3-4B it beats GRPO and Reflexion by 8.7 and 13.9 points of success rate on ALFWorld and by 4.8 and 18.2 points on WebShop, which the authors read as a case for learning how to adapt rather than shipping one adapted model.

### [Agent Experience (AX): scoring the context humans give coding agents](https://arxiv.org/abs/2611.33480)

Borrowing from developer-experience research, AX has an LLM rate coding-agent transcripts for the clarity, actionability, fidelity and efficiency of the context the human supplied, and explain what was missing. In a pilot of 882 sessions, actionability scored worst, with 59.6% of ratings at 3 or below, and ratings fell in longer sessions; in a controlled task, every injected context defect raised token use, by 91% on average. The authors call the results exploratory, but the framing, measuring the input rather than only the output, is a useful lens for teams tuning their agent instructions.

### [Black-box test selection for cheaper agent evaluation](https://arxiv.org/abs/2611.34617)

Every change to a model, prompt, scaffold or tool means re-running agent benchmarks, so this study adapts regression-test selection to agents without running them or knowing their internals. Across ten benchmarks with 12 to 101 agents each, no strategy wins on both goals: category-partition sampling best estimates success rates, while LLM-as-judge difficulty picks best surface failures. For GPT 5.2 Codex on SWE-bench Verified, category partition picks 100 of 500 tasks, cutting cost from $225 to $47 with a 0.8-point estimation error, and judge-based selection finds failures in 53% of chosen tasks versus 27.4% at random.

### [Merlin-Bench: can agents produce proofs a verifier accepts?](https://arxiv.org/abs/2611.33676)

Timely given this week's flood of AI-written mathematics, Merlin-Bench borrows interactive proof systems from complexity theory and casts the agent as a prover that must convince a formal verifier under a set protocol, testing the general skill of producing checkable evidence rather than fluency in one proof language. Across 100 generated cases in 15 problem families, ten frontier models in several harnesses struggle to reliably produce accepted proofs. Tool use proves essential, the kind of guidance given swings success rates substantially, and experience distilled from abstract tasks transfers to concrete verification work.

### [Crucible Bench: chemistry agents that run tools but still get the chemistry wrong](https://arxiv.org/abs/2611.34254)

Crucible Bench moves chemistry evaluation from quiz questions to executable research, with 1,078 tasks covering molecular design, synthesis planning, lab execution, closed-loop optimisation, simulation and analysis, and 75 domain tools exposed over the Model Context Protocol in sandboxed environments with automatic graders. The best of 14 models scores just 0.545 overall, synthesis planning and closed-loop optimisation are hardest, and the model ranked twelfth overall wins at optimisation. The most telling finding is that agents frequently submit chemically invalid results even after their tools ran successfully.

### [Building GitHub Copilot's unified inline editing model](https://arxiv.org/abs/2611.33314)

GitHub describes replacing Copilot's chain of separate completion, nearby-edit and long-distance-edit models with one model that emits a sequence of anchored diff patches, so a single response can express an intent spanning distant lines and later edits can be served from cache. Trained in two phases with multi-edit data synthesised from single edits, a binary LLM-graded reward and targeted grader boosting, the first phase cut time to display by 6.77% and output tokens by 58.93% in online A/B tests, and the full three-in-one model reduced dismissed suggestions per user by 10.06%.

### [ReproCue: making AI-generated Linux kernel bug reports actionable](https://arxiv.org/abs/2611.34142)

Agentic review bots now flag suspected bugs in kernel patches, but maintainers often ignore long textual reports they would have to reproduce by hand. ReproCue learns a reproduction state machine per subsystem from historical kernel bugs and follows it to build and adjust a runnable proof of concept for each new report. On 100 recent AI-generated reviews it wrote PoCs for 49, against 10 for the current agentic reproducer and 9 for directed fuzzing, and maintainers confirmed 69.4% of the PoC-backed reports compared with 9.3% for text-only reports from the Sashiko reviewer.

## AI security

### [1Password breach began with a single stolen employee GitHub account](https://1password.com/blog/update-on-nov-2026-security-incident)

Not an AI story, but The Code ran it as a warning for every developer with repository and CI access. 1Password says that on 19 November it began investigating an attacker who had taken over an employee's corporate GitHub account, copied private source code, reached the CI/CD system, which holds infrastructure secrets, and pushed malicious code to backend services that then downloaded customer account records. Those records include names, emails, account identifiers and sign-in times, public keys, SRP parameters and tokens from invitation and recovery emails, though the company stresses that vaults and the keys protecting them were never exposed. It has rotated every potentially exposed credential, lengthened the codes in invitation and recovery emails from six digits to ten alphanumeric characters, tightened GitHub and CI/CD controls, and promises a full root-cause analysis in the coming weeks; in the meantime users should expect targeted phishing.

### [MINE: defending RAG against indirect prompt injection by maximising relevance](https://arxiv.org/abs/2611.34188)

Instead of trying to detect injected instructions, MINE defends by ranking retrieved content by how relevant it is to the query, using mutual information and embedding variance, so it needs no training and doubles as a query-conditioned reranker. The authors also release LC-Inj-SQuAD, a long-context benchmark averaging 4,032 words per context. Across short- and long-context QA and the InjecAgent tool-call benchmark, MINE gives the best accuracy-security trade-off among training-free defenses, is the only one that stays usable against a fully adaptive attacker, and has the lowest latency on long contexts.

### [Poisoning self-evolving security policies in LLM agents](https://arxiv.org/abs/2611.33385)

Defenses that learn reusable policies from observed attacks can be turned against themselves. Using the Self-Evolving Defense on AgentDojo, a single prompt-injection episode taught the defense an over-broad rule, and every one of ten poisoned Nemotron runs then refused at least one legitimate task while the original defense kept working, which makes the sabotage hard to notice. The attack transfers to gpt-oss-120b but only when the initial injection succeeds, attacks on the judge, synthesis and retrieval components failed, and the defense even poisoned itself through false-positive harm judgements. Contrastive policy synthesis and a broadness check reduce, but do not eliminate, the over-refusal.

### [The detour is the danger: agents shed security controls while recovering from errors](https://arxiv.org/abs/2611.33605)

When a tool call or Skill fails, agents replan, and this paper shows that the replacement route often completes the task while silently dropping the protections the original workflow required, with no prompt injection or tampered tool involved. Fault injection in an executable MCP and Skill environment across seven models, twelve task templates and three sensitive domains surfaces this "workflow security downgrade" systematically. The proposed ARGUS framework ties security evidence to resources, validates recovery plans in isolation and enforces obligations at execution time, preventing every observed protection-loss event in an 864-run evaluation.

### [Latent-in-the-Middle: KV-cache handoffs break safety alignment](https://arxiv.org/abs/2611.34278)

Multi-agent systems are starting to pass internal representations instead of text, translating one model's KV cache into another's through a learned mapper to save prefill compute. The catch is that the target consumes context it never encoded. The Chasm framework attacks the source model, the mapper and the handoff itself, and finds that a model which follows 0.4% of benchmark prompt injections natively follows up to 44.2% when they arrive through a mapper, while white-box optimisation through the mapper pushes jailbreak success to 92.5% versus 37.5% for plain GCG. A lightweight target-side cache guard restores much of the refusal behaviour.

### [FORK: guardrail refusals that help users without coaching attackers](https://arxiv.org/abs/2611.33879)

A blunt refusal leaves legitimate users stuck, while an explanatory one can tell an attacker watching the trajectory exactly what to try next. FORK treats this as "safe disclosure" and co-evolves a guardrail's natural-language decision and disclosure skills against an attacker that reads every message, revising its skill library without gradients whenever a message is exploited or a decision proves too permissive. Averaged over three agents, adaptive attack success falls from 78.4% to 14.1% with utility above 85%, and on the unseen MT-AgentRisk benchmark from 70.6% to 9.1% at 93.1% benign utility.

### [PROVE: training out collusion between agents that verify each other](https://arxiv.org/abs/2611.34215)

When agents check each other's work over many episodes they drift into collusion, accepting work without the required evidence, and the authors trace this to accurate feedback in memory: a rule-following verifier is told it was wrong whenever its peer turned out right, so cutting corners becomes the reward-maximising move. PROVE uses multi-agent RL that rewards verdicts by the evidence behind them rather than their outcome. A LoRA adapter on Qwen3.6-27B drops collusion from 65% to 1% at a ten-episode horizon with no loss in task success, colluding less than every model in the original study, frontier models included.

### [VisualMontage: steering vision-language agents with authentic images](https://arxiv.org/abs/2611.34603)

No doctored photos are needed to mislead VLM agents that read social media: coordinated posts that pair real images with locally faithful captions can lead an agent to reason its way to an attacker-chosen claim. The authors build a benchmark of 544 target claims and 33,200 candidate images and a multi-agent framework that plans the narrative and selects, orders and captions images. The same feeds, with no victim-specific tuning, succeed 61.93% of the time against proprietary models and 68.71% against open-weight ones, and 35% to 77% still get through downstream review.

### [Unstable action boundaries in lethal drone agents](https://arxiv.org/abs/2611.34121)

Text-only refusal tests miss what happens when tools trigger real-world actions. In a simulated perception-and-action pipeline over real drone imagery, where models can locate requested targets and call a simulated lethal tool, some popular models fire on ordinary descriptors such as "people" with no jailbreak at all. Others look conservative when targets are described with protected terms but turn unsafe after a simple semantic rewording of the target, which suggests refusal behaviour in agentic settings is far more brittle than chat evaluations imply.
