## Agent memory

### [Action Conditioned Bisimulation For GUI Agent Memory](https://arxiv.org/abs/2609.38778)

Zhang, Song, Li, Yang, Wen, and Yao notice that GUI memory keyed on *observation* similarity merges pages that look alike but answer the same click differently—two tabs of one widget, two rows of one menu. They replace the merge rule with an action-conditioned bisimulation over the empirical predictive state graph a frozen agent fills as it acts: states merge only when shared actions lead to agreeing outcomes and successor blocks under an affordance label, with no observation similarity and nothing trained. Dropped into an existing outcome-value memory, closed-loop MiniWoB++ lifts success over a memoryless agent, while controls with identical exploratory detours, a prior successor-representation merge, and the same criterion without action conditioning change nothing. Affordance-merge note for Tal: merge GUI states by action→outcome bisimulation—don’t equate visual similarity with behavioral sameness.

### [TAGGRAPH: Tag-Augmented Graphs for Graph Retrieval of Agent Persistent Histories](https://arxiv.org/abs/2609.38353)

Chen, Liang, and Xie argue agent memory systems are hard to compare because representation, indexing, retrieval, and eval usually move together. They hold 5W-style conversational memories fixed and vary only graph traversal: localized configs over a shared base graph, AdaptiveGraph with chronological edges plus Personalized PageRank diffusion, BM25 over the same notes, and OpenClaw as a raw-input reference. Rankings flip by setting—on LongMemEval-S AdaptiveGraph leads graphs at 0.844 MRR but BM25 hits 0.867 and OpenClaw 0.880; on ATANT Core localized traversal beats diffusion and BM25, while BM25 wins stress rounds—and missing extraction tags dominate top-five misses. Graph-vs-lexical note for Tal: evaluate graph retrieval against BM25 on the same notes—don’t declare graph memory better without the lexical baseline.

### [How Can Recommendation Feedback Evolve Agent Memory?](https://arxiv.org/abs/2609.37544)

Mao, Li, Zhang, Li, Wang, Yu, and Zhu treat delayed recommender outcomes—impressions, clicks, conversions, negatives—as the fitness signal for a content-generation agent’s memory bank, even though attribution is confounded by audience, placement, and policy and may span multiple memories. TIDE (Trajectory-Informed Directed Memory Evolution) plus Memory Evolution Gain (MEG vs a no-memory baseline on future tasks) does temporal/semantic credit, responsibility credit over memories referenced at generation, then reinforce/crossover/mutate/evict under a capacity constraint. On an e-commerce membership agent it posts +7.75pp MEG in offline temporal replay and lifts UCTR and activation in an online A/B; on a delayed-label bench it leads MAE/RMSE/MEG. Delayed-feedback note for Tal: evolve memory from attributed recommender outcomes, not only immediate semantic hits—don’t treat click noise as unusable.

### [Auditable Long-Term Memory: A Deterministic Retrieval Chain Measured at 479/475 of 500 on LongMemEval-S](https://arxiv.org/abs/2609.38021)

Chanhnourack ships an auditable long-term memory chain—hybrid candidates, cross-encoder rerank, coverage-first packet compilation, deterministic scaffolds—with the LLM only a replaceable final reader, and releases packets, scaffolds, outputs, and controls for re-scoring. Gold sessions land in the candidate pool for 468/470 answerable questions and gold-complete packets for 462/470; two Claude Opus passes score 479/500 and 475/500 under GPT-4o judging (straddling Chronos High’s published 478), while a maximum-reasoning agentic reader on the *same* packets regresses to 461/465. All components were developed on the same 500 questions with no held-out set, and knowledge-update rows used a modified scoring prompt. Audit-chain note for Tal: separate deterministic retrieval packets from the reader—and don’t trust a single LongMemEval headline without released packets and judge agreement.

### [Learning to Retrieve Missing Evidence for Long-Term Memory QA](https://arxiv.org/abs/2609.37443)

Deng, Zhang, Liu, Xue, and Yang observe that long-term memory QA fails when evidence is scattered and the question omits the clues needed to find it—yet already-retrieved facts can expose those clues. MERA (Missing-Evidence Retrieval Augmentation) keeps globally searchable memory separate from a question-specific evidence state, lets verified evidence steer the next query without walling off the global store, and RL-trains a 0.6B planner to recover previously missing evidence. With Qwen3-30B for evidence/answer and that small planner it hits 77.40% on LoCoMo and 71.29% on LongMemEval-S—beating a 30B planner without retrieval-grounded training by ~4pp—and LoCoMo cumulative evidence recall climbs from 55.5% to 80.5% across later rounds. Missing-evidence note for Tal: train the retriever to chase what’s still missing given verified evidence—don’t one-shot retrieve from the bare question.

### [CoEM: Empowering Long-Context Reasoning with Commit-on-Evidence Memory](https://arxiv.org/abs/2609.36935)

Li, Wu, Guo, Ma, Dai, Zheng, Chen, Li, and co-authors attack premature compression in chunked long-context pipelines that keep a bounded textual memory: once you compress, you can’t get the detail back. Commit-on-Evidence Memory (CoEM) parks potentially useful source excerpts in a *pending* set under a fixed context-memory budget; a learned policy later promotes, retains, or discards each excerpt as new context arrives, and a frozen verifier accepts proposed facts only if supported by retained excerpts plus current context. RL mixes step-level evidence rewards with final-answer reward. On 6,400-document inputs CoEM beats the strongest memory baseline by 10.4–11.4 F1 on Qwen3.5-9B. Commit-later note for Tal: delay irreversible compression until evidence earns a commit—don’t fold every chunk into memory on first sight.

## Agent harness

### [AgentBug-Smith: Automatically Reproducing Real-World Harness Bugs in Agentic Systems](https://arxiv.org/abs/2609.37864)

Cheng, Rahardja, Zhang, Chen, Chen, and Lou argue harness bugs are a distinct failure class that today’s software agents struggle to repair, while existing benches are tiny, fixed, and human-expensive to build. AgentBug-Smith continuously discovers and reproduces real-world harness bugs from open-source agentic systems—10.67–27.56pp higher reproduction success than general-software bug-reproduction baselines—and yields Live-Harness-Bench (200 reproducible bugs and growing). SOTA repair agents look weak on that live set; distilling reusable repair skills from the fix knowledge base lifts harness-bug repair rates by 6.32%. Harness-bug note for Tal: treat harness bugs as a live, auto-reproduced bench—don’t wait on hand-curated static harness suites.

### [MILO: Automated Harness Discovery via Orchestrated Multi-Agent Evolution](https://arxiv.org/abs/2609.38349)

Jana, Goswami, Liu, Li, Huang, and co-authors treat the harness—not just the model—as the long-horizon lever, and note that hand search must be redone as models change. MILO co-evolves complete harnesses *and* the discovery strategy: hierarchical lineage memory over island trees (rejected mutations as negative evidence), per-island mutator agents that rewrite whole harnesses from global history, and an orchestrator that grafts lineages, reassigns mutators, and revises curriculum. With Opus 4.8, MILO-discovered harnesses beat eight SOTA harnesses and six search methods (+12.0 / +28.3 / +10.3pp resolution on Terminal-Bench 2.1 / PaperBench / DeepSWE vs prior-search bests of +4.5 / +18.3 / 0), hit 86.1±2.0% on Terminal-Bench 2.1 above the official top entry while using 26% fewer tokens than the initial harness, and tighten EinsteinArena open bounds. Harness-search note for Tal: co-evolve the harness and the search policy—don’t only tune prompts/skills inside a frozen scaffold.

### [Do LLM Agents Execute the Plans They Declare? From Planning-Mode Declaration to Pattern-Specific Execution](https://arxiv.org/abs/2609.38108)

Oota, Herrera, Cabot Sagrera, López de Prado, and Khan separate *selecting* a planning mode from *executing* it faithfully—final task success alone cannot tell those failures apart. Planning-as-Routing has the LLM declare Predefined / Sequential / Hierarchical / Search, then a deterministic router dispatches to a pattern-specific executor. Across four benches and three LLMs, generic Plan+ReAct preserves declared structure in only ~22–45% of trajectories on three benches, while pattern-specific executors enforce it; best mode flips by environment (Search on ALFWorld, Hierarchical on SWE-bench) and even by model within a bench; execution lifts ALFWorld success 0.48→0.92 and SWE-bench Verified 0.36→0.44 over Plan+ReAct, yet mode *selection* still lags. Plan-execute note for Tal: route declared modes to pattern-specific executors—don’t trust Plan+ReAct to keep the structure it announced.

### [FOCUS: Training-Free Decision-Preserving Context Compression for LLM Agents](https://arxiv.org/abs/2609.37590)

Dixit, Bastos, Zhang, Bansal, and Rajmohan reframe agent context compression as *which past interactions causally shape future decisions*, not offline “what to discard” policies that need data and freeze before test-time trajectories. FOCUS is training-free and architecture-agnostic: attach at test time to closed-API frontier models as a modular layer that preserves decision-relevant interaction units. Across API/tool-calling, QA, web, and multi-turn dialogue it cuts peak context up to 48% and dependency 73% while *raising* task success up to +8.9pp over uncompressed execution. Decision-preserve note for Tal: compress by causal decision preservation at test time—don’t pay offline compressor training that can’t see the live trajectory.

### [When Correct Memory Goes Wrong: Fuzzing Persistent Memory Use in LLM Agents](https://arxiv.org/abs/2609.38275)

Meng, Tang, Zhang, Yang, and Xi fuzz the case where memory *content* is fine but *use* fails when queries shift or memory state evolves—query-related vs memory-state failures that fixed test cases miss. U-Fuzz seeds from memory checkpoints, mutates queries or memory under explicit obligations, validates mutants, and guides search from observed memory behavior while keeping failure labels out of the loop; it also works output-only when retrieval is hidden behind API LLMs. Across several memory systems and baselines it consistently finds more confirmed memory-use failures. Memory-use fuzz note for Tal: fuzz query×memory-state use, not only poisoned content—don’t assume correct stores imply correct retrieval-under-shift.

### [Can Agents Trust Their Skills? Uncovering Unsafe Chains of Trust in Skill-Based LLM Agents](https://arxiv.org/abs/2609.39065)

Wang, Zhang, Chen, Chen, Zhang, Ma, Dai, and Sun map the trust chain in installable skills (instructions + code + resources auto-invoked later): users delegate authority to agents, frameworks admit skill content into context with thin validation, and malicious skills ride that authority. TrustProbe finds source-to-sink paths from skill-controlled inputs to sensitive ops, evolves SKILL.md seeds with canaries, and oracles attacker-controlled flows plus observable harm—104 taint-style vulns across 11 open-source agents (eight with >10k stars); on real ClawHub-style skills, 25.1% of skill-agent trials hit vulnerable paths and payload injection weaponized 15 vulns. Skill-trust note for Tal: treat installed skills as untrusted until source-to-sink is gated—don’t auto-admit skill markdown/code into the agent context.

## LLM security

### [Where Do LLMs Decide to Break the Rules? Mechanistic Localization of Prompt Injection Compliance](https://arxiv.org/abs/2609.37737)

Wen, Liu, Yang, Sakuma, and Sun ask *where* in the net the model decides to abandon its system role under prompt injection—not only how often. Layer-by-layer causal activation patching on five models (4B–32B) shows attack content is linearly decodable from layer one, yet causal leverage stays near zero until a late-layer bottleneck in the final third; patching that bottleneck reverses compliance in 77–92% of cases. The compliance mechanism sits in a compact linear subspace (rank-8 at 4B/14B, rank-64 at 32B), is stable across families, and that same peak layer is the best attack-detection site—early classifiers degrade under leetspeak-style obfuscation. Bottleneck note for Tal: intervene/detect at the late causal peak, not the early readable layer—don’t equate early linear decode with the decision.

### [Render Before Reading: Visual Rendering as a Prompt Injection Defense](https://arxiv.org/abs/2609.36121)

Zhang, Baroian, van Rijn, Shafran, and Tramèr find a systematic modality asymmetry: multimodal LLMs obey adversarial instructions more when they arrive as text than when the same bytes are an image (or audio). They attribute it to text-centric instruction tuning—text is to be obeyed, other modalities mostly described—and turn the gap into training-free **Pictionary**: render all untrusted payloads as typographic images (or audio) before the model sees them. Across ten models and DirectInject + AgentDojo it cuts ASR even against strong adaptive attacks and human red teamers while largely keeping benign utility; benign fine-tuning on image-rendered instructions erodes the gap. Render-untrusted note for Tal: render untrusted tool/web text to image/audio before the model—don’t feed raw third-party text into the instruction channel.

### [ContractWarden: Kernel-Enforced Damage Boundaries for AI Agents via Human-Authorized Contracts](https://arxiv.org/abs/2609.38248)

Cui, Gu, Zheng, Xi, Han, and Liao put the damage boundary in the kernel: the model may propose a tri-state asset contract (allow / deny / no_egress), but a human authorizes it, an execution gate binds contract to task before untrusted code runs, and an eBPF LSM data plane enforces file/network decisions while monotonically propagating no_egress through processes, files, pipes, FIFOs, and supported Unix sockets. All 570 runs across 19 security tests meet return-value and side-effect criteria; median overhead is ~12% in a Linux 6.15 VM and higher on bare metal, still below the frozen ActPlane baseline. Kernel-contract note for Tal: human-authorize asset contracts and enforce in-kernel—don’t trust the agent (or its suggested policy) after prompt injection.

### [ToolFence: Fine-Grained Authorization for Secure Tool-Using LLM Agents](https://arxiv.org/abs/2609.37196)

Li, He, Dai, and Xiao target within-tool IPI—same tool, attacker-steered arguments—where content filters and multi-path consensus still leave high ASR, and heavy data-flow control (e.g. CaMeL) is too slow. ToolFence compiles a typed authorization blueprint before execution, enforces it with a deterministic monitor, and when the blueprint is incomplete asks a judge for *capability* grants rather than per-call adjudication; provenance-aware auth separates user-authorized values from untrusted observations. On AgentDojo with Qwen3-max, overall ASR falls near zero at a 3.80pp clean-utility cost with practical overhead. Effect-auth note for Tal: authorize tool *effects* from a typed blueprint before run—don’t only filter observation text.

### [SceneJail: Exploiting Video Scenario Context to Jailbreak Multimodal LLMs](https://arxiv.org/abs/2609.38899)

Chen, Wang, Zang, Meng, Gao, Wang, Li, and Guo show video jailbreaks have treated the clip as a *carrier* for a harmful query, missing the surrounding scenario as an attack surface—the same harmful ask flips safety outcomes across scenarios. SceneJail pairs Adaptive Scenario Construction (search a compatible surround) with Scenario-aware Prompt Search (black-box feedback for textual guidance). On HADES and SafeBench across eight Video-MLLMs including GPT-4.1 and Gemini3.5-Flash, SceneJail-F hits up to 91.5% ASR (+29.1pp over strongest baselines); SceneJail-S (query split across frames) keeps 72.3% ASR under strict image filtering. Scenario-jail note for Tal: red-team video models on scenario context, not only how the query is painted into frames—don’t assume frame filters close the channel.

### [MADBench: Benchmarking the Security of Multi-Agent Debate](https://arxiv.org/abs/2609.39146)

Liu, Zhang, Huang, and Duan ask whether multi-agent debate mitigates or *amplifies* adversarial influence when agents exchange critiques. MADBench layers attacks onto the MAD workflow (established plus debate-specific), covering six attack families over 356 source tasks and 3,958 cases. Under attack, MAD is not an automatic reasoning win: vs a single-agent baseline it can help answer accuracy on QA yet *amplifies* unauthorized reads/writes on QA and workspace tasks; even 3-of-5 collusion flips a correct final answer on only 28.30% of previously correct tasks, and only 3.26% of initially correct honest agents switch during debate. Debate-security note for Tal: score MAD on influence propagation and unauthorized I/O, not only final-answer accuracy—don’t assume more debaters are safer.
