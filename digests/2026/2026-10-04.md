### [Tavus Griffin, a video model that talks over you](https://www.tavus.io/griffin)

## Agent memory

### [MemFit: Efficient Long-Term Agentic Memory](https://arxiv.org/abs/2610.00872)

Most long-term memory systems spend the expensive part of the work at write time, calling an LLM to organize and consolidate every turn, or they throw away surface detail by compressing it. MemFit does the opposite for conversational agents: each turn goes into an append-only store verbatim, with no model call on the way in, and segment summaries are an index rather than a replacement. Retrieval is also LLM-free, a multi-path mix of lexical and semantic signals plus cross-encoder reranking over caption-augmented episodes, and it covers both text and multimodal memories. On LoCoMo, MemGallery, and LongMemEval-S it reports state-of-the-art quality while cutting memory-construction time and cost several-fold, which is the practical claim: persistent agent memory can stay cheap if you stop rewriting history in order to store it.

### [Mem++: Non-Destructive Memory for Long-Term Organizational LLM Agents](https://arxiv.org/abs/2610.02002)

Organizational agents have a versioning problem that chat memory usually ignores. A revised decision arrives as a new document, not an edit, so the answer depends on which version was in force at the time the question asks about. Mem++ refuses the usual write-time distillation into facts, notes, or graph edges, which freezes what can be answered before any question exists. It stores every document whole, with date and author, and calls no generative model on write. At read time it keeps only documents dated up to the asked-about moment and fuses lexical and semantic rankings, leaving older versions intact for the answering model. On OrgMemBench it beats the strongest memory baseline by 8.0 to 13.1 points across two models; with gpt-4.1-mini it is also best overall, 2.6 points above plain RAG, best on LoCoMo by LLM judge, and second on LongMemEval-S behind only its own entity-graph variant.

### [Madeleine: Learning Involuntary Recall for Conversational Memory from Simulated Lives](https://arxiv.org/abs/2610.01118)

The memory a long-term assistant most needs is often not similar to what the user just said, and today’s systems recover that association by letting an LLM reason at write or read time, hundreds to more than a thousand calls per memory bank and up to several thousand context tokens per query. Madeleine treats association as something you can learn offline: a life simulator writes cue-trigger pairs, and those pairs teach a query encoder a residual on top of frozen similarity. Online it calls no LLM and drops into any vector store by swapping only that encoder. Under the official LoCoMo-Plus protocol it reaches 66.6 plugged into HyperMem, the highest score reported there; alone it matches released HyperMem (52.4 versus 52.9) at about a twenty-first of the answer context, and it lifts T-Mem by 26.2 points without hurting ordinary QA on a 4B backbone.

### [CAVE-Mem: Boundary-Aware Experience Validation for Memory Search](https://arxiv.org/abs/2610.00238)

Experience memory for long-term agents mostly optimizes relevance: retrieve a past search lesson that looks like the current state and inject it into the prompt. A relevant lesson can still be the wrong intervention when the memory substrate, the question’s intent, the answer granularity, or the evidence boundary has changed. CAVE-Mem, training-free, represents an experience as a typed operator with applicability, boundary, and utility conditions. It first takes a base memory-search answer, then lets the operator change that answer only if it matches the current substrate, the answer contract, the evidence boundary, and a cross-fitted utility estimate; otherwise it abstains. Across long-term conversational memory, multi-hop QA, and long-document narrative reasoning, that gate beats relevance-only reuse of past search experience. The useful idea is refusal: a memory of how you searched is not automatically a license to search that way again.

### [Causal Memory Policy: Making Memory Utility Identifiable by Intervening on Retrieval](https://arxiv.org/abs/2610.02070)

Memory-augmented models increasingly keep or drop a memory according to its estimated effect on task performance, but those estimates only ever see memories that were retrieved. If a memory is never pulled into context, store-level interventions look identical, so its utility is unidentified. Causal Memory Policy treats that as a retrieval-level positivity violation and fixes identification by intervening on retrieval itself, reserving a fixed number of context slots for memories sampled with known propensities and estimating utility by self-normalized inverse propensity weighting. Identification fails for 54% of required memories on LongMemEval and 67% on LoCoMo, including inside a deployed memory system; CMP lifts required-versus-not discrimination from 0.54 to 0.66 AUC. The sting is the last result: per-query utility hits 0.78 AUC on the query it was estimated for, yet no aggregation a retention policy can actually use predicts value on unseen queries.

### [Heavy-Tailed Memory Traces in Long-Horizon Language Agents](https://arxiv.org/abs/2610.00010)

Long-horizon agents treat external memory as a frozen world model and then score it only by task success or token cost, which misses the shape of use. Under a finite context and repeated retrieval, agent memory concentrates on a small core and leaves rare states in a long tail where prediction errors pile up. A tail audit finds the concentration is real but policy-dependent: random-walk agents look roughly log-normal, while semantic LLM policies produce the strongest truncated-power-law core-tail traces. Core-Tail World Model turns that shape into a controller, spending prompt budget by rank with a single exponent while keeping a summarized tail. On a synthetic graph world it holds full state and transition coverage, cuts prompt tokens 5.9%, and lowers bottom-half tail error 13.6% versus a graph-memory baseline, with similar token savings on ALFWorld and a 24.48% token cut on LongMemEval at matched accuracy.

## Agent harness

### [Mingbird: A Local-First Agent Harness Enabling Small Open Models to Complete Real Tasks](https://arxiv.org/abs/2610.02001)

Small open models in the 2–9B range run on a laptop, then fall over inside cloud-scale agent harnesses: tool prefill blows the context, self-correction diverges, tool demos loop, and tasks get abandoned without saying so. Mingbird is a local-first harness for Windows and Ollama whose mechanisms are aimed at those failure modes, including a byte-level net-zero prefill budget, a finish gate that re-reads the task before accepting “done,” and signature-level loop detection. On a controlled comparison that holds machine, models, budgets, and scoring fixed, it scores 0.886 overall against 0.631 for goose, 0.479 for opencode, and 0.405 for agent-mini; on τ²-bench it totals 0.856 against 0.791 and 0.737. A frontier-model probe on the same 18 tasks swings from 0.997 to 0.478 across harnesses. The authors flag the limits themselves: a self-built benchmark, one machine, and single-trial scoring, with same-night reruns moving a mean by up to 0.069.

### [Finding the Right Fit: Model-Harness Interactions across Agent Tasks](https://arxiv.org/abs/2610.00917)

Picking an agent is picking a model and the harness it acts through, and neither ranking survives a change of setting on its own. Sixty-six configurations, four harnesses (OpenHands, DeepSeek Harness, PI, openJiuwen) times five models on TUA-Bench, ALE-CLI, and Terminal-Bench 4, plus native Codex-GPT and Claude Code-Claude pairings, show model order reversing by harness. On Terminal-Bench 4, Claude leads GPT by 7.94 points inside OpenHands and trails it by 30.16 inside PI. For four of the five models the best harness changes from one benchmark to the next, though some pairs stick: openJiuwen is Kimi’s best on all three, by 5.61 to 11.11 points. A vendor’s own harness is not reliably best, and more spend is not reliably more score. GPT does better under PI’s lean scaffold than under DSH at less than a quarter of the cost per task, largely because models start their own repairs and live or die by how the harness hands a failure back.

### [ActiveSaddler: Automated Curriculum Learning for Agent Harness Optimization](https://arxiv.org/abs/2610.00906)

Automated harness optimizers already rewrite prompts, tool interfaces, and control logic from execution feedback, but they usually freeze the scenarios that produce that feedback. As the harness changes, the failures worth practicing change with it. ActiveSaddler treats the curriculum as a non-stationary bandit: recurring failures become reusable arms, each scored by how much more learning progress it still offers, and the optimizer splits effort between known weaknesses and unseen scenarios that might reveal new ones. Outcomes update both the pattern set and the priorities, so the curriculum moves with the harness. On GAIA2 and Terminal-Bench 2.0 it improves test Pass@1 by 4.4 and 7.5 points over the same optimizer fed a scenario order fixed before optimization. Ablations say the gain needs all three pieces: targets built on the fly, an estimate of their changing value, and a balance between drilling old failures and finding new ones.

### [VeriHarness: Scaling Agentic Verification for Long-Horizon Tasks](https://arxiv.org/abs/2610.00972)

Long-horizon agents are now hard to grade, and the usual escape, sample several rollouts and hope, fails in a specific way: disagreement often surfaces a correct alternative, while consensus can hide a shared error. VeriHarness keeps the base model fixed and, with no reference answers or rubrics at test time, turns that same model into a verifier by giving it a workspace, evidence tools, and reusable verification skills. A disagreement resolver checks competing claims against the environment; a consensus challenger attacks claims everyone agreed on and looks for requirements nobody mentioned. Across five long-horizon workspace benchmarks and two frontier models it posts the best selection scores among the baselines tried, and evidence-backed revision adds 6.2 points over a single rollout for Gemini 3.5 Flash and 6.4 for Claude Opus 4.8. The skills can also be updated from their own failures. The released pool is about 26,000 rollouts, generated at a cost of over $100,000.

### [GUI-HARVEST: Self-Improving GUI Agents through Evidence-Driven Harness Evolution](https://arxiv.org/abs/2610.00948)

For a GUI agent the harness decides how screenshots are packed, how clicks are issued, and when to verify, recover, or stop, and optimizing that loop is messier than for a text agent because intent has to be reconciled with what actually changed on screen. GUI-HARVEST keeps the backbone frozen and edits the harness from evidence: it lines model outputs and executed actions up against before-and-after screenshots, treats repeated runs of the same task as one evidence unit so flaky execution does not look like a new bug, then turns recurring patterns into bounded source edits whose predicted effects are checked by running them again. On OSWorld-Verified the held-out gains hold across six open, GUI-specialized, and proprietary backbones, including +12.33 for Qwen3-VL-32B-Instruct on the full suite. The same frozen harness, moved without further optimization, lifts GPT-5 by 13.87 points on WindowsAgentArena at 50 steps, and beats Self-Harness and Meta-Harness from the same starting harness.

### [Measuring the Microtask Eligibility Gap: When Is an Off-the-Shelf SLM Enough for an Agent Harness?](https://arxiv.org/abs/2610.00025)

Harness designers want a small model on the chores around a frontier planner: auto-approving shell commands, writing memory, selecting tools, ranking past turns. A four-microtask benchmark with frozen prompts and a pre-specified bar, anchored to a cheap non-LLM baseline and passed only if the confidence bound clears that bar, finds an eligibility gap. At their best setting (FP16, greedy, one frozen prompt, no tuning), zero of 16 Qwen3 configurations from 0.6B to 8B pass, and a log-prob diagnostic splits the misses into things the model cannot do and things a different decision threshold might fix. Four-bit quantization (RTN, GPTQ, AWQ) damages results in a size-dependent way and promotes nobody into eligibility; Llama-3.x is 12 for 12 ineligible, and 0 of 112 cells pass once prompt paraphrases are included. The suggested placement is the reverse of the usual cascade: keep a baseline that already clears the bar, and call the SLM only where that baseline fails. A 4B reranker over a BM25 shortlist beats BM25 by 0.047, and still does not itself certify as eligible.

## LLM security

### [The Innocent Courier: Covert Exfiltration Through Legitimate LLM Web Fetching](https://arxiv.org/abs/2610.01768)

Local malware that cannot open its own network connection can still smuggle a secret out by asking an LLM to do an ordinary web fetch. LLMLeak embeds the secret in a URL and presents the page as something a benign task needs, such as notes for a library migration. Inputs that say “send this data” or that try to import a network library are the easy cases to block; a fetch tool is supposed to run. When the model requests the URL, an attacker-controlled DNS or web server sees the encoded secret. Across eleven open-parameter models the attack succeeds 79.7% of the time, and a case study on real chatbots is offered as evidence this is not only a lab tool-policy hole. Structuring inputs against prompt injection, or keeping the model local so the vendor never sees the data, does not close a channel whose whole point is a legitimate outbound fetch.

### [From A2A Attacks to Envelope-Layer Defense: Red-Teaming Evaluation of LLM Agents and a Three-Layer Isomorphic Attack-Defense Model](https://arxiv.org/abs/2610.00392)

Once agents accept tasks from remote peers over protocols such as A2A, a peer message looks like a legitimate request, which is a ready-made channel for indirect prompt injection. Attack success rate alone cannot say whether a miss was the model recognizing the payload or some later mechanism refusing to run it. A2A-TIBA combines that injection with a bypass: implant, command, exfiltrate, pushing the target to install a callback program so later commands skip the agent. A gateway-capture testbed splits outcomes into semantic refusal, semantic breach, interception, and penetration instead of one ASR number. The defense claim is a three-layer split, envelope packaging, model recognition, and agent interception, matched to implant channel, prompt optimization, and execution mechanism. On 15 front-end/back-end pairings and a 1,000-case set, labeling malicious prompts at the envelope (A2A, tool, and memory channels) measurably improves the model’s chance of recognizing them.

### [MOMAT: Mixture of Multiple Atlases for Low-Power Jailbreak Defense of Quantized LLMs](https://arxiv.org/abs/2610.01058)

Quantizing a model for an edge device weakens the alignment that was supposed to refuse jailbreaks. MOMAT answers with a hardware-side guard rather than a bigger safety model: harmful and benign examples plus policy templates are clustered into “atlases,” and a prompt is checked by retrieving top-k features from every atlas into a small mixture-of-experts detector, a form of domain-local retrieval meant to avoid one huge, sparse safety database. The similarity search itself runs in compute-in-memory. On a 100-query batch that retrieval drops from 15,052.44 ms to 3,207.21 ns against a DRAM baseline on a Raspberry Pi, about a 4.69-million-fold speedup, and energy from 8.1×10^7 μJ to 3.32 μJ. Red-team numbers are reported as matching current defenses without the usual over-refusal of benign prompts. The dataset they plan to release is 223.2k samples.

### [Do Defenses Against LLM Extraction Work Across Attacks? A Lifecycle Benchmark of Black-Box Model Extraction](https://arxiv.org/abs/2610.00839)

Text-only APIs can be copied by anyone willing to collect enough answers and train a surrogate, and the papers on that threat do not share access assumptions, budgets, or what “defense worked” means. This benchmark lines up six extraction attacks, ten defenses, and two adaptive attacks that paraphrase or back-translate protected responses before the surrogate is trained, holding model configuration, query data, budget, and held-out eval fixed inside each comparison while leaving each attack’s own query and training procedure alone. The reported measures are surrogate capability, fidelity to the victim, a repetition quality score, and how results move with query budget; defenses keep their own security metrics next to surrogate performance. For the adaptive pair it also scores provenance detectors against surrogates trained on the rewritten outputs. It is a comparison harness, not a new attack, and the point of reading it is whether a defense you liked still holds once the attacker is allowed to rephrase.

### [Intrusion Detection for Agentic Processes: Evidence-Based Runtime Monitoring](https://arxiv.org/abs/2610.00151)

Agent deployments mix model calls, retrieval, delegation, tools, outside systems, and human approval, so a security failure can be a drift across that whole process rather than one bad prompt. A-IDS is a proposed monitoring layer whose object is the process: evidence-backed observations compared with a versioned expectation for workflow state, authorization, communication, and events that were supposed to happen. Matching is three-valued, an unseen event is not treated as proof it did not occur, and a finding is supposed to separate “what the evidence shows” from “what you should do about it.” Prompt injection is framed both as an input problem and as something that can later show up as a process deviation or a cross-agent influence path, including when adversarial content reaches the monitors themselves through an otherwise legitimate observation. The paper is explicit that this is a conceptual model: no implementation, no detection-rate results, and no enforcement mechanism.

### [We're going to need default hard budget caps on pretty much everything](https://simonwillison.net/2026/Oct/3/default-hard-budget-caps/)

Simon Willison’s argument is that pay-by-usage APIs need a hard default: after a configured amount, the service stops and returns errors, and living without that cap should be an explicit opt-in checkbox. Soft caps that email you at midnight do not help when a coding agent, or a personal agent that is a coding agent in a softer wrapper, has already spun up something that bills for API calls, hosting, or storage while you sleep. He would rather have the application throw errors than discover a five-figure bill, and he wants agents themselves to start preferring providers that offer the hard cap. AWS has begun shipping project spend limits that pause a project for the month, still rolling out to a limited set of customers, and Google Cloud added Spend Caps on specific services in July. The post is short on mechanism and long on the product default he thinks every usage-billed platform now owes people who let agents deploy things.
