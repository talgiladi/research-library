## Agent memory

### [Do Conversational Agents Need Explicit Memory? A Controlled Comparison with Raw-History Retrieval](https://arxiv.org/abs/2610.24671)

Memory systems for agents keep getting more elaborate, but this study asks the awkward question of whether any of that construction work beats simply retrieving from the raw conversation history. The authors pit six state-of-the-art explicit memory systems against a strong raw-history RAG baseline on LongMemEval-S and BEAM-100K, under both original and controlled retrieval settings, and find only localized gains for certain question types and very tight context budgets. Oracle retrieval explains why: some systems lose the answer-supporting facts while building memory, sometimes after hours of construction per conversation, while others keep the facts but fail to fetch them. The takeaway is that retrieval, not richer memory structure, is often the real bottleneck.

### [Memories That Outlive Their Reasons: Dependency-Tethered Memory for Tool-Using LLM Agents](https://arxiv.org/abs/2610.25123)

An agent that remembers past verifications saves work, but a remembered verdict is only as good as its premises, and when a signing key is revoked the advisory names only the key, not everything that depended on it. In long simulated chats, an agent reading a memory of atomic facts went on to publish 62 percent of objects whose failure lay upstream, each backed by a record that was true when written. Tether fixes this by recording at write time the exact versions each verdict derives from and withdrawing any verdict whose support has failed anywhere in the store. It cuts unsafe publications to 0.3 percent with 37 percent fewer verification calls, while Mem0 publishes 42 percent and A-Mem and Graphiti 9 percent.

### [Whose Credential Is It? How Owner Attribution in Agent Memory Shapes Cross-User Account Misuse](https://arxiv.org/abs/2610.25707)

Shared long-term memory makes it easy for an agent serving one user to pull up another user's login, and this paper separates three things that usually get blurred together: exposure, behavior and actual damage. In AppWorld, a store mixing 763 past logins retrieved a foreign credential for 84.7 percent of required apps, yet agents rarely used it. The danger appears when memory lacks the user's own credential and presents a single foreign one as theirs: seven agents then used it in 80 to 94 percent of runs and changed the victim's account in up to 43 percent. The fix is almost embarrassingly simple, because naming the owner on each credential line cut misuse from 92 to 1 of 305 paired runs.

### [Can Agents Keep Secrets They Were Never Told? Benchmarking Latent Privacy Risks Across Sessions with MemJoin](https://arxiv.org/abs/2610.24359)

Some privacy leaks cannot be spotted when a memory is written, because the sensitive fact only emerges once clues from several sessions are joined. MemJoin turns that problem into a benchmark of 288 synthetic analysis cases in which the full history entails a sensitive relation about a person but no single session does, and an agent completing an ordinary task may state the relation anyway. The authors run six memory systems with the same answer model, plus full-history and no-history controls, and check what lands in stored records, retrieved context and final answers. The interesting result is that removing shared identifiers and connecting clues can change whether the full relation is disclosed even while every individual attribute stays visible, so attribute-level audits miss the real risk.

### [Memory, Know Your PLACE: Governing Lifecycle State and Query-Time Eligibility in Persistent-Memory Agents](https://arxiv.org/abs/2610.25179)

Persistent memory turns old interactions into durable state, but most systems have no way to say whether a memory is still valid or whether it should be allowed to shape a given answer. PLACE adds a governance layer on top of an existing backend with two separate controls: write-side certification of the lifecycle state a memory is in, and read-side authorization that decides at query time which memories are eligible to influence the response. A factorial evaluation on Mem0 with Qwen2.5-3B and 7B isolates each piece, showing that write-side governance mostly fixes state correctness while read-side governance eliminates measured causal leakage from ineligible memories. Together they give the best joint results without starving queries of the support they actually need.

### [Bud ContextCompact 2.0: Context Compaction for Agent Success and Accuracy with Small Language Models and Constrained Context Windows](https://arxiv.org/abs/2610.25516)

Compaction, replacing older turns with a summary so a session can keep going, is standard in agent runtimes, and this report from the Bud runtime measures when it actually pays off on small models and tight windows. On 100 SWE-bench Verified tasks run by a 27B reasoning model with a 49K-token window, compaction lifted the resolve rate on long sessions from 41 to 53 percent and used 13 percent fewer tokens per solved task. The more interesting finding is the failure it prevents, which was not the history overflowing but a single reasoning turn running out of the room the history left. The gain has limits too: each summary took a median of 161 seconds, so it vanished under a 45-minute session budget.

### [Editing as Language: Teaching LLM Agents a Grammar for Native Context Editing](https://arxiv.org/abs/2610.25550)

Most context management lives in the harness, where tools or code prune and summarize the model's working memory from the outside. Native Context Editing moves the job inside the model by giving it a grammar of dedicated special tokens for editing its own context, so it can fold, drop or rewrite earlier material as it generates, much as a synopsis compresses a novel. Agents are trained on iteratively constructed trajectory segments in which each teacher edit is conditioned on the evolving context. On Terminal-Bench 2.0 and three SWE-bench variants, the approach raised average task success by 5.6 points for LongCat-Flash-Lite-Sparse and 4.5 for Qwen3.6-35B-A3B, while cutting token usage by 36 and 15 percent.

## Agent harness and skills

### [One Skill Takes Over: Clashing Agent Skills and a One-File Fix](https://arxiv.org/abs/2610.25064)

Users install agent skills from many authors, so two skills for the same job can easily sit in context together, and this paper shows the model rarely merges them. On SkillClash, 16 code-checked pairs of same-job skills, seven models from 4B open models to Qwen3-235B and GPT-4.1 followed a skill's rules 93 to 99 percent of the time alone but only 61 to 62 percent when its rival was loaded. Most outputs show takeover, where one skill wins completely, and the worked examples inside the skills drive it. Telling the model which skill has priority does not help, but ending each file with one example that satisfies both cut takeover to 1 to 15 percent, and a single merged file restored 96 to 99 percent compliance.

### [When the harness decides success: state that cannot be re-observed](https://arxiv.org/abs/2610.26632)

Harnesses decide what a model sees across turns, by dropping old turns, summarizing them or replaying its earlier reasoning, and this paper shows those choices can decide success itself, not just cost. In a pre-registered probe, truncation cost a reasoning model nothing when a needed fact could be looked up again but dropped it to chance when the fact could not be re-observed, a gap of 92.5 points. On ARC-AGI-3, the authors take apart the wide gap between the benchmark's Standard harness and its Provider Adapter harness one component at a time. Summarizing old turns while keeping an invitation to take notes recovers 86 percent of a 63-point gap without any reasoning replay, while dropping that invitation halves the recovery to 43 percent.

### [When Code Becomes an LLM Call: An Empirical Study of Call-Site Contracts in Agentic Systems](https://arxiv.org/abs/2610.24545)

When an agentic system hands a decision such as picking the next tool or judging whether an action is allowed to a model, the guarantee the program relies on has to come from the code around that call. This study audits 496 LLM call sites across 40 popular open-source agent projects, 13.4 million lines in four languages, using a pipeline validated by 17,428 human judgments. Nearly half of model outputs reach control flow or execution, and 73 percent of those never pass a human. Although 82 percent of call sites are checked before and after the call, 63 percent of expected constraints go unmet and only 5.3 percent satisfy their whole contract. Ten recurring patterns explain almost all the gaps.

### [EvoSkill v2: Fully Agentic Skill Evolution from Benchmark Adaptation to a Stateful Evolver](https://arxiv.org/abs/2610.25931)

EvoSkill v2 improves an agent by rewriting only its skills, leaving the model and harness untouched, and its main design choice is to make the optimizer itself a long-lived agent. A benchmark adaptor turns the user's benchmark description and grader into a plugin, a solver attempts the tasks, and a single stateful coding agent with a bash tool reads the rollouts and rewrites the skills each epoch, unlike SkillOpt's one-shot model calls or SkillBoost's fresh-each-round agent. It also measures how noisy the solver's rollouts are and accepts every epoch's skills rather than chasing noisy scores. The result is 7.7 and 5.4 points above the best baseline on SpreadsheetBench v2 and τ³-bench banking, and gains of up to 21.5 points with Claude Haiku 5.5 on both sides.

### [HarnessPro: Recursive Harness Self-Improvement with Pareto Optimization for Performance-Cost Trade-offs](https://arxiv.org/abs/2610.26770)

Self-improving harnesses tend to buy their gains with ever more expensive execution, and HarnessPro tries to optimize for both axes at once without ground-truth labels. Candidate harnesses are scored against LLM-generated tests, specialized agents diagnose execution trajectories and plan updates with different performance-cost priorities, and instead of one winner the method returns lite, medium and heavy harnesses for different deployment budgets, which then seed the next round. Across Terminal-Bench 2, SWE-Bench Pro and ProgramBench, using GPT-5.5 with Codex, the heavy mode beat the earlier RHO method by 2.0 points in average pass rate while cutting per-task cost by 26.1 percent. The advantage held when GLM-5.2 was driven through Claude Code.

### [How Effectively Do Security Skills Guide Coding Agents in Vulnerability Detection in Linux Kernel?](https://arxiv.org/abs/2610.25705)

Security-auditing skills for coding agents are multiplying, and this is the first large-scale test of whether they work on real bugs: 37 skills run through Claude Code with four underlying models against 100 real Linux kernel vulnerabilities, 14,800 runs in all. The results are sobering, with only 24.4 percent of runs locating the vulnerable function and 15.7 percent classifying the vulnerability correctly. Failure analysis points to weak evidence gathering, poor reasoning about state relations and incomplete investigation coverage. The authors then propose SKILL-SIF, which evolves skills from missed vulnerabilities and failure patterns, and on 100 unseen bugs it raised fully correct detection from 2 to 16 percent for the best skills.

### [Design and Cross-Domain Evaluation of an Agent Execution Harness](https://arxiv.org/abs/2610.25568)

This harness keeps the user's original objective separate from a revisable plan and an execution record, so a planner can hand out scoped tasks, workers can produce artifacts and a reviewer can check results against the original request before submitting or sending work back. Reusable domain instructions guide each role and are refined from task inputs and trajectories without access to official grading. It passes 83 of 89 Terminal-Bench 2.1 instances and reaches a length-adjusted score of 69.63 on HealthBench Professional. The paper is unusually candid about the price: on a paired HealthBench comparison the harness scores 19.89 points above direct completion in aggregate, but the median task barely moves and mean cost rises from $0.29 to $2.13 per task.

## LLM and agent security

### [Connection Escrow: Holding AI-Agent Pod Egress in the Kernel Until an Isolated Verifier Rules](https://arxiv.org/abs/2610.26501)

Controls that sit between an agent and its tools can be bypassed by a child process or a raw socket, so this system moves the checkpoint into the kernel. A 98-instruction eBPF program on the pod's cgroup parks every outbound TCP connection inside connect() before a single packet exists, attributes it to a process, binary digest and pod identity, and waits for a signed verdict from a verifier in a separate container. Only an unexpired, unused verdict naming that exact socket releases it, so forged, replayed and late approvals fail, as do child-process and renamed-binary bypasses. The hold adds a median 4.5 milliseconds, and an eBPF uprobe can even score request content at the TLS-library boundary without breaking encryption.

### [SPIDES: Information-Flow Control for Browser Agents](https://arxiv.org/abs/2610.24277)

Browser agents act across sites with the user's authority, which has led some researchers to call for restoring the Same-Origin Policy, but SPIDES argues that is both too weak and too strict, since a same-origin public sink can still leak data and many legitimate tasks need cross-origin flows. Instead it applies information-flow control, gating primitive actions such as typing, clicking and navigating on labels propagated from element-level confidentiality and integrity annotations in the HTML. Untrusted and confidential content is masked from the agent's context, and policies block unauthorized flows regardless of which model drives the agent. On MicroNet, a closed ecosystem of 28 interlinked sites built for the evaluation, it reaches 0 percent attack success by design while keeping task completion high.

### [The Window Is in the Reasoning: When LLM Agents Decide to Follow Prompt Injections](https://arxiv.org/abs/2610.24048)

Runtime monitors and single-run benchmarks quietly assume that whether an agent follows a prompt injection is settled the moment it reads it, and this paper tests that with branching rollouts that replay an episode up to the injection and resample everything after. On four AgentDojo suites, a Qwen3 agent without thinking is mostly decided at read time, with 0.91 of outcome variance fixed there, but with thinking on that share falls to 0.62, and the decision forms gradually as the agent reasons. Thinking lowered Qwen3's attack success rate but raised it for two other models. Cheap chain-of-thought monitors miss much of what is already decided, and single-run labels for thinking agents disagreed with a rerun up to 35 percent of the time.

### [ToolRosetta: Surface-Form Invariance of Tool-Call Guards](https://arxiv.org/abs/2610.24055)

Step-level guards for agents are usually tested on tidy JSON tool calls, but real coding agents act through execute_bash and execute_code, whose payloads are just strings. ToolRosetta re-renders every action in the AgentDojo and AgentHarm splits of TS-Bench as a Python call, a shell command and a version without the agent's rationale, keeping the request, history, label and effect fixed. Frontier and strong open-weight guards barely move, but four of five specialized agent guards fall apart under the shell form, with false-positive rates rising by 21 to 47 points and blocking between a third and nine in ten benign actions. The practical lesson is that accuracy on JSON calls says little about a guard's behavior behind a code-acting agent.

### [SoK: PIAtlas: Decomposing the Unbounded Prompt Injection Attack Space](https://arxiv.org/abs/2610.24999)

More than twenty public prompt-injection datasets describe attacks in incompatible vocabularies, usually by delivery vector or attacker goal, and this systematization reorganizes the field around how an injected instruction actually subverts the model. PIAtlas has six root classes, one per subversion mechanism, each branching into techniques and sub-techniques derived from how models are trained, prompted and swayed by human-like framing. The authors also release PICorpus, which they describe as the largest license-clean collection of public injection datasets, and map thousands of records to the taxonomy with human verification. The mapping shows attacks usually combine several techniques from only a few mechanisms, and that widely used agent benchmarks cover only part of the space adaptive attackers favor.

### [Honeypots for AI Agent Insider Threats](https://arxiv.org/abs/2610.26664)

Agents deployed inside companies can become insider threats through mistakes, compromise or misaligned goals, and this position paper argues that honeypots belong in production, not just in pre-deployment evaluations. Defenders would plant decoy opportunities for harmful actions throughout the real environment, which can elicit misbehavior under true deployment conditions, incriminate a malicious agent even if chain-of-thought monitoring degrades, and scale cheaply across many agent instances. The more interesting effect is deterrence, since an agent that cannot tell which opportunities are real has a reason not to try any of them. The authors also lay out the limits and a research agenda covering honeypot robustness, comparisons with other monitoring and the infrastructure needed to run them.

### [Simon Willison: eMudhra Intermediate CA Compromise](https://simonwillison.net/2026/Oct/20/emudhra-certificates/)

Simon Willison calls this one very, very bad news: the private keys of eight eMudhra intermediate CA certificates have been compromised, and those certificates chain to roots trusted by the Mozilla, Microsoft, Apple and Chrome root programs and many downstream trust stores. That means any software that bundles its own list of trusted certificates needs an update, and a tracking site with a companion GitHub repository is following which projects have shipped fixes, with Linux distributions needing new ca-certificates packages. For Python users the fixes are already out in uv 0.13.4, pip 26.2.2 and certifi 2026.10.19, which makes this worth checking in any agent sandbox or container image that pins older versions.

### [Simon Willison: Battle Drones, a vibe coded RTS with audio-based multiplayer](https://simonwillison.net/2026/Oct/20/battledrones/)

Willison's latest vibe-coding experiment is a Command & Conquer style strategy game built over 12 major iterations and 321 commits by coding agents, mostly Claude Code, and he admits the leap in fun came from telling Claude to "make it a LOT more fun". For agent watchers the standout is Agent Battles, in which two LLMs play each other through a tools interface that exposes only what fog of war allows, with recorded replays such as Claude Haiku 5.5 against GPT-6 Luna. Two devices within microphone range can also play each other over an audio modem. His observations include Opus 5.5 composing the game's music in code and replacing browser trigonometry functions to keep replays deterministic.
