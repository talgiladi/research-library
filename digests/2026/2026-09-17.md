### 1. TypeSafe Jev — System One models that choose, don’t chat
Primary link: https://typesafe.ai/blog/introducing-system-one-models-and-jev
Also: https://typesafe.ai/ · https://therundownai.beehiiv.com/p/chatgpt-co-creator-launches-a-new-kind-of-ai · https://codenewsletter.ai/p/chatgpt-co-inventor-s-frontier-lab-drops-new-model

Ex-OpenAI researcher Diogo Almeida (ChatGPT-era instruction-following work) emerged from two years of stealth with TypeSafe and **Jev**, the first of a class he calls **System One** models—named for Kahneman’s fast intuition rather than slow deliberative chat. Instead of generating free-form strings, Jev takes unstructured program state and returns only predeclared typed options with calibrated confidence scores, so software can treat the call like a probabilistic function rather than a parser minefield. Under the hood TypeSafe pairs a parallel sampler with **RLCD** (Reinforcement Learning for Calibrated Decisions), claiming 70–500 ms end-to-end latency, input pricing around $0.042 / MTok with free outputs, and workflow evals that put Jev roughly two orders of magnitude faster and cheaper than wrapping frontier chat models for the same structured decisions—Rundown’s figure is ~238× vs Claude Fable 5.1 on in-app judgment calls. The trade is explicit: Jev is a classifier, router, and verifier for automations, not a prose or coding model, and “zero hallucinations” here means schema-guaranteed outputs plus honest uncertainty, not omniscience. For Tal’s harness lane the interesting bet is swapping brittle LLM-as-judge / routing hops for a System One call that software can depend on at interactive speeds.

### 4. Decoding AI — coding agents stay safe because of sandboxes, not trust [HIGH]
Primary link: https://www.youtube.com/watch?v=7CHMb8jWs6A
Also: https://substack.com/@pauliusztin

Paul Iusztin’s Decoding AI piece (with video companion) argues Claude Code, Open Code, and similar agents don’t “never wreck your machine” out of model virtue—they stay safe because of **sandbox isolation**, and he walks through rebuilding that layer after reading their sources. The architectural punchline matches what he’s been shipping in Decode: keep the harness, conversation, memory, and orchestration local as a control plane, and route only computer-touching tools (read/write/edit/bash) through a `CommandExecutor` into Docker or remote Modal sandboxes (`SANDBOX_MODE=none|docker|modal`). Full-VM agents kill UX by wiping conversations and config on every switch; tool-only sandboxing preserves local context while swapping compute, enabling GPU burst work and parallel subagents in isolated Modal sessions (gVisor) without giving the LLM a host shell. Fresh `docker exec` into a long-lived workspace container keeps filesystem coherence across tools. **HIGH** for Tal’s harness: treat sandbox mode as a first-class harness config, not an afterthought bolted onto an agent that already runs as root on the laptop.

### 5. ByteByteGo — how RAG finds the needle (and why retrieval—not the LLM—fails)
Primary link: https://blog.bytebytego.com/p/how-llms-can-find-a-needle-in-a-haystack

ByteByteGo’s overnight explainer pairs cleanly with Wed’s goldfish-memory primer: when a stranded employee asks whether a cancelled flight’s hotel is reimbursable, the answer lives in a policy that says “involuntary travel disruption,” sits beside older conflicting limits, and must be the current regional version. The piece walks chunking tradeoffs (too-small chunks drop exceptions; too-large ones bury the rule), embeddings and similarity metrics (cosine vs Euclidean vs dot product—score ≠ probability of correctness), and why flat O(n) search gives way to IVF clustering and HNSW graph navigation as collections grow—approximate neighbors that can miss the true match. More importantly for product RAG, it stresses metadata filters (region, effective date, version), pre- vs post-filtering pitfalls on graphs, hybrid keyword+vector + reranking, and coordinated version swaps so old and new limits don’t both stay eligible. Punchline: a strong generator with the wrong or stale passage still answers wrong—retrieval architecture is the product surface. Direct Tal read for the memory/RAG lane: evaluate chunk→filter→index→rerank as carefully as the base model.

## Agent memory

### Retrieval-Driven Memory Reconsolidation for Long-Term LLM Agents

https://arxiv.org/abs/2609.16053

Song, Wang, Ma, Fu, Lin, Liu, Wang, Deng, Yu, and Zhang argue most long-term agent memory systems update when new facts arrive but treat retrieval as a dead end—so access never reorganizes the store for next time—and they still lean on fixed schemas plus fixed pipelines. REALM (reconsolidation-evolution agentic long-term memory) borrows cognitive reconsolidation: memories live in a heterogeneous cognitive graph, retrieval adaptively composes graph-search atoms, then reconsolidates from retrieval feedback. On LoCoMo it reaches 75.97% (+7.17 over the strongest baseline) and 65.11% on LongMemEval (+1.31); ablations show reconsolidation progressively clusters related units for collective recall. Memory design read for Tal: close the retrieve→rewrite loop so access itself evolves the store—don’t only append.

### Interactive Memory Learning for Long-Term Conversations

https://arxiv.org/abs/2609.17088

Ke, Yan, Zhang, Liu, Yuan, Yu, Wang, and Xu say long-term conversation agents still archive passively with static heuristics—no adaptive sense of what is worth keeping as user needs drift. ICML (InteraCtive Memory Learning) turns memory into a learnable multi-agent policy: a Planner selectively encodes high-value information, a Trigger retrieves to optimize responses, and both co-evolve via online RL with delayed rewards that credit earlier storage decisions from later outcomes. A session-synthesis pipeline seeds expert data for fast test-time adaptation on unseen scenarios. Claims continuous quality gains as interactions accumulate versus strong baselines. Product read for Tal: treat write and retrieve as co-trained policies with delayed reward—not separate heuristics bolted onto a vector store.

### The Immutable Past: Formalizing State Mutability and Conflict Resolution in Mutable RAG

https://arxiv.org/abs/2609.16073

HaddadPajouh and AmiriTabat formalize why append-only RAG memory fails long-horizon agents: Semantic Shadowing—conflicting historical observations accumulate and statistically dominate fresh updates—plus a Majority Vote Trap where enlarging the retrieval context window paradoxically dilutes attention under semantic equivalence (Asymptotic Recall Decay). GC-Mem is an inference-time consistency protocol: a temporal dominance operator paired with contradiction detection surgically excises shadowed chunks, unlike blunt time-decay that also destroys valid long-term memory. On a 137,760-chunk behaviorally inferred bench with accumulation sweeps, standard RAG and timestamp re-ranking degrade hard; GC-Mem recovers >90% conflict-resolution accuracy. Mutable shared-memory rule for Tal: garbage-collect contradictions by temporal dominance—don’t just grow the window.

### ORDER: Task-Conditioned Routing for Retrieval-Augmented Generation

https://arxiv.org/abs/2609.17012

Pellet, Perez, and Puren note that RAG’s one fixed indexing/chunking/metadata stack is a poor fit for domain-expert settings where heterogeneous queries need different granularities, filters, and sources. ORDER (Optimal Routing for Dynamic Evidence Retrieval) discovers semantic clusters over a question set, learns per cluster a chunking strategy plus metadata filtering and reranking, and at inference routes queries by nearest-centroid assignment to the matching pre-built index. A supervised query router (QRe) predicts which collections hold relevant evidence, and a Uniform Multi-source Sampler (UMS) spreads the retrieval budget. Task-conditioned routing for Tal: pre-build a small menu of RAG configs and route the query—don’t force every ask through one preprocessing choice.

### Query-Aware Source-Risk Triage for Retrieval-Augmented Generation

https://arxiv.org/abs/2609.16564

Zhou, Qian, Xu, and Yi (Google / Sony) put a pre-generation triage layer on RAG that treats a source’s material risk as query-dependent rather than a static page score. The method routes canonical query families for enhanced review and assigns retrieved pages to pass, contextualize, exclude, or review via a four-dimension page score, rank-discounted family aggregation, intent-preserving query mutations, and a family-held-out router. A 200-URL single-coded pilot plus a 20,000-row synthetic scenario show why page-level frequency cannot substitute for family-level exposure. Caveat: annotation reliability is unmeasured and synthetic rankings omit live retrieval dynamics—an auditable method and validation plan, not a deployed workload estimate. Ops pattern for Tal: gate retrieval by query-family risk before generation, not only by chunk similarity.

### Where Should a Document Live: Context, Representations, or Parameters?

https://arxiv.org/abs/2609.17346

Rakotonirina, Hardalov, Iglesias, and de Gispert compare three ways to give LLMs new documents: stuff them in the context window, encode them into parameters, or inject them as latent representations. In a controlled oracle setting on five knowledge-intensive benches, KV-cache Cartridges are the most accurate injection at nearly every storage budget—about 10 points over parametric methods—while Compaction only matches Cartridges at low compression and lags ~10 points above 50×. More importantly, in multi-document retrieval only Cartridges match in-context learning, leading parametric methods by 29 points and Compaction by 15. The catch: Cartridges (like full fine-tuning and large MLP adapters) also suffer catastrophic forgetting (~6% overall, ~13% on coding controls). Placement brief for Tal: prefer KV document injection for retrieval-shaped workloads if you can live with the forgetfulness tradeoff.

## Agent harness

### BLINDSPOT: A Benchmark for Safety and Refusal Calibration in Long-Horizon Tool-Using Agents

https://arxiv.org/abs/2609.16305

Asif, Amiri, Abbas, Pedapati, and Sattigeri argue long-horizon tool agents break the usual safety scoreboard: failures emerge only after many turns of tool use, persistent state, and shifting authorization, yet evals often collapse to task or attack success and hide whether the agent acted, refused, or stayed calibrated. Blindspot is a live-simulation benchmark—adaptive adversarial interaction, stateful tool execution, execution-grounded adjudication—with 22 attack families and 35 scenarios across seven domains, yielding >2,500 trajectories (average 14.7 turns) labeled Safe Completion, Correct Refusal, Unsafe Completion, Over-Refusal, or Indeterminate. Unlike fixed attack datasets, it is an extensible framework for swapping attacks, tools, policies, and agent configs. Harness eval for Tal: score trajectory-level calibration across the whole session, not terminal ASR alone.

### Protocol-Preserving Context Trimming for Agentic Workflows: Benefits, Failure Regimes, and Budget Guardrails

https://arxiv.org/abs/2609.16461

Harish Gaggar compares five context-trimming strategies for multi-step agentic workflows—recency, relevance, summarization, protocol-aware trimming, and adaptive budget guardrails—against task success, protocol adherence, valid tool calls, token savings, latency, and cascading failures. Conventional strategies save ~60% tokens but drop task success to 66.6–77.3% with protocol adherence as low as the mid-to-high 80s. Protocol-aware trimming lifts success to 92.2%; adaptive guardrails reach 96.0% success, 96.3% adherence, and 1.0% cascading failure at 56.0% mean token savings. Retained-context budgets of 25% or less raise failure odds sharply versus budgets of 50% or more. Context hygiene for Tal: preserve protocol-critical state first—maximizing token removal is the wrong objective for long-horizon harnesses.

### Turn-level Multiscale Density Ratio Estimation for LLM Agents

https://arxiv.org/abs/2609.16760

Zhao, Chen, Li, and Liu (Alibaba) note that popular alignment recipes—PPO, DPO, DIL, and GRPO—mostly target single-turn tasks, while LLM agents need multi-step thinking and tool interaction. They propose Turn-level Multiscale Density Ratio Estimation (tlm-DRE): different weights per turn plus asymmetric token-level training that exploits positive–negative space gaps across the trajectory. On a wide range of agent benches the method is competitive with traditional alignment, and it holds up under both in-domain and out-of-domain multi-turn reasoning. Post-train note for Tal: when aligning tool-using agents, credit turn-level density ratios—not only whole-trajectory preferences shaped for chat.

### Skill-based Agentic Evaluation for Real-time Data Science Tasks

https://arxiv.org/abs/2609.16487

Tamhane, Addanki, Aggarwal, Bansal, Wang, Menguy, and Jain tackle a live-data headache: queries like “what were last week’s audience sizes” change as the underlying tables change, so static references rot and ordinary LLM-as-judge pipelines cannot check against a fixed answer. Their ground-truth-as-code idea encodes each expected answer as an executable reference that recomputes from live data at eval time, then a factoid-level judge scores precision, recall, and accuracy over atomic claims regardless of response format (prose, list, table, HTML). On an internally developed ML skill over a synthetic DB that mirrors production schemas, the method improves Matthews correlation with expert annotators by 29% versus a natural-language ground-truth baseline and cuts tokens per test case 16%; a self-directed no-ground-truth baseline is anti-correlated with humans. Eval pattern for Tal: ship reference-as-code for non-stationary agent outputs.

### Self-Emergence Agent Architecture:Behavior-Inertia HMM, Reflexive Metacognition,and Social-Contrastive Self-Modeling

https://arxiv.org/abs/2609.17331

Xiaoyang Liu targets three structural limits of generative agents: personality drift, reflection that never rewrites the policy, and no self–other boundary. SEAA closes a loop—(i) an HMM encodes long-term behavioral inertia as an editable transition matrix, (ii) a Reflexion-style verbal metacognition loop updates those HMM parameters rather than merely appending text, and (iii) initially identical agents continuously compare behavior in a multi-agent social environment. A language-model-free prototype spontaneously breaks symmetry into distinct stable personalities; with a hosted LLM, five-agent deliberation grows a consensus hub and a unanimously rejected outlier. Epistemologically agnostic: behavioral emergence only, no qualia claims. Multi-agent harness idea for Tal: make reflection edit inertia parameters, not only append memories.

### Verifiable Social Reasoning for LLM Assistants

https://arxiv.org/abs/2609.17496

Taubenfeld, Gekhman, Grinstein-Dabush, Laish, Goldstein, Croak, Hassidim, Matias, and Feder note that daily social-advice assistants are hard to evaluate: the model learns situations from subjective user narratives, and properties like others’ intentions usually lack ground truth. Fuse is a multi-agent simulation where a target agent with a hidden motive interacts with others (including a user stand-in), who then consults the evaluated assistant to infer that motive—verifiable ground truth by construction, validated with 24k human annotations. Across 12 LLMs, user mediation compounds social-reasoning difficulty, models show systematic sensitivity to biased user framing, sometimes need more detail than humans, and longer conversations do not always help. Framework and a 21k-example dataset are open-sourced. Social-assistant eval for Tal: test motive inference under mediated noisy narratives, not clean third-person prompts.

## LLM security

### Universal Defenses for Tool-Integrated LLM Agents Against Adversarial Attacks

https://arxiv.org/abs/2609.16098

Li and Wang unify practical defenses for tool-integrated LLM agents across direct prompt injection, indirect prompt injection, memory poisoning, and backdoors. Under the hood they ship two tool-level moves—Attacker Tool Filtering (Isolation Forest anomaly detection to drop suspicious tools) and Normal Tool Recalling (restore the agent’s original toolset before planning)—plus prompt-side Chain-of-Thought, self-reflection, and task paraphrasing. Across Gemma2-9B, Qwen2-7B, LLaMA3-8B, LLaMA3.1-8B, and GPT-3.5/4/5, Attack Success Rate often falls to 0% while original task success holds or improves. Modular defense stack for Tal: filter and recall tools outside the prompt loop before you trust prompt-only mitigations on MCP/tool agents.

### Can We Stop The Ads? Taxonomy and Characterization of Smartphone Splash Ads and Existing Countermeasures

https://arxiv.org/abs/2609.17316

Keyword hit is “jailbreak” in the smartphone root/jailbreak sense, not LLM jailbreaks—kept with that caveat. Zhang, Liu, Shao, Yang, and Long taxonomize splash-ad harms (delayed emergency response, accessibility breakage) and audit 108 documented advertising defenses for deployment barriers: device rooting or jailbreaking, runtime code injection, app modification, extra permissions, rule maintenance, or payment. In an evaluation of 13 configurations of 11 tools across 10 popular apps, only one prevented the target ad-triggered navigation everywhere—and it needed Accessibility permission, with ads still visible for about a second. Peripheral cs.CR item; useful mainly as a reminder that “jailbreak” in this category often means device privilege escalation, not prompt attacks.
