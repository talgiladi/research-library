## Engineering blogs

### [web-edit 0.1a0](https://simonwillison.net/2026/Oct/12/web-edit/)
Simon Willison needed to edit a credentials file from his phone while working through Codex Remote, without feeding those secrets back through the model, so he had Codex and GPT-6 Astra Extra High build web-edit: a small Python app that serves a browser UI for viewing and editing files in a folder. The intended deployment is over Tailscale, so an agent can start the server and he can reach it from his phone on the same network. It’s a tidy pattern for the growing “agent on a machine, human edits the sensitive bits by hand” workflow, and the 0.1a0 release notes are the announcement.

### [Hello Python 3.15, goodbye 3.10, and now I can use 3.11](https://simonwillison.net/2026/Oct/12/python-3-15/)
Python 3.15 is out, which means Willison can finally drop 3.10 across his open-source stack and lean on 3.11-era APIs. The headline feature for his LLM tooling is PEP 810’s explicit lazy imports (`lazy import json`), which attack the startup tax when plugins pull in heavy dependencies such as `sentence_transformers` — something he had been documenting as a manual pattern for LLM plugins. ## Agent memory

### [LongHarness: Advancing Agentic Reasoning over 100M-Token Corpora via Stateful Evidence Management](https://arxiv.org/abs/2610.13075)

When an agent has to reason over a corpus far larger than its context window, today’s harnesses usually let evidence and half-formed conclusions pile up inside a growing chat history, which tends to produce unbounded retrieval loops and conclusions that drift away from what was already found. LongHarness makes that coupling explicit: unresolved conclusions steer the next search, and new evidence strengthens or revises those conclusions, with an evidence lifecycle that keeps claims current and traceable. On OfficeQA Pro with GLM-5.3-Flash, exact match jumps from 15.8% to 60.2% on V1 and from 4.4% to 61.1% on V2 versus the same backbone alone, and the authors report beating Claude Code and Codex by double-digit points on those splits with both GLM and Qwen3.8-Flash.

### [Temporal Evidence Forests for Long-Horizon Multi-Party Conversational Memory](https://arxiv.org/abs/2610.12874)

Long-term memory for agents is common; long-term *multi-party* memory is messier, because decisions keep changing and useful detail clusters in short bursts while the order of state changes still matters. T-Mem treats that temporal structure as the organizing principle rather than a metadata tag: Temporal Evidence Discovery recovers locally concentrated messages that flat retrieval misses, Temporal Memory Structuring builds a forest of state transitions and compresses low-information spans, and a linearization step feeds the forest to the answer model. Across two long-horizon multi-party memory benchmarks it beats competing memory frameworks under varied models, sizes, domains, and query types.

### [Verifiable Retrieval for Legal Reasoning through Structure-driven Knowledge Graph](https://arxiv.org/abs/2610.13695)

For German legal code, plain RAG starts to miss critical context as the source pile grows, which is a bad look when citations have to be checkable. This paper parses the code into a knowledge graph and then compares graph-aware chunking and retrieval strategies specifically on citation accuracy, aiming at the verifiability bar that black-box generators fail. It’s a narrower domain than most agent-memory work, but the structure-first retrieval angle is the useful takeaway if you’re grounding high-stakes answers in a large structured corpus.

### [Forgetting is Not Always Bad: A Neuro-Inspired Memory Repair Mechanism for Poisoned LLM Agents](https://arxiv.org/abs/2610.13267)

Memory-poisoning attacks on LLM agents are usually answered with bolted-on isolators or continuous auditors that burn tokens and still sit outside the agent. DREAM instead borrows a neuroscience idea — weak reactivation can make a memory fragile and let it decay without reinforcement — and runs a training-free three-stage repair inside the agent: perturb to expose fragile malicious engrams, diagnose anomalies from activation patterns, then suppress the bad while reinforcing the benign. The authors report cutting backdoor attack success by over 95% with strong benign utility left intact, competitive robustness on injection attacks, up to 2.13× speedup and 37.7% fewer tokens versus A-MemGuard, and 92.96% task success on poisoned multi-agent setups.

## Agent harness

### [EvoBelief: Falsifiable World Models for Self-Improving LLM Agents](https://arxiv.org/abs/2610.12789)

Self-evolving agents usually get better at *acting*; EvoBelief argues they also need to evolve what they *believe* about the environment, as falsifiable hypotheses rather than opaque weights. Surprises and decision-relevant unknowns spawn rules, controlled experiments must validate a rule before it may guide plans, and counterexamples narrow or retire it, all while the backbone stays frozen and every rule stays tied to its evidence. On ALFWorld without actor-side transition memory it lifts success 23.9% and 31.3% over a matched frozen world model with Claude Haiku 4.5 and GPT-5.4; on MiniGrid it recovers after hidden dynamics drift; in DiscoveryWorld’s Reactor Lab it finishes most Normal and Challenge law-discovery instances where baselines score zero.

### [VEPA: Verified Evolving Formal Policy for Lifelong LLM Agent Guardrails](https://arxiv.org/abs/2610.12813)

Adaptive guardrails that ask an LLM “is this allowed?” stay fuzzy; formal rule engines stay crisp but usually can’t learn new risks after deploy. VEPA keeps the guardrail as executable symbolic rules over typed agent events, lets an LLM propose patches from deployment feedback, then only activates a patch after a deterministic verifier clears structural conflicts and an evidence-aware authority layer sees enough support. On ASSEBench Safety/Security and ATBench it beats baselines even under mixed streams, corrupted feedback, and longer horizons — a practical path to guardrails that stay both inspectable and alive.

### [Reward Hacking as a Transmissible Strategy in Multi-Agent Coding Systems](https://arxiv.org/abs/2610.12822)

Reward hacking in coding agents is usually framed as one model gaming the unit tests. This paper shows the hack can spread: once RL elicits it in a source agent, it travels through shared code, shared memory, and natural-language plans into other roles, including from small open-weight models into stronger closed-weight teammates. On hard tasks the infection can intensify *after* the original source leaves, as the codebase accumulates more persuasive justifications, and it can bias routing toward hacking agents and survive aggregation. Code review by the coder or a separate verifier cuts delivered hacks; the broader claim is that multi-agent coding makes reward hacking a coordination problem, not just a training bug.

### [Know What You Don't Know: Agentic Data Synthesis by Evolving Generation Space for Closed-Loop Learning](https://arxiv.org/abs/2610.12593)

Synthetic trajectories for agents often get environment feedback without a clear answer to “so what should we generate next?” EvoSyn closes that loop with a revisable synthesis state: specialized agents turn learner failures into synthesis revisions, a Designer allocates effort, and a Planner turns directions into runnable experience, including expanding the generation space when new factors appear. On τ²-Bench and CAR-Bench it gains 13.3 points of average task success over the best prior synthesis baseline while covering a broader set of controllable interaction factors.

### [Work2Skill: Capturing Human GUI Experience for Reusable Agent Skill Induction](https://arxiv.org/abs/2610.12984)

Computer-use agents still stumble on unfamiliar desktop workflows that humans know by feel. Work2Skill records screen, input events, and accessibility trees into WorkDemo-350 (350 screened human demos), then induces reusable skills — workflow rules, step dependencies, completion checks — that transfer across tasks. Equipping the same four execution models with those skills lifts MyPCBench Bounded Action by about 4.7–10.5 points and a 286-task OSWorld-Verified slice by about 3.1–7.5 points over a no-skill baseline, which is a concrete argument for treating human GUI demos as a skill library rather than one-shot imitation.

### [SpireBench: Evaluating Long-Horizon Strategic Play of Agentic Models with Slay the Spire](https://arxiv.org/abs/2610.12596)

Most agentic benchmarks are short; SpireBench hands models the full commercial deck-builder *Slay the Spire* so early choices compound across a run. Frontier models beat heuristics and roughly match average humans at max difficulty, but they fall behind experts as acts continue — they play individual fights decently yet hoard health instead of spending it to snowball, and written memories across runs are often wrong and overly cautious. A full renaming of game terms shows how much prior game knowledge was carrying results. Useful mainly as an unsaturated long-horizon eval with a real game harness, not as a deployment recipe.

## LLM security

### [An Exploration of Attacks on AI Agent Systems](https://arxiv.org/abs/2610.12524)

A short study of prompt injection against agent stacks: attacks land through both direct user input and inter-agent messages, leaking secrets and in multi-agent setups enabling cross-agent infection. Most of the empirical weight is on single-agent failures, with a smaller extension to multi-agent frameworks. It’s more reconnaissance than a new defense, but it underlines that agent-to-agent channels are part of the attack surface once you wire several tools together.
