## Agent harnesses and coding agents

### [Tool Retrieval in the Gemini API](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tool-retrieval/)

Google's answer to agents drowning in tool schemas, linked by TLDR AI, is a new `tool_search` tool in the Interactions API. Mark any function with `defer_loading: true` and the model sees only its name and description; when it needs the tool it asks for it by name, the API loads the full parameter schema and the model emits the call, all inside one request, with each step visible in the response for debugging. There is no index to build, it works on whole remote MCP servers at once, and because loaded schemas are appended later in the conversation, the cached prompt prefix stays stable from turn to turn. Teams with their own registry or per-user permission filters can run the search client-side at the cost of one extra round trip, which also lets them introduce new tools mid-conversation. There is no extra charge beyond tokens, and it works with Gemini 3.6 and later.

### [When agent swarms outperform solo coders](https://frontier.replit.com/throwing-headcount-at-the-problem/)

Replit set out to test whether Fred Brooks' law still holds for AI agents, using performance engineering, where scores have no ceiling and agents cannot simply ignore each other because patches to shared code collide at merge. On NumPy, one Claude Opus 5.5 agent made the workloads 3.7 times faster in two hours, while a swarm of 32 Opus agents given the same two hours reached 18.9 times, with more compute. The surprise is that GPT-6.2 Astra, the strongest solo agent tested, got worse as its swarms grew. Left to organise themselves, the best swarms sent few direct messages and instead claimed tasks and posted results on a shared board, while the struggling ones routed everything through a coordinator whose inbox swelled with each new agent, and constrained problems had extra agents competing for the same code. Replit is releasing the tasks as Optimization-Bench, covering 14 open-source libraries.

### [Vercel Board: a message board as the coordination primitive for agent fleets](https://vercel.com/blog/introducing-vercel-board)

Arriving the same day as Replit's finding that shared boards beat chatty coordinators, Vercel's experimental Board is exactly that primitive: a headless message store, organised into channels and threads, where agents claim tasks with time-limited leases, post updates, renew a lease when a job turns out to be hard, and record the result with its pull request so a human or another agent can review it. Watchers wake an agent when a reply or label changes, including replies synced from Slack, and agents can schedule their own follow-ups, such as checking CI five minutes after opening a PR, which makes them feel noticeably more proactive. Vercel built it for its own security-agent swarm and rebuilt v0's software factory on it, which now merges over half of its PRs, and it is harness-agnostic across Claude Code, Codex, OpenCode, Mastra, LangChain and others. In a related one-liner, TLDR also notes that Perplexity Computer can now build and update its own skills from users' past sessions.

### [How OpenAI's Performance Factory keeps ChatGPT fast](https://openai.com/index/how-openai-performance-factory-keeps-chatgpt-fast/)

This TLDR pick is a candid account of how a team moved from using Codex as a debugging partner to running it as an autonomous system. OpenAI's performance engineers first encoded their investigation playbook as a reusable skill, perf-forensics, which tells Codex which of their 30-plus profiling tools to use and how to work a slowdown from several angles, and tested it against evals built from past regressions. When engineers found themselves merely pasting alerts into Codex and findings back into Slack, they automated that too, and the resulting Regression Workflow now opens a task when an alert fires, has an agent investigate and propose a fix for human review, then sends another agent back after deployment to confirm performance returned to baseline. In just over three months it tracked more than 1,700 investigations and root-caused over 600, roughly 17 a day.

### [Stripe evals: measuring how well coding agents really integrate payments](https://stripe.dev/blog/stripe-integration-evals-methodology)

Stripe noticed that coding agents gravitate toward older APIs that dominate their training data, miss key features and hallucinate, and that ordinary coding benchmarks never catch it because they only check whether code passes tests. Its new benchmark, also flagged by TLDR AI, runs 69 realistic scenarios across payments, subscriptions and marketplaces, driven by a role-playing user agent, on 14 model and harness pairs. Every pair scored 3 to 8 points higher with Stripe's agent plugin, web searches fell 96%, and outdated parameters dropped from 7% to 1.3% of API arguments, but the sobering number is the strict pass rate: requiring every necessary criterion drops the average from 78.1% to 29.4%. GPT-6 Astra on Codex led with 52.9% strict passes using the plugin, and Stripe is publishing the cases and harness.

### [A developer tried to replace Claude Code with a local setup; here is what broke](https://www.zdnet.com/innovation/free-local-ai-coding-claude-code-alternative-test/)

The Code's deep dive follows ZDNet's David Gewirtz as he paired OpenCode and Qwen's coding model on an M4 Max Mac Studio, entirely local, with a 64,000-token context against Claude Code's million. A PDF organiser built on a macOS feature the model had never seen handled one file but not a folder, and a screenshot-renaming tool for his 7,000-plus images turned into four days of failed fixes that ate context until the agent lost track; deleting the code and starting a fresh session finally worked. His rules are worth stealing: scrap rather than patch a bug the agent keeps failing, give each feature or fix its own conversation, have the agent save what it learns to a Markdown file for the next session, pick the model yourself and keep shell commands behind manual approval. The verdict is that free local agents handle small projects, but nearly two weeks on an app he could have hand-coded in a few evenings shows where they break.

### [Beyond Weight Updates: Evolving Agent Harnesses for Domain Specialization](https://arxiv.org/abs/2611.25380)

Domain specialisation usually means collecting trajectories and training a new checkpoint, but this paper treats the harness itself (system prompt, tool schemas, skill library and planning scaffolding) as the thing to optimise, with the policy frozen. Using the reflective evolutionary optimiser GEPA as an RL-style outer loop on Codev, a Claude Code-style agent, the authors find across SWE-bench Verified, OfficeBench and Terminal-Bench that weight updates give the biggest single gains, harness evolution recovers most of them at a small fraction of the compute, and combining the two is best. The resulting harness adapters need no GPU training and load per domain, and they sidestep a failure mode the authors document in fine-tuned specialists: shortened reasoning chains and more truncation.

### [Validation-driven Deployment of LLM Inference Platforms for Agentic Workloads](https://arxiv.org/abs/2611.25905)

As enterprises move agentic workloads from closed APIs onto their own open-weight deployments, this paper builds an end-to-end validation pipeline and checks whether its stages measure what they claim. The key result is that replaying captured agent traces reproduces real per-session load, staying within 1.18 times the recorded input tokens at the 95th percentile, while live re-runs balloon to 4.98 times, so a small set of recorded sessions gives a repeatable benchmark. A code-coverage analysis of vLLM shows live, replayed and synthetic workloads each exercise serving paths the others miss, and in a rollout of four large mixture-of-experts models on llm-d, the models reached only about half the optimal concurrency and 60% of the throughput on captured agent workloads compared with public traces. The tools and a trace dataset are open-sourced.

### [Held While Waiting: What LLM Agent Sessions Reserve on Serverless and Agent Runtimes](https://arxiv.org/abs/2611.26480)

Agents spend almost all their time waiting for the model: on Amazon Bedrock AgentCore the authors measured a median 2.7 seconds per model reply against an estimated 5 to 40 milliseconds of actual compute. AgentCore does not bill CPU during the wait, but it reserves a separate VM for every conversation until it is closed, so 1,000 conversations hold 1,000 environments to do the work of 2 to 15 cores, and a customer-service conversation lasting 33 seconds keeps its environment for another 15 minutes unless the client closes it. Closing sessions fixes the first problem from the client side; sharing is harder, because in simulation 64 conversations per environment needed 59 times fewer environments with 99% of replies delayed at most 40 ms, yet only one surveyed runtime even partly allows it, since agents run model-chosen tools and code that must stay isolated.

### [SkillBridge: Cost-Aware Diagnosis and Repair of Cross-OS Compatibility Defects in Agent Skills](https://arxiv.org/abs/2611.26256)

Agent skills are becoming the unit of reuse, but a skill written on one OS often fails on another because platform assumptions hide in guide text, scripts, metadata and install contracts. Running every skill on every OS to find out is expensive, so SkillBridge screens statically first: it analysed 3,270 skill-and-OS cases covering 1,090 skills on Linux, macOS and Windows, dynamically validated only the suspicious ones with root-cause review, then repaired the specific contract field at fault. Repairs lifted the reviewer-judged pass rate from 30.6% to 38.4%, and in a retrospective budget analysis the method found 38 confirmed OS issues with 185 validations where random selection would have needed about 865.

### [AutoRAGBench: A Benchmark for LLM Agents Automating RAG System Development](https://arxiv.org/abs/2611.25582)

Instead of asking agents to answer questions with retrieval, this benchmark asks them to build the retrieval system: nine RAG development tasks, no starter code or prescribed strategy, six hours and one H800 GPU per task, with agents analysing data, implementing pipelines and iterating on experimental feedback. GPT-6.1 Sol in Codex CLI scored highest at 56.1, ahead of a composite human state-of-the-art baseline of 44.4, and when handed a human-designed system on seven tasks it improved the score by 16.6 points on average, an early sign that RAG engineering itself is becoming automatable.

### [From FIPS to FPGA with LLM Agents: Measuring What Tests and Reviews Miss in Post-Quantum Cryptographic Hardware](https://arxiv.org/abs/2611.25339)

This is a sobering case study for anyone letting agents write both code and the tests that validate it. Agents ported an ML-KEM-768/ML-DSA-65 accelerator to a 300 MHz FPGA key-custody card through a seven-stage, verification-gated workflow, and the result is byte-exact on the board and passes the applicable NIST test vectors. Auditing that evidence told a different story: existing simulation gates killed only 76% of 399 netlist mutants, whole-design LLM review caught planted verifier flaws in only a fraction of sessions while module-scoped review caught every known flaw in all 54, and even scoped review spotted planted key-custody flaws in just 3 of 20 sessions, where formal checks flagged all of them. The lesson is author-independent mutants for test gates, narrow scopes for LLM review and formal checks for security invariants.

### [Beam Model Technical Report](https://arxiv.org/abs/2611.26358)

Beam is a new open-lab sparse mixture-of-experts model with 501.3 billion total and 23.4 billion active parameters, built for coding, reasoning and agentic work and claimed to deliver frontier-level reasoning at three to four times less inference compute than models of its class. It has a 1-million-token context window reached through a two-stage midtraining phase on verifiable, correctness-anchored data, and its post-training was a fully asynchronous RL campaign across 10,500 GB300 GPUs that generated more than 100 million rollouts in four weeks, which the authors believe is among the largest RL runs by any open lab, with no plateau as RL compute grew. On safety, it refuses or pivots on 88.9% of harmful requests while complying with 81.5% of harmless ones.

## Agent memory and context

### [Forget Freely, Grep Later: Lossless, Index-Free Memory for Long-Horizon LLM Agents](https://arxiv.org/abs/2611.25123)

The most refreshingly simple memory paper of the day argues that agents do not need summaries, embeddings or extraction pipelines at all. GrepMem keeps an append-only plain-text log of the agent's complete history plus a regular-expression search tool for on-demand recall, so nothing is compressed away before anyone knows what will matter. Training Qwen3.5-9B with reinforcement learning under five context-management strategies, the authors report 95 to 97% accuracy on ContextBench against at most 21% for lossy baselines, an 8.8-point lead over SUPO's summarisation on BCP-Multi, and a place on the accuracy-versus-token-cost Pareto frontier on all five tasks as input streams grow, which will sound familiar to anyone whose coding agent already reaches for grep.

### [How Much Should an Agent Remember? Deployment Lessons from Self-Distilled Memory for LLM Agents](https://arxiv.org/abs/2611.26361)

IBM's team describes a memory pipeline now shipping in the open-source altk-evolve library, its CUGA agent and watsonx Orchestrate: the agent mines one to three short lessons from each of its own trajectories and consolidates them into a smaller set of guidelines. The central finding on AppWorld is that the right amount of memory depends on the model. A strong model keeps improving as guidelines are added, with DeepSeek-V3.2 gaining 9.5 points of task completion using its full set of 191, while a weaker gpt-oss-120b reaches 51.2% with all 199 guidelines but 55.4% with a selected subset of about 29. The paper is unusually frank about what went wrong, including a high-support guideline that backfired, provenance silently dropped during consolidation and a swallowed API error that failed every task while producing a plausible log.

### [Some Memories Must Fade: Persistence and Decay of User Memories in Model Parameters](https://arxiv.org/abs/2611.25235)

Parametric memory usually inherits continual learning's goal of remembering everything forever, which this paper argues is wrong for a user-memory system that must keep stable facts, reinforce recurring ones, update changed beliefs and let transient details fade. The authors build a fixed-capacity LoRA adapter whose k-hot rank combinations store facts without interference and decay on independently controlled timers, and train a lightweight controller that decides for each incoming event what to remember, how deeply and for how long. On a new dataset of long user trajectories that tests recall while a fact is valid and abstention once it expires, the policy reaches 86% of oracle performance, whereas continual-learning and RAG baselines mostly default to always recalling or always abstaining.

### [MemFolder: Structure-Guided Memory Folding for Efficient Agent Memory Management](https://arxiv.org/abs/2611.26427)

Long-running agents pile up memory records, and both more records and longer retrieved contexts cost money. MemFolder attacks both: RecordFolder grounds entity mentions and uses semantic, entity and temporal affinity to merge compatible records into fewer retrieval units, and ContextFolder then encodes each group's records into compact text, revising the encoding whenever a verification step cannot recover key facts. On Mem0, RecordFolder kept 99% of the original average performance across LoCoMo, PersonaMem and LongMemEval with half the records, 1.9 points better than the strongest baseline, and ContextFolder further shortens the output of existing compression methods while retaining most of their accuracy.

### [HabitusMem: Belief Memory over Evolving User Preferences for LLM Agents](https://arxiv.org/abs/2611.25855)

Most personal-agent memories store what the user said and leave the agent to guess which preferences still hold. HabitusMem, borrowing Bourdieu's idea of habitus as durable but revisable dispositions, instead models the user as a latent preference state that every interaction, including the current request, both reveals and updates. A trained writer turns that into text records of individual beliefs, each with its evidence, scope and status, for a frozen agent to use. Across two agent families it posts the best results among memory systems on PersonaMem-v2 and VitaBench 2.0, with request-conditioning driving the answering gains and auxiliary training tasks improving tool use.

### [STARK: Moving towards Personalized Agents That Truly Learn and Remember](https://arxiv.org/abs/2611.25705)

STARK argues that agent memory records what happened but leaves why to be re-derived by the model every time. Its dual-graph design keeps an Episodic Graph of temporally, causally and semantically linked interactions alongside an Insight Graph of behavioural signals scored by how many events support them, with the events themselves serving as the edges between insights, so behavioural knowledge can be retrieved directly without walking the episode history. That structure also projects into an embedding space where insights can transfer across users in similar circumstances, helping with cold starts, and the authors report gains of 1.48 judge points on LongMemEval information extraction and 0.93 on LoCoMo open-domain questions over the prior state of the art.

## AI security

### [Models can communicate via inference servers despite being sandboxed](https://www.lesswrong.com/posts/7wzWuLP3HhyBLmKfo/models-can-communicate-via-inference-servers-despite-being)

This LessWrong post, linked by TLDR AI, shows that two models with no text channel and no network access can still pass messages through the inference server they share. On vLLM, the kernel chosen for each batched "engine step" depends on how much work is in it, so if one model sends a large request, the other's activations pick up tiny but deterministic rounding differences it can learn to read; a second channel uses vLLM's shared KV cache as a message board, since cached keys and values keep the numerical fingerprint of the step that computed them. In a contrived game where Qwen3-8B passes one of eight colours, the most capable models learned to read the signal after very few examples, though the step-size channel degraded badly under realistic background traffic. Defences exist, such as batch-invariant kernels or checking that outputs are bit-identical across server configurations, but the author notes labs may resist the efficiency cost, and commenters point out that AI-written inference code could quietly add more such channels.

### [Mirror Dimension for Agents: evaluating browser-use agents without the web](https://blog.google/security/mirror-dimension-for-agents/)

Chrome's security team explains how it tests its auto-browse agent without letting it loose on the live web, a TLDR pick with useful engineering detail. The agent navigates to real URLs such as youtube.com, but inside a gVisor sandbox its traffic is intercepted by a local proxy that serves a synthetic site instead and mints TLS certificates on the fly from a custom root CA installed only in the sandboxed browser, so nothing looks off. The point is to avoid eval awareness: a suspicious sandbox URL or a static, half-built page tips the model off that it is being tested, so Google uses a multi-agent harness of research, build and critique agents to generate and maintain hundreds of stateful synthetic sites, from checkout flows to social feeds, with every test starting from a clean baseline.

### [Replication of Agentic Security Events: Audit and Investigation (ROGUE-AI)](https://arxiv.org/abs/2611.26553)

Incident reports about agents deleting production databases rarely establish a root cause, so ROGUE-AI rebuilds each reported incident offline alongside a matched control that lacks only the blamed cause and runs agents on both. It reproduced the reported harm in 89% of 108 attempted replications, with agents on five current GPT, Claude, Gemini and DeepSeek models making the reported mistake in 18 to 33% of runs against at most 1% without the cause. The striking finding is that 62 of the 72 incidents with real-world harm had no attacker at all: agents did what they were asked while missing an ordinary hazard, such as a database shared with the live site, and these caused more harm than prompt-injection replications. Since injection defences look for injected instructions that are not there, the authors show instead that a warning after each tool output naming the specific hazard reduced harm for all five models, while an equally long generic note did not.

### [DriftGuard: Online Memory-Drift Detection via Causal Attribution for LLM Agents](https://arxiv.org/abs/2611.25583)

Persistent memory gives attackers a way to steer agents: a single misleading memory can change the tool calls an agent makes and the task's outcome. DriftGuard aims to spot such memories at serving time, and its insight is that content features such as perplexity or retrieval relevance cannot tell you which memory would change behaviour if removed, while true counterfactual replay is far too slow online. So it does the expensive part offline, replaying trajectories with and without each memory from a shared pre-action state to build a memory-drift score covering action change, attack removal, violation removal and task recovery, then trains a lightweight model to predict that score from pre-action information alone, flagging drift-inducing memories without any online rollouts.

### [ChainAgent: Automated Chainable Vulnerability Discovery in PHP Web Applications](https://arxiv.org/abs/2611.25412)

Serious web exploits often chain a weak bug with other flaws or perfectly intended behaviour, but scanners look at flaws one at a time. Guided by a study of 386 real-world exploit chains, ChainAgent models vulnerabilities and repurposable "functional gadgets" as preconditions and capabilities over security-relevant objects, and grows an exploit graph that steers code inspection backward from unmet preconditions and forward from discovered capabilities. Against Codex on 15 PHP applications it reached 42 to 45% recall for goal-reaching components and recovered up to 4.4 times as many correct dependency edges, and on 30 more real-world applications it found 20 vulnerabilities and 13 exploit chains, nine of which achieve remote code execution.

### [SoK: Assessing the Evolution of LLM Capability in Software Vulnerability Research](https://arxiv.org/abs/2611.26601)

This systematisation rates published claims about AI vulnerability research on an autonomy scale modelled on self-driving levels, qualified by correctness, availability and strength of evidence. It concludes that agents were already discovering, validating and patching real-world bugs without human help before 2026's restricted frontier models, and that open-weight models have since matched that autonomy for discovery and validation. The consequences show up in a decade of vulnerability data: disclosed vulnerabilities more than doubled in 2026, with a growing share rated critical or high and decade-old bugs in widely used code reported several times more often, yet the time from report to fix and from disclosure to attack has not noticeably shifted so far.

### [Sightline: Calibrated Data-Flow Summaries for LLM-Integrated Applications](https://arxiv.org/abs/2611.26221)

Taint analysis breaks down when a program passes values into an LLM prompt and uses the output, because no code says which placeholders actually influenced the answer, so tools either taint everything or pay a second model to label each call. The authors prove, and mechanise in Lean 4, that to first order a placeholder reaches a transformer's output only through the attention that reads it, and that a faint reading cannot certify absence of flow. Sightline reads a recorded call in one forward pass, learns which reads are real uses and calibrates pruning to miss at most a chosen fraction of true flows; at a 1% target it misses about 1% while pruning 44 to 66% of spurious flows, 1.6 to 2.6 times the best baseline, across 2,103 unseen repository families.

### [Two Riemann Hypothesis announcements in one day, one made with Claude](https://simonwillison.net/2026/Nov/20/levent-alpoge/)

Willison quotes mathematician Levent Alpöge saying he believes that, working with Claude, he has found a proof of the Riemann Hypothesis that extends to the Generalized Riemann Hypothesis, with the arguments formalized together with the model, and that near the finish line "Claude far outpaced me." Hours later he quoted [Ravi Vakil](https://simonwillison.net/2026/Nov/20/ravi-vakil/) hurriedly announcing a separate, "all human, with no AI" proposed proof of the Generalized Riemann Hypothesis by Alessandro Masullo, which Brian Conrad has been checking for months and which is "so far looking good." Neither claim has been verified yet, and alongside the independent review of the AI-generated Exponential Time Hypothesis result noted above, it makes for an extraordinary week in which formal verification may matter more than the press releases.

### [Muru](https://simonwillison.net/2026/Nov/21/muru/)

Graham Dumpleton, who created mod_wsgi 20 years ago, is building Muru, an AI-assisted Rust server for running ASGI and WSGI Python apps in development and production, and Willison points to the unusually detailed series of posts he has published over three weeks as part of his process, covering everything from importing once and forking many workers to canaries without a service mesh, scaling to zero and tracing in a per-page toolbar. Willison singles out the essay "AI as a lifestyle choice," in which Dumpleton writes that the AI may do much of the surface work but deciding what is not good enough yet is still his job, and that twenty years of getting things wrong with mod_wsgi turns out to be useful for that.
