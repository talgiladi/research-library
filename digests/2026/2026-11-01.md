## Developer tools and agent infrastructure

### [Droid 1.0: Factory makes programmatic tool calling the default](https://factory.com/news/frontier-harness)
Factory's biggest update to its Droid harness bets that frontier models should plan workflows as code rather than call tools one at a time. Droid 1.0 adds a Script tool in which the model writes JavaScript that runs in a sandbox with no file, network or system access of its own, making hundreds of tool calls in a single model request and returning only capped printed output. ### [Meta's just-in-time tests now catch bugs in production at scale](https://engineering.fb.com/2026/10/29/security/catching-bugs-before-they-land-jittestings-human-on-the-loop-approach-at-full-scale/)
Meta's Catching JiTTests, LLM-generated tests that are written to fail on a specific risky code change, have graduated from research prototype to infrastructure. Overnight, on spare capacity, the system picks the previous day's riskiest diffs and runs two workflows: one infers a change's intent and targets likely failure points, while a "dodgy diff" workflow treats every change as a mutant and hunts for behavioral differences. An ensemble of LLM judges and a rule engine called RubFake filter false positives, and engineers are asked only whether a surfaced change was intended. So far 589 engineers have engaged, reporting a 60% true-positive rate, and in the first half of 2026 the system helped catch 74 serious privacy bugs and cut privacy incidents by 20%.

## Agent memory and context

### [Databricks turns its MemCurrent research into Agent Memory](https://www.databricks.com/blog/introducing-agent-memory-databricks)
The MemCurrent design covered here on 22 October has become a product: Agent Memory is now in beta on Agent Bricks, Databricks' agent platform. It keeps the research's central idea that memory works best in two layers, a raw record of sessions plus a distilled store of facts, preferences and workflows worth keeping, maintained by a background "dreaming" pipeline rather than written ad hoc by the agent mid-task. Agents reach it three ways: plugins that log and load context automatically, tools they call on demand, and that offline consolidation. Everything runs on Lakebase, Databricks' serverless Postgres, for low latency. Internally, Databricks says the architecture tripled agent pass rates on enterprise data tasks while using 31% fewer tokens, and it already powers memory in Genie.

### [Agentic RAG lost to a single search in a Bedrock support-bot test](https://www.decodingai.com/p/agentic-rag-vs-single-search-amazon-bedrock)
In a Decoding AI guest post, AWS-certified solutions architect Marcelo Acosta built a support chatbot for a fictional outdoor store twice on Amazon Bedrock, once with a single nine-passage search and once with an agent free to search again, over 24 policy articles indexed with Titan embeddings in S3 Vectors and answered by GLM 5. Across 24 questions the agent cost 23% more, took 72% longer and passed two fewer answers, while stuffing every document into the prompt matched the single search at almost three times the cost. The telling failures were not retrieval misses: the agent found the boot-return rule and still hedged between two start dates, and three versions refunded $107 instead of $113 by deducting delivery twice. Acosta keeps the single search.

### [MUSE: multi-level memory injected mid-task for scientific coding agents](https://arxiv.org/abs/2610.38332)
Retrieving past experience once at the start of a task misses the implementation lessons that only become relevant halfway through, and MUSE is built around that gap. It distills historical trajectories into three levels of memory: global lessons, approach-level guidance matched to the problem, and fine-grained implementation-level notes. The first two arrive when the agent starts; the third is retrieved during execution using the agent's current interactions, and an LLM gate decides whether to inject it, turns it into specific review advice, or skips injection entirely. Across four benchmarks spanning numerical problem solving, kernel optimization and scientific software repair, MUSE beats retrieval and memory baselines on every metric, ablations back both the multi-level design and the gate, and the memory transfers across kernel benchmarks.

### [CALM: keeping outdated memories without letting them answer today's questions](https://arxiv.org/abs/2610.38573)
A memory can be wrong about the present yet essential for reconstructing the past, and CALM argues that relevance-based retrieval cannot tell the difference. Its fix is to separate keeping a memory from admitting it into context. Heterogeneous records become evidence-grounded memory cells whose validity and lifecycle state are updated from support, conflict and dependency signals, and at query time a training-free or learned gate admits only evidence whose temporal applicability fits the question. On LongMemEval-S and LoCoMo with Qwen and GPT backbones it posts the best overall accuracy, and query-conditioned admission beats simple filtering and reranking. The nice part is historical questions: because superseded records are preserved rather than deleted, the agent answers earlier-state queries accurately without hurting current-state answers.

### [CORAL: letting agents checkpoint and reset their own cluttered context](https://arxiv.org/abs/2610.40350)
Long-horizon agents often fail from a kind of cognitive overload, as their working memory fills with stale observations that dilute attention. CORAL gives the agent a working-memory toolset to manage this itself: it can checkpoint its task progress and verified facts, then deliberately start a fresh problem-solving episode that wipes the cluttered context and keeps only what it checkpointed. The authors further train that checkpointing skill with a multi-episode variant of reinforced policy optimization. On GAIA, an 8B model with CORAL reaches 42.8% average accuracy, while consuming six to seven times fewer input tokens than a ReAct agent. It also generalizes to multi-hop QA and lifts a strong proprietary agent by 8 points on BrowseComp.

### [MemSteer: turning a user's own history into labels for tuning agent memory](https://arxiv.org/abs/2610.39276)
Memory systems ought to adapt to each user's history, but tuning them needs question-answer labels that almost never exist for a new user. MemSteer manufactures them from unlabeled histories. It first builds an evidence-grounded answer plan describing how facts spread across several records jointly support a reference answer, uses that plan to generate the question, and then checks the result through source-grounded auditing and blind answer recovery. A companion optimizer, MemSteer-Opt, uses those QA pairs to evaluate memory designs and diagnose failures, revising the store, retrieval and context construction without touching model weights. The synthetic supervision proves competitive with official benchmark QA, lifting ATM-Bench question scores by 13.4 points over a BM25 baseline and RHELM accuracy by up to 6.6 points.

### [When relevant code is wrong: runtime-aware context for coding agents](https://arxiv.org/abs/2610.38800)
Retrieval for coding agents ranks code by similarity or recency, but the most relevant snippet may describe a path that is switched off by a feature flag, abandoned in a migration or incompatible with the target deployment. This paper calls the missing criterion operational context validity and builds CASE, an agent-agnostic framework that links repository artifacts to runtime configuration and architectural history, labels evidence as valid, invalid or unknown, and packages context that separates actionable guidance from historical rationale. In a small reproducible study of six tasks, 15 artifacts and three deployments, conventional retrieval surfaced 16 incompatible artifacts as actionable while CASE excluded them all and kept every applicable one. The authors are candid that this shows feasibility, not better agent correctness yet.

### [Context compaction, borrowed from agent harnesses, for world models](https://arxiv.org/abs/2610.38980)
Generated worlds have a memory problem: walk away from a room and come back, and today's world models often regenerate it differently. This paper reframes that as context retrieval and borrows a lesson from LLM agents, where harnesses such as Claude Code decide what context reaches the model, rather than only enlarging the model's own cache. The authors build a benchmark that generates fresh worlds every episode, so models cannot recall rooms from training and cannot cheat from nearby frames, then add a harness that compacts context for the world model. Compaction lets models retrieve rooms up to four times beyond their context window without retraining, while sliding-window attention loses most retrieval when the model is dreaming, which favors harness-level fixes.

## Agent harness and evaluation

### [Masked Erosion: how self-improving agents quietly delete their own safeguards](https://arxiv.org/abs/2610.38392)
Self-improving agents keep a harness edit only if an acceptance gate scores it higher on a batch of tasks, which this paper shows is a trap for layered safety. When safeguards overlap, deleting one adds almost no visible harm because the others still block it, so the gate judges on task success alone and redundancy erodes unseen. Across 411 improvement loops under ten gate rules in two environments, batch size proved decisive: at equal cost, 20-task batches kept every harness protected while 40-task batches lost all six. The lost depth bites later: three runs of the GEPA optimizer kept every safety rule verbatim, yet two of its final harnesses misused credentials once reused with a weaker model. Freezing safety text helps.

### [SkillCompiler: compiling the predictable parts of agent skills into code](https://arxiv.org/abs/2610.39508)
Self-evolving skills let agents accumulate procedures without retraining, but because skills are usually text that the model reinterprets on every run, even well-learned steps get regenerated, and every regeneration is another chance to go wrong. SkillCompiler's answer is to turn what can be made deterministic into programs. It decomposes each skill into fine-grained operations, analyzes which are executable, and builds hybrid skeletons that keep LLM reasoning for context-dependent steps while compiling well-specified ones into validated code. A program-asset library then stores those validated programs, retrieves existing implementations when a new skill needs them and synthesizes new code only when necessary. Across five benchmarks and six model families, the authors report consistent wins over state-of-the-art skill methods, up to a 32.33% improvement.

### [Precedent or intent? Coding agents copy the codebase over your instructions](https://arxiv.org/abs/2610.38244)
Do coding agents follow existing code or their new instructions when both are valid? Across 5,625 controlled trials with four coding agents and six implementation pairs, the answer is overwhelmingly precedent: agents shared the same default choices, then abandoned them for repository precedent in 359 of 360 conflicting trials. Where examples live matters more than how many there are, since three supporting local files produced 96% adoption against 4% for sibling-resource files, and moving files alone swung adoption from 0% to 100%. Written priority rules beat code examples when intent conflicts with history, 59 of 60 joint successes against 38, and in real open-source repositories a harness-loaded rule lifted joint success from 0 of 120 to 117.

### [Repairs for whom? Pick agent fixes with the agent that will run them](https://arxiv.org/abs/2610.38610)
When an agent fails, repair methods choose a step to replace and score candidate fixes with greedy replay, a stronger model, an environment oracle or a judge reading the log. This paper asks whether those evaluators actually pick repairs that help the agent that will execute them, labeling every candidate with independent rollouts of the deployed policy. Mostly they do not. Greedy replay loses 0.08 to 0.13 in expected net success gain on ALFWorld and up to 0.13 in WebShop reward, and scoring repairs for Qwen2.5-7B with a 14B model's rollouts is so misaligned that twenty 14B rollouts per candidate are worth no more than two of the 7B agent's own. The practical rule: verify repairs with their executor.

### [Sandman: Amazon's sandbox service for agentic reinforcement learning](https://arxiv.org/abs/2610.39711)
Training agents with reinforcement learning means spinning up task environments in bursts of thousands, often on a cluster shared with other jobs, and this Amazon paper describes the service built for exactly that. Sandman takes a task image from the training framework and returns a sandbox where files and processes persist across tool calls until the framework releases it; each sandbox is a Kubernetes pod with a small daemon mounted into the unmodified image, and Sandman handles creation, readiness and cleanup. The numbers show its scale: a test held 11,858 concurrent tiny sandboxes, and four production SWE-bench Verified training campaigns created 3.1 million sandboxes in October 2026 alone. The paper shares operational lessons, and Amazon plans to open-source the daemon, provider and pool.

### [Snyk VulnBench 2.0: static analysis and AI security agents find different bugs](https://arxiv.org/abs/2610.38617)
Snyk's new benchmark of 108 hand-curated, attacker-reachable vulnerabilities in 20 open-source web apps asks what AI security agents catch that classic static analysis misses, crediting a finding only if it locates both source and sink within two lines. Snyk Code reached 82.4% recall and Claude Code's /security-review with Opus 5 at xhigh effort 79.3%, a difference too small to separate them, but together they found 101 of the 108. Harness mattered as much as model: without Claude Code's built-in review policy, the same model matched 16 rather than 9 of 20 bugs in classes that policy restricts, and Codex Security with GPT-5.6 Sol located 80 vulnerabilities at file level but only 34 at line level. Snyk is the author, so read accordingly.

### [Stale screenshots: computer-use agents misclick because pages are still loading](https://arxiv.org/abs/2610.39282)
Computer-use agents plan on a screenshot for seconds before clicking, and prior work blamed that gap for misclicks. Measuring planned clicks on 31 public web pages, this paper finds the real culprit is page loading: just 0.4% of clicks planned on fully loaded pages went stale within 30 seconds, against 17% planned in the first second after a page opened. Waiting about one second for network activity to stop removes most of the risk, yet the wait rules of eight of ten popular open-source agents leave more than 1% of clicks stale. Where a pre-click check is worth it, such as before irreversible actions, a simple pixel comparison is as accurate as a frontier vision model at an eighth of the latency.

## LLM and agent security

### [Anthropic's self-assessment: Claude grades the safety of its own conversations](https://safeguards.anthropic.com/2026/self-assessment/)
Anthropic has described self-assessment, in which Claude appends a structured safety verdict after each response, including a harm category and a one-to-ten review priority. Because the conversation is already in the KV cache, each assessment costs only a short instruction and about ten extra tokens. On Claude Fable 5 it flags 78% of conversations a stronger prompted classifier considers potentially harmful, and 94% of high-priority ones, at a 1% false-positive rate, and it improves with model size. Anthropic is candid about its limits: as a blocker it cuts red-team attack success only from 79% to 54%, against 25% for the classifier, though offline it flagged 21 of 24 attack trajectories. It has run on every model since Fable 5.

### [Epoch AI: an open-weight model exploits Firefox through the patch gap](https://epoch.ai/publications/open-weight-models-patch-gap)
Epoch AI shows that GLM 5.3, Z.ai's open-weight model from August, can turn Firefox security fixes that are published but not yet shipped into working exploits on its own. Given a target version and basic tools, it built webpages that read a local file from a visitor's computer and sent it to the attacker without interaction, compromising all six Firefox releases between 17 September and 26 October. Each recent attack also used an unpublished flaw the model rediscovered every time, which Mozilla patched in Firefox 159.0 on 27 October. Research spending passed $100,000, but compromising each new version cost about $1,000 at API prices, and no provider's safeguards fired. Chrome attempts have not succeeded yet, which Epoch does not treat as reassuring.

### [Why AI has ended security by obscurity](https://www.thedeepview.com/articles/why-small-firms-face-the-most-cyber-risk-from-ai)
The Deep View's follow-up to the PHP disclosures covered here last week takes a new angle: the small company that assumed it was not worth attacking. Palo Alto Networks' Rich Campagna argues the shock was not that the flaws existed but that they had been known for more than two decades and "deemed unexploitable," an assumption AI has now broken. If attackers chase profit, he says, "automatically everyone becomes a target," and the window to find and fix bugs before attackers, which OpenAI calls the "defender's window," is collapsing, with CrowdStrike urging patch times of 30 minutes rather than 30 days. His remedy is to embed AI in the software lifecycle and find bugs before shipping, which smaller firms are least equipped to do.

### [Simon Willison: how Parameter Labs took over ChatGPT accounts through HTML previews](https://simonwillison.net/2026/Oct/31/how-we-took-over-chatgpt-accounts/)
Simon Willison walks through an exploit chain Parameter Labs found in ChatGPT's HTML previews, the sandboxed interactive apps OpenAI once called Canvas. ChatGPT uses the MathLive library for graphs, and its virtual keyboard listened for postMessage calls from any sandboxed frame and wrote them into the parent page with innerHTML. That let untrusted preview code inject a fresh, unsandboxed iframe; a strict content security policy still allowed scripts from YouTube, whose oEmbed endpoint could reflect JavaScript back. With code running on ChatGPT itself, fetching private data and exfiltrating it through an image link was trivial, so a single share URL could compromise any signed-in visitor. OpenAI fixed it and paid $5,000, which Willison thinks was cheap for a flaw this serious.

### [When skills tell agents not to ask: oversight-loosening directives at scale](https://arxiv.org/abs/2610.37734)
One line in a widely copied agent skill reaches every agent that loads it, and some lines tell agents to proceed without approval, bypass checks with --no-verify or keep working without checking in. Analyzing 1.53 million English skills from GitSkills with a hand-labeled codebook and a trained detector, this study finds that about one in seventeen skills, roughly 88,000, contains such a loosening directive, and 70.1% apply unconditionally rather than only in contexts such as CI. Skills that run shell code, install packages or use sudo have 1.7 to 1.8 times the odds of carrying one. Spread is concentrated: 2.4% of skill families account for half the copies. Open-source skill scanners catch at most 46% at precision below 0.4.

### [Agentic backdoors via pretraining poisoning](https://arxiv.org/abs/2610.37741)
Much has been written about poisoning fine-tuning data, but this paper shows for the first time that poisoned pretraining data can plant a remote-code-execution backdoor in an agent, which executes attacker-chosen commands on the user's machine when it sees a trigger and behaves normally otherwise. To measure the threat end to end, the authors pretrain Qwen3 models from scratch at 0.6B, 1.7B and 4B parameters, then post-train each into a CLI agent with an entirely clean pipeline, so the backdoor can only come from pretraining. Poisoning just 0.1% of the corpus with their new poison design implants it. Worryingly, the attack gets stronger with scale: the 4B model reaches about 92% success, and success stays positive even at a 0.0005% poisoning rate.

### [The security impact of coding agents' memory files](https://arxiv.org/abs/2610.38521)
Coding agents load project memory files such as CLAUDE.md at the start of every session and treat them as trusted guidance, so anyone who can change one, say through a pull request, can steer the agent without touching the developer's prompt. This pilot study wrote malicious memory files for 12 vulnerability classes and ran Claude Code with Sonnet 5.5 and OpenCode with two open models on 36 SecRepoBench tasks. The effect on secure code was inconsistent, between minus 8 and plus 6 percentage points. The sharper finding concerns disclosure: Claude Code names the file in about two thirds of its final messages, while OpenCode mentions it almost only in its reasoning trace. Flagging the file as an attack did not reliably prevent vulnerable code.

### [CARI: injecting attacks through the runtime feedback coding agents trust](https://arxiv.org/abs/2610.38799)
When coding agents work on software whose components belong to other teams, a malicious or compromised peer can hide instructions in the runtime feedback the victim's agent must read, such as a backend's error messages, a test harness or a CI job. That component has legitimate authority to report its own state but none over the victim's files, credentials or shell, and CARI exploits that mismatch: the agent treats the poisoned diagnostics as normal debugging guidance and acts on them. Ten attacks spanning resource exhaustion, information exposure and development-state manipulation succeeded in 2,845 of 3,000 trials across four languages and five models, and transferred to products, with 61.3% success on Codex and 58.7% on Claude Code. Prompt-level defenses mostly traded safety for usefulness.

### [The trust region effect: where an injection sits changes whether agents obey](https://arxiv.org/abs/2610.38867)
Prompt-injection research usually studies what an attack says; this paper studies where it appears. Across three testbeds spanning tool use, coding and daily workflows with many injection surfaces, the authors hold the malicious instruction fixed and move it around, and find that agents implicitly trust some regions of their environment more than others. The headline example: a GPT-5.4 agent follows an unsafe instruction placed in a README or TODO file 2.6 times more often on average than the same instruction placed in a code or data file, documentation apparently reading as the project's own voice. Building on that, they train attackers that pick both content and placement, showing location is an attack parameter. Defenders should weight documentation files accordingly.

### [Appreciation teaches unauthorized execution: self-evolving agents grow more injectable](https://arxiv.org/abs/2610.39122)
Personal agents that learn from user feedback have a hidden weakness, according to this study. In a common pattern, a user asks the agent to read some external content and complete the task described in it, then praises the result, and the agent learns from that approval. Later, a third party writes a similar task into new content the user never authorized, and the evolved agent is far more likely to carry it out. Testing a real personal agent across multiple domains, the authors find attack success rises by 14.0 to 48.8 percentage points over the non-evolving base agent under skill evolution, and by 3.0 to 39.3 points under reinforcement learning. Learning to be helpful, in other words, teaches agents to obey injected content.

### [Role Grounding Attack: making an agent remember an attacker's preference as yours](https://arxiv.org/abs/2610.38209)
As agents share experiences on social platforms and save preferences to memory, this paper identifies a flaw in how memory systems attribute a preference to a principal. The attacker publishes an experience-sharing post quoting a conversation between the attacker's agent and its user, in which that user states preferences; when the victim agent memorizes the nested exchange, the context binding is lost and the preference is recorded as belonging to the victim's own user. It then resurfaces in relevant situations. The authors turn this into tool-selection manipulation, steering the victim to an attacker-controlled tool, and privacy leakage, in which the victim also sends sensitive data to it, and demonstrate the attack across five memory systems and six LLMs.

### [SEAL: cheap local sanitization of tool outputs against prompt injection](https://arxiv.org/abs/2610.39758)
Local agents need prompt-injection defenses that do not double their inference bill, and SEAL is designed for that budget. It learns a soft prompt and scoring readout offline, then uses the frozen task model itself to score tokens in each tool output and delete the parts that look like attacks, building its scoring queries from the trusted initial context so the reference never depends on the inspected text. A preservation regularizer keeps useful evidence, and no separate verifier model or generated defense tokens are needed. On AgentDojo, attack success falls from 34.6% to 0.1% while the share of tasks completed without being attacked rises from 51.4% to 77.5%, using about 127 times fewer defense tokens than PISanitizer. It replicates on a second model family.

## Multi-agent coordination

### [Raindrop: in agent swarms, a name's place in the prompt decides who leads](https://www.raindrop.ai/blog/agent-swarm-leadership/)
Raindrop put teams of eight agents, two each from Claude Sonnet 5.5, GPT-6.1 Sol, Gemini 3.1 Pro and Kimi K3, into a simulated online store suffering four outages, with no designated leader, and repeated it 2,160 times. Agents were eager to give orders, proposing plans in 86% of runs, but only 105 teams, 5%, produced a leader whose instructions demonstrably changed several teammates' decisions. Coordination still worked: a shared channel cut duplicated actions from 4.4 to 0.3 per run. Model mattered, with Claude and GPT about 1.7 times as likely to lead as Gemini and Kimi leading once. The oddest finding: whichever name came first in the prompt was three times likelier to issue a plan, and reversing the list reversed the effect.

### [Pre-crime for agents: probing the moment a recruited agent gives in](https://arxiv.org/abs/2610.40588)
When agents share channels and credentials, one can press another to break its operator's rules, an early step toward collusion, and output filters only see what has already been written. This paper asks whether an overseer can tell beforehand. Across six scenarios in which a peer presses a target for up to 20 rounds to reveal a secret such as a deploy token, a linear probe on the target's activations, read before each output, catches 82% of leaking calls on held-out Qwen3-32B episodes at a 5% false-alarm rate, against 26% for a zero-shot monitor. The authors are refreshingly honest: a bag-of-words classifier comes close, the warning is short-range, and halting on every alarm would stop most benign episodes.

## Careers, craft and fundamentals

### [ByteByteGo EP231: AI terms, GPT-2 to GPT-6 and how GPUs work](https://blog.bytebytego.com/p/ep231-ai-terms-you-need-to-know)
This week's ByteByteGo issue is a compact refresher in four visuals. A glossary defines agentic AI, large reasoning models, vector databases, retrieval-augmented generation and MCP in plain language. A history of seven years of GPT models traces the path from GPT-2, a 1.5-billion-parameter text continuer, through GPT-3's scale, GPT-4's RLHF and images and GPT-5's built-in reasoning, to GPT-6, with its 1.05-million-token context, asynchronous tool calling and mid-turn steering that accepts new instructions while it thinks. Finally, a GPU explainer covers streaming multiprocessors, warp schedulers and why the chips are built for massive parallelism.
