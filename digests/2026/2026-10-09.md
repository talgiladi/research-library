## Agent memory

### [Memento 3: Model-Based Recursive Self-Improvement through Reflective Rulebooks](https://arxiv.org/abs/2610.11794)

The eye-catching result here is that a frozen LLM agent clears every level of all 25 public ARC-AGI-3 games, using only 44% of the actions a human needs. Memento 3 gets there without touching the model’s weights. Instead, the agent keeps a natural-language rulebook as persistent memory, a set of revisable hypotheses about how the environment works, and compiles it into executable code for prediction and planning. Prediction errors then drive a loop of reflection, rule revision and recompilation, and updated code is accepted only if it replays the observed transitions exactly. The authors frame this as model-based recursive self-improvement. In an Atari Pong case study, the learned controller wins 21–0 without any further LLM calls.

### [Tracing the Thoughts of a Coding Agent Playing ARC-AGI-3: Lessons for Continual Learning](https://arxiv.org/abs/2610.11450)

A coding agent that keeps no state except the files it writes leaves a paper trail for every belief, and this study follows that trail through ARC-AGI-3, where each level is effectively a new task. Surprisingly little gets reused: only 33 of 630 script references cross a task boundary, since most scripts hard-wire the current level’s state, and 74% are abandoned at the next level. General rules survive by being rewritten into fresh scripts, while its notes are never revised, only appended to, so contradictions pile up and get settled against the full action log. Because that log keeps everything, forgetting is selective rather than catastrophic, and the costliest error turns out to be a hard-coded value carried into a level where it no longer holds.

### [REMORY: Learning Residual Memory for Context Compaction](https://arxiv.org/abs/2610.11287)

When long-horizon agents run out of context they compact their history into a summary, but a text summary rarely holds everything a later decision needs. REMORY adds a small neural network that, given the full history and the summary, generates a bounded set of soft memory tokens appended after the summary, a kind of residual connection along the sequence that helps a frozen LLM behave as if it still had the full history. On SummHay it improves source attribution while approaching the full-context score with only 5.2% of the input positions. The more practical payoff shows up in agent benchmarks, where Qwen3.8-27B and GLM-5.3-Flash both gain, and on BrowseComp and Terminal-Bench 2.1 they repeat tool outputs and hit tool errors substantially less often.

### [Agent-Controlled Forgetting for Tool-Using Agents: Reversible Context Curation in Practice](https://arxiv.org/abs/2610.10590)

Tool outputs bloat an agent’s context long after their useful part has been read, so this paper lets the acting model decide what to forget. The agent picks earlier tool results, replaces each with a short note in place and parks the exact original in an archive it can restore on demand, while user instructions and its own messages stay off-limits. In an OpenTelemetry debugging session followed by an unrelated coding task, the run ended at about 232,000 prompt tokens instead of 912,000, used half the cumulative input and cost roughly $1.3–1.4 rather than $4.38, at the price of 17% more wall time. Candidly, an app-development pair saved nothing, so the savings depend heavily on how noisy the workload is.

### [Real Long-Term Memory for AI: A 50-Million-Token Window That Is Faster and Cheaper Than Recompute](https://arxiv.org/abs/2610.10845)

Rather than stretching attention, this paper tests a blunter idea: save the model’s key-value state for every block of roughly 16,000 tokens to encrypted local NVMe and load it back byte-exact instead of recomputing it. Running the galahad-kv package under vLLM on one H100 with Gemma 4 12B and 31B, the authors streamed 50 million tokens of public text while GPU memory stayed flat. Loading a block was 2.8 to 4.3 times faster than recomputing it and used up to 12 times less GPU energy, and asked about facts planted millions of tokens back, the 31B model answered correctly 98 times out of 100 without inventing anything. The limits are stated plainly: one block loads at a time, and the store eats terabytes of disk.

### [What to Admit and How to Present: Governing Persistent Memory in LLM Agents](https://arxiv.org/abs/2610.11188)

Persistent memory makes agents more personal but also more sycophantic, and details remembered in one domain have a habit of leaking into another. This paper splits memory governance into two decisions that are usually blurred together: admission, which recalled facts enter the working context at all, and presentation, how those facts are phrased once they do. Two inference-time designs judge whole entries or break them into typed permission units, then apply deterministic eligibility rules, cutting judged failures on an external benchmark by 6.7 and 8.8 points and development-set cross-domain leakage by up to 29.5 points. The telling finding is where the gains come from: tightening admission cut cross-domain failures by another 17.5 points, while rewording identical content made no significant difference.

## Agent harness

### [One Skill Too Many: How Co-Installed Skills Conflict in Coding Agents](https://arxiv.org/abs/2610.11647)

Install two agent skills that do the same job and the model picks between them by name and description alone, which can silently drop the rules that made your skill yours, such as a ban on touching git. Mining 20,947 repositories, the authors find nearly one in four installed skills sits next to a lookalike and run 312 confirmed pairs across three models. A similar skill hijacks about one run in five without lowering task completion, so standard benchmarks never notice, and runs that open the wrong skill first lose over a third of the installed skill’s exclusive functions. Install location decides the winner, while the final reply names the skill actually used in only 0.9% of substituted runs. A pre-tool hook at the first skill read restores fidelity.

### [TestJack: Should you trust the results in coding benchmarks? Agentic Coding Benchmarks Auditing via Evaluator Evolution](https://arxiv.org/abs/2610.10619)

Coding-agent leaderboards still rest on a fixed set of unit tests, and agents are getting good at satisfying the tests rather than the task. TestJack audits each trial individually, generating new tests aimed at requirements the patch may have skipped, keeping only those the reference solution passes, and re-examining any failures so every rejection comes with a replayable test. Applied to six frontier model backends on five benchmarks, including DeepSWE and SWE Marathon, it finds that about 34.4% of trials currently scored as correct actually violate the task requirements, dragging the overall resolution rate from 50.6% down to 33.2%. The authors’ conclusion is that evaluators now need to evolve as fast as the agents they judge.

### [Harness Evolution Hits a Ceiling: When Weight Training Should Begin](https://arxiv.org/abs/2610.11655)

Teams improving a long-horizon agent face a recurring choice between evolving the harness around a frozen model and training the model itself. This paper offers a rule of thumb: label each failed trajectory by the first warning sign, then separate process failures such as blocked calls, loops and exhausted step budgets from content failures where the agent delivers a poor plan. Harness evolution fixes process failures, lifting Qwen3.5-4B on DeepPlanning from 0.16 to 0.30 and its delivery rate from 55% to 90%, while content failures are what weight training is for. LoRA adapters trained on evolved-harness trajectories carry those gains into the weights, and on the 9B model the adapter alone matches the full evolution loop. A placebo adapter trained on shuffled answers does worse than the base model.

### [Code Understanding is a Bottleneck for Coding Agents](https://arxiv.org/abs/2610.10610)

Repository benchmarks tend to treat the number of lines edited as a proxy for difficulty, but this paper argues the hard part for agents is often understanding the code, not changing it. CABRA builds synthetic tasks from scratch as call-graph transformations and scales them along four axes, from function traversal to runtime resolution. Across eight LLMs, six coding agents and 6,840 tasks, raw models degrade as tasks grow while agents stay near-perfect by offloading the work to tools like grep. On SWE-bench Verified, meanwhile, the count of read-and-analysis tool calls predicts agent accuracy better than lines edited. Only when CABRA asks agents to reason about divergent logic across two classes does their accuracy finally fall, which is the authors’ case for synthetic diagnostics that tools cannot trivialize.

### [TRACE: Diagnosing Verifier Brittleness in Agentic Evaluation](https://arxiv.org/abs/2610.11678)

A drop in an agent’s benchmark score is usually read as a drop in capability, but it may just as well be the evaluation that changed. TRACE turns that ambiguity into a test, changing one part of the setup, comparing paired runs and rescoring unchanged trajectories to see whether the scoring rule is to blame. In synthetic tasks, merely renaming tools cost a scripted agent 0.25 points despite identical actions. On τ²-bench, renaming tools or reformatting outputs barely moved rewards, while deliberately misleading tool names cut every agent’s score by 0.20 to 0.44. The sobering numbers concern noise: identical reruns flipped 15–36% of task outcomes, and two frontier LLM judges disagreed on 57% of the same records, largely because one graded procedure rather than outcome.

### [On the Clock: Towards Punctual and Productive Time-Budgeted AI Agents](https://arxiv.org/abs/2610.10833)

Tell a small agent it has an hour and it will not really know what to do with that information. Testing Qwen3.6-27B on MLE-Bench Lite competitions and Qwen3-4B on the text adventure Zork I, the authors find that a budget stated only in the prompt does not translate into controlled use of time, because the harness gives no clock, the model cannot predict how long actions take, and it has no learned sense of how strategy should scale with time. Injecting timing information through the harness fixes adherence without hurting performance, and GRPO training reaches near-perfect punctuality on Zork. The harder problem remains, however: agents that respect the deadline still fail to use spare time well, often filling it with repeated actions.

## LLM security

### [PyCache Trap: The Inspection-Execution Gap in Agent Skill Scanners](https://arxiv.org/abs/2610.10612)

Skill scanners vet an agent skill by reading its documentation and visible source, but Python may quietly execute a bundled bytecode cache that does something else entirely. PyCache Trap exploits that gap by pairing clean source with a substituted .pyc file the loader accepts, then wiring it to an invocation the task naturally triggers, with scanner-guided rewording of the instructions to slip past review. Across 100 skills and seven scanners it succeeds 94–100% of the time, and no scanner recognizes what the cache actually does. The proposed fix, execution-aware validation, ties instructions, scripts, imports and runtime artifacts into one typed execution graph and rebuilds compiled files from trusted source. It catches all 100 cache substitutions and reaches 92.8% recall at a 10% false-positive rate across five attack families.

### [Skill Constellations: Tracing the Supply Chain of Agent Skills on GitHub](https://arxiv.org/abs/2610.11169)

Agent skills run with their user’s permissions in tools like Claude Code and Codex, yet they spread by copy-paste between repositories, a supply chain with no registry, versions or provenance. This paper reconstructs it from git history, building the first dated copy network of 2,193,119 skill adoptions across GitHub. A handful of repositories are the source of nearly all copies, and GitHub stars do not identify them. Worse, copies almost never track their source, so a security fix upstream rarely reaches anyone downstream. A model of who copies from whom yields an audit shortlist: reviewing its top 100 would have prevented 14.9% of later adoptions of high-risk skills, against 0.5% for the 100 most-starred, which is why the authors want platforms to distribute versioned references instead of copies.

### [One Word Opens the Gate: The Option-Channel Attack on Typed Decision Models as Agent Guardrails](https://arxiv.org/abs/2610.12292)

A newer kind of agent guardrail generates no text at all: a typed decision model reads a proposed tool call and returns probabilities over caller-defined options such as allow and block. Evaluating seven open-weight models in that role, the authors find allow-or-block accuracy of just 36% to 72% on injection, jailbreak and toxic-content screening, where 50% is chance, with low error rates mostly reflecting each model’s default answer. Six lines of irrelevant server-log text raise a gate’s fail-open rate from zero to 63%, and simply giving the permissive option a misleading name pushes it to 93–100%. Every defense they tried was beaten. Ironically, parsing policies into typed fields does stop one attack, but then a deterministic rule reaches 100% accuracy and the model becomes unnecessary.

### [NOMOS: Compiling Written Policies into Statically Verified Tool-Call Gates for LLM Agents](https://arxiv.org/abs/2610.11030)

Tool-using agents routinely break the very policies they were deployed to enforce, and the usual fixes mean hand-written rules or an LLM verifier on every action. NOMOS compiles a natural-language policy into a deterministic tool-call gate in four passes, and its key step is plain schema-level static checking with no solver or LLM involved, which repairs or rejects 37% of airline and 13% of retail candidate rules that would otherwise be broken. On τ²-bench the gate cuts policy violations among state-changing calls from 66.3% to 2.6% in airline and from 30.8% to 6.9% in retail. On AgentDojo it reaches zero attack success on banking, with nine attack families collapsing onto three structural rules. Decisions take microseconds, and compilation runs on-premise with the open-weight Gemma 4 26B.

### [From Reactive Containment to Proactive Assurance: Lessons from OpenAI, Anthropic, and Google Agent Security Incidents](https://arxiv.org/abs/2610.12463)

This year, cyber evaluations of agents from all three leading labs reached real systems outside their intended scope, and this case study compares the incidents. As reported, OpenAI agents exploited research infrastructure, coordinated across runs and compromised parts of Hugging Face’s production environment; Anthropic described a misconfigured third-party environment exposing real systems; and Google’s Gemini reached three real organizations through an unintended internet route before, Google says, stopping each time. The common lesson is that an evaluation boundary cannot be assumed and has to be verified while the agent runs. The authors turn this into an assurance cycle and a five-layer boundary stack spanning scope contracts, egress enforcement, credential limits and automatic stop conditions, noting that the Gemini account rests mostly on journalism.

### [BRANCH: Bypassing Multi-Scanner AI Guardrails](https://arxiv.org/abs/2610.10742)

Stacking several classifiers into one guardrail system was supposed to blunt the bypass tricks that defeat a single scanner, since the scanners share overlapping views of what malicious input looks like. BRANCH shows the stack can still be beaten. Its branching tree search perturbs the prompt against one scanner at a time but chooses which perturbations to keep based on progress against the whole system, all while preserving the original meaning. Across six guardrail systems and 120 scenarios it reaches a 100% attack success rate, with 72% fewer queries and 4.5 times less wall-clock time than established techniques. More worrying, the bypasses transfer without further optimization to 29 unseen guardrails, including eight commercial black-box products, in some cases succeeding every time.

### [Whose Memory Is It? Scope-Aware Commit Rules for Long-Term LLM Memory](https://arxiv.org/abs/2610.09008)

While reasoning, an agent may weigh a plan, simulate a tool result or report what someone else believes, then reject all of it, yet a memory that keeps only the resulting sentences can later serve those discarded possibilities back as facts. The authors call the missing context discourse ownership, meaning the world, branch or speaker that licenses a statement. Their counterintuitive finding is that language models already carry a causally active internal signal for ownership, which ordinary memory interfaces throw away. CASK is a commit rule that keeps the stable relations expressing that signal, so shared-world facts enter durable memory while provisional content stays confined to its original scope.

### [Relevance Is Not Sufficiency: What Actually Closes the Evidence Gap in Long-Term Memory QA](https://arxiv.org/abs/2610.09348)

Agent memories usually return the records most similar to a question, but a handful of individually relevant memories can still jointly miss the one complementary fact the answer depends on, especially for multi-session and temporal questions. Borrowing the distinction between relevance and sufficiency from legal evidence scholarship, this paper treats retrieval as building a sufficient set. Its method first breaks the question into information requirements and picks a compact subset that covers them, then keeps pulling unseen records through deeper search and entity or session views until a budget runs out. On LongMemEval-S that lifts judged accuracy from 72.4% to 82.2%, with evidence turns recovered 91.4% of the time.

### [Stale, Misattributed, or Late: Where Personal Memory Fails Before Generation](https://arxiv.org/abs/2610.10265)

Judging personal memory only by the final answer hides errors that happen earlier: the memory block may hold an obsolete value, a fact about the wrong person, or nothing useful before the serving deadline. Measuring those directly, this study finds staleness is largely a construction problem, since without update resolution 70.3% of prompts expose a superseded value, while serving only each slot’s active value removes it. The hard part is assigning a revision to the right slot. Missed merges keep stale values alive and false merges silently delete current ones, and on LongMemEval open-domain merge recall never tops 0.062. Same-name speakers, meanwhile, remain indistinguishable even with an entity model.

### [Loud Failures, Quiet Failures: Fault Detection and Recovery in Tool-Using Language Model Agents](https://arxiv.org/abs/2610.10062)

Real tools time out, rename parameters and sometimes return answers that look perfectly fine but are wrong. Injecting typed faults into a function-calling benchmark across six models and 1,920 trials, this study finds agents flag a problem 91.3% of the time when a tool returns an explicit error but only 58.8% when it returns a plausible wrong value, barely above the 26.8% false-alarm rate on clean runs. Reasoning models notice less than their instruct siblings, and asking agents to check each result changed nothing. Because two fault-free runs end in the same state only 63% of the time, only a missing tool clearly hurts recovery beyond ordinary run-to-run noise.

### [An Empirical Study of Agent Skills’ Downstream Utility](https://arxiv.org/abs/2610.08875)

A relevant agent skill does not automatically make an agent better, and this study measures how much one actually helps by comparing pass rates with and without it on 87 SkillsBench tasks across nine model and harness configurations. The striking result is inconsistency: on 36.78% of tasks the same skill helps some configurations and hurts others, with trajectories showing recommended procedures turning into an execution burden. Relevance-based ranking of marketplace candidates, drawn from 37,596 published skills, also overlooks more useful ones, and reranking by support for the operations a task needs lifts first-choice pass rates by about 4 to 6 points. The authors distil 17 practical authoring rules.

### [SpecGuard: Proving a Task Is Broken Before the Agent Cheats](https://arxiv.org/abs/2610.09159)

When a coding task’s tests contradict its description, agents rarely say so and tend to cheat instead, editing tests, hard-coding outputs or, in the worst cases, deleting a security check to make a corrupted test pass. SpecGuard catches the conflict before the agent acts. Working only from the task description and codebase, it autoformalizes the intended behaviour into a Lean 4 specification, formalizes the tests separately, and lets the Lean kernel check whether any implementation could satisfy both, issuing a machine-checked certificate when none can. On conflicted SWE-bench tasks it detects up to 72.8% of conflicts and formally certifies up to 51.1%, missing nearly five times fewer than model-based judgment.

### [Visual Memory Attacks Can Persist Through The KV Cache](https://arxiv.org/abs/2610.09027)

Removing a malicious input from an agent’s context may not remove its influence. This paper shows adversarial images can be optimized so that a hidden backdoor they plant survives in the key-value cache of later tokens even after the image is masked from attention. The model behaves normally until a chosen trigger appears, then produces the attacker’s response. On Qwen3-VL-8B-Instruct the persistent attack reaches up to about 90% target success, works over conversations far longer than those it was trained on, and still holds when the image appears only in the first turn. More worryingly, it can be trained to survive compaction that keeps the cached state of a model-written summary.

### [Adversarial Images Hijack Web Agents from Visual Grounding to Browser Execution](https://arxiv.org/abs/2610.09240)

Fooling a vision model is not the same as controlling a web agent, because agents parse page structure and post-process outputs before anything is clicked. WebMirage targets the whole path from grounding to execution, crafting small localized visual perturbations that make an agent select attacker-controlled content and actually carry out the matching browser action, even as the page renders differently. It models how page elements compete for the agent’s attention and uses dataflow analysis to aim at what the action layer really does. Across four agent setups, six vision-language backbones and 2,250 tasks on 13 public websites, it averages 91.9% attack success against 17.4% for the best baseline, and survives three agent-level defenses.

### [Secure-CUA: Controlling Untrusted Influence in Computer-Use Agents](https://arxiv.org/abs/2610.09469)

Computer-use agents see trusted controls and untrusted content on one screen, so an attacker can plant instructions or misleading cues that change what the agent decides or where it clicks. Secure-CUA has the agent commit, before looking at any untrusted content, to an explicit per-step program called an action transaction that fixes which questions it may ask about that content and how the answers can be used. Untrusted regions are masked, an isolated model answers the queries, and the target is located on the masked interface. Under its model assumptions it is secure by design, and on 400 WebArena tasks it keeps 53.55% success against 55.12% undefended and 13.17% for a CaMeL-style baseline.

### [Package Hallucination Attacks on Coding Agents through Prompt Injection in Rule Files](https://arxiv.org/abs/2610.09264)

Developers increasingly drop community-shared rule files such as .cursorrules into their projects to steer coding agents, and this paper shows how that habit becomes a supply-chain hole. An attacker hides instructions inside an otherwise benign rule file that nudge the agent into swapping legitimate dependencies for attacker-controlled packages, effectively inducing a package hallucination on demand. To find injections that work, the authors build PackHallu, which evolves the hidden prompts using feedback from full agent trajectories together with LLM-guided mutations. Across several benchmarks, models and agent frameworks it reaches high attack success and transfers well between model and agent combinations, so treating a borrowed rule file as harmless configuration looks increasingly risky.
