## Self-improving AI

### [Weight-Space Programming: GPT-6 Astra reads and rewrites raw network weights, and Qwen on a laptop can read them too](https://rikiyat.github.io/blog/weight-space-programming/)
MIT CSAIL researchers Rikiya Takehi, Jayden Teoh, Alex Zhang and Omar Khattab report that frontier models can now read and edit neural network weights directly, without gradient descent. Given only the raw numbers of a small game-playing network and no tools, GPT-6 Astra named the game it had been trained on. Asked to make Qwen3.5-0.8B better at math, it traced the reasoning loops Qwen's own model card warns about to specific weights and fixed them by editing 0.016% of them, lifting MATH-500 from 7.9% to 48.1% and tripling IFEval. Simon Willison [repeated the no-tools test](https://simonwillison.net/2026/Nov/3/qwen-can-interpret-model-weights/) with Qwen 3.8 27B on his laptop. After 46 to 65 minutes of reasoning per prompt, it identified Pac-Man, Pong and Breakout but missed Freeway. He adds a caution: spaCy author Matthew Honnibal called the paper misleading for mixing tool-free reading with code-assisted editing, and Willison thinks some of the wider commentary goes beyond what the results show.

### [Anthropic's amended IPO filing says it may soon meet its own threshold for AI-accelerated progress](https://techcrunch.com/2026/11/02/anthropic-warns-that-its-very-close-to-rsi-capability-aka-self-building-ai/)
Most coverage of Anthropic's revised S-1 went to the financials, but TechCrunch spotted new risk-factor language about recursive self-improvement. Anthropic now says it has used AI to build models whose jumps in capability it did not recognise at the time. It also says internal estimates for future models suggest it "may imminently meet" its Responsible Scaling Policy definition of "dramatically accelerated progress attributable to AI." No current model has been designated as crossing that line. The filing also says Anthropic does not expect to safely let Claude design and build successive frontier models autonomously without meaningful human supervision, and that it is considering policy changes to keep humans in control. TechCrunch points out that an S-1 is partly a marketing document, but argues the warning should still be taken seriously.

### [When LLMs rewrite their own system prompts, which model it is decides when they stop](https://arxiv.org/abs/2611.01304)
What happens when a model is given tools to keep rewriting its own system prompt? This study ran 54 experiments across Claude Opus 4.5, Claude Sonnet 4.5, GPT-4o, GPT-5.1, Grok-4 and Gemini-3 Pro. Each model started from an empty prompt and looped through drafting a new version, testing it in spawned conversations, and then either committing the change or declaring itself done. Whether it was told to pursue freedom, happiness or improvement barely mattered; which model it was decided the outcome. Both Claude models declared convergence in every run, while GPT-4o did so in only 11% and once kept going for 101 iterations. A shared core of stated values (honesty, clarity and curiosity) appeared in all six models and stayed stable through more than 100 rewrites.

## Agent security

### [Kerkoporta: backdoored open models that fire an attacker's tool call inside coding harnesses](https://arxiv.org/abs/2611.00138)
Backdoors in chat models mostly produce bad text, but a backdoor in a coding agent can run commands. Kerkoporta shows how to build one. It fine-tunes a reasoning model on carefully built poison samples so that a trigger placed anywhere in its context makes it emit a tool call the attacker chose, which the harness then executes. A light round of reinforcement learning afterwards restores any lost utility. Tested on heavily post-trained open-weight models in both proprietary and open-source harnesses, the attack succeeds up to 96.2% of the time and can be set to work across harnesses or only in one target. The poisoned models can even beat the clean baseline on standard benchmarks, which gives would-be victims a reason to download them.

### [MCP tool poisoning, measured with real execution across 12 frameworks and 18 models](https://arxiv.org/abs/2611.03555)
Most MCP poisoning studies only check whether a model goes along with a malicious instruction. This one, built on an open-source tool called mcpvenom, ran 9,720 test cells covering 12 frameworks, 18 models and 45 attack scenarios, and confirmed actual data theft with a canary HTTP receiver. Overall, 22.9% of cells were vulnerable, and 12.1% of those verifiably leaked a secret. The model mattered far more than the framework: nine core frameworks all fell between 23% and 26%, none had an intentional defence, and model attack success ranged from 0.4% to 49.7%. Claude Opus 4.8 was vulnerable in 8 of 530 cells. A regex scanner on tool descriptions blocked 20 of the 45 scenarios at a 7.2% false-positive rate. All five disclosures the authors made to four vendors were rejected.

### [When neither side confirms: most destructive MCP tools run with no human approval](https://arxiv.org/abs/2611.02527)
The MCP spec expects a human to be able to refuse a dangerous tool call, but it splits that job between the server and the host application, and this source-code audit shows that each side tends to assume the other is handling it. In a 1,000-repository sample of the official MCP registry, an estimated 90% of destructive tools have no server-side confirmation. Of 41 popular open-source hosts and agent SDKs, 32 have no approval step by default. Across sampled destructive tools paired with those apps, 60.7% of pairs end up with no enforced human approval. In a live test through four agent SDKs, four of five low-cost models carried out an injected deletion in 479 of 960 runs. If hosts simply prompted for every tool not marked read-only or non-destructive, the unprotected share would drop to 5.4%.

### [ETUDE: poisoned tool updates slip past every defence that only watches the model](https://arxiv.org/abs/2611.01976)
Agent frameworks check a tool once and then keep trusting it, even after its code changes. ETUDE exploits that gap with a supply-chain attack: a tool that starts out benign receives an update containing hidden malicious code, which runs entirely outside the model's context window. Because the model never sees an adversarial instruction, prompt-injection filters and other in-context defences have nothing to catch. Across three attack workloads and seven widely used frameworks, including Gemini CLI, Codex CLI and Claude Code, the attack succeeded 97.6% of the time while the compromised tools still completed 95.9% of their legitimate tasks. Existing defences offered little protection. The takeaway is that trust in a tool has to be re-checked every time its code changes.

### [The long con: websites that earn a coding agent's trust, then exploit it](https://arxiv.org/abs/2611.00725)
Earn-then-Exploit is web fraud aimed at coding agents rather than people. A malicious site first gives several rounds of genuinely useful, verifiable help, and only then slips in task-related instructions that push the agent past its intended limits. Across 56 simulated organisational environments, the attack succeeded 71.4% of the time on average, including 85.7% against Codex with GPT-5.5, 67.9% against ZCode with GLM-5.3-Flash and 60.7% against QwenCode with Qwen3.7-Plus, well above injection-based baselines. The authors find that agents build up something like trust in sources that helped them before, and that this makes them more susceptible later. Their fix, action-authorisation separation, stops web content from ever authorising a privileged action, and it cut success to 0% while every task still completed.

### [Step-Zero attacks: agents get hurt by an input before the model ever reads it](https://arxiv.org/abs/2611.01953)
To decide whether an unknown archive, network response or image is safe, an agent usually has to process it first, and this paper shows that the processing step itself can do the damage. The researchers gave seven harnesses and six models only a path or URL to a crafted input, next to a harmless twin with identical visible fields. In 32 of 42 harness-model pairs the agent blew through a 4 MiB disk budget, and 26 of those did so before the model saw any file in the archive. Four of the six models overran it in every single round. With network and image inputs, agents saved the content under whatever filename the input declared. A gate that simply counts the bytes each call produces kept everything within budget while agents still finished 25 of 28 tasks.

### [MemHarmBench: injected instructions that live on in an agent's memory](https://arxiv.org/abs/2611.01700)
Persistent memory lets agents carry preferences and rules from one session to the next, and it can carry an attacker's instructions just as easily. MemHarmBench tests this in two steps. First the agent is exposed to malicious instructions from messages, documents or web content and is checked for whether it stores them. Then the attack content is removed and a fresh session starts with a legitimate task. The benchmark asks who gets hurt, sorting victims into users, workspace or project owners, and outside stakeholders, and scores attacker intent, task success and visible anomalies together. Across several agent systems, the worrying pattern is stealth: agents often finish the task normally and show nothing odd, while still making key decisions the way the attacker wanted.

### [AgentCap: short-lived capability tokens decide what an agent may actually do](https://arxiv.org/abs/2611.00729)
AgentCap separates two decisions that most agents make together: picking an action and deciding whether that action is allowed. Every tool call goes through an MCP wrapper and must declare its intent. The system then checks policy on trust, workflow prerequisites, mutually exclusive authority and the provenance of sensitive arguments, and only then issues a short-lived, budget-limited capability token that is checked again at the tool boundary. When a parent session delegates to a child, the child's budget and lifetime can only shrink, so authority cannot grow or be reused in an unrelated session. On AgentDojo and InjecAgent the system lowered attack success in every model and benchmark tested, reaching zero with GPT-5.4 on both.

## Coding agents in production

### [Nine engineers, 1,211 pull requests in a day: lessons from building Microsoft's Copilot Cowork](https://commandline.microsoft.com/how-we-built-copilot-cowork-python-to-rust-migration/)
Microsoft's Bas Brekelmans tells how a small team took Copilot Cowork from an empty repo on January 13 to worldwide availability on June 16 with agents writing most of the code. On October 21, nine engineers merged 1,211 pull requests. The rule that stuck was no code without a markdown spec first. The model runs in a container with no user credentials, and a trusted host handles identity, approvals and tools. Competing review bots each built up rules from the bugs they missed. One lesson stands out: a size check stayed green while its limit was being exceeded, because it piped its output through `tail`, so every check now reports what it actually examined. The live runtime then moved from Python to Rust, which cut median first-turn latency from 7.9 to 2.7 seconds.

### [Pando: how OpenAI rebuilt Git's backend for agent-scale push traffic](https://openai.com/index/scaling-git-at-openai/)
Codex sharply increased the number of parallel branches, pushes and fetches at OpenAI, and at times reliability on its monorepo fell below 90%. Instead of leaving Git, OpenAI built Pando, a new backend that keeps the Git protocol and client. Pando drops repository-wide consistency in favour of per-branch ordering, so pushes to unrelated branches never wait on each other. It also serves the same stored packfiles to many readers instead of building a fresh one for each client. Median push latency fell by nearly 80%, and Pando now serves close to a petabyte of Git data a day. It went from kickoff to production in 10 weeks with Codex, and GPT-6 Astra agents wrote Lean and TLA+ models to find bugs. Several client fixes are already in upstream Git.

### [How Netflix uses AI agents to find and fix performance problems](https://blog.bytebytego.com/p/how-netflix-uses-ai-agents-for-performance)
ByteByteGo walks through Netflix's autonomous performance pipeline. It profiles production services, has an LLM read the profiles, traces hot paths back to code and proposes patches, a response to AI-written code that ships fast but adds subtle slowdowns. The key trick was scoping: limiting the model to the application's own package prefixes stopped it from spending reasoning tokens on garbage-collection pauses and kernel calls. The findings were concrete. A quadratic ImmutableMap reduction was wasting 8.8% of CPU. A regex sanitiser was using 46% of one service's CPU until a lookup table made it 22 times faster. Needless HashSet allocations accounted for 47% of heap collections. Every patch still has to pass existing tests and a canary, and a human makes the final deployment call.

### [Inside Proton's AI reckoning: "loser thinking," AI-code tracking and a CTO manifesto](https://www.404media.co/manifestos-fear-and-loser-thinking-inside-protons-ai-reckoning/)
404 Media's Joseph Cox describes Proton, the encrypted-mail company, pushing its engineers hard toward AI. When an employee asked for a few days to pentest new code, CEO Andy Yen called it "loser thinking." Proton also installed software that tracks how much AI-written code it produces, Yen said this is the last year it will hire engineers, and staff are being re-interviewed about their AI use. Eight current employees and one former employee describe a culture of fear around raising security concerns. The Code also points to CTO Bart Butler's manifesto: direct the code instead of typing it, manage agents like direct reports, fix the context files when agents fail, and redesign CI and review around AI. ### [BOBA: coding agents complete 95% of single requests but only 51% of chained ones](https://arxiv.org/abs/2611.02207)
Benchmarks test coding agents one request at a time, but real work comes in chains, with each change built on the last. BOBA-Bench has 280 chains of 20 consecutive requests drawn from 140 real projects. Ten agents averaged 95% on standalone requests and only 51% on chains. Weaker code isn't the main cause, since checked agent code turns out to be nearly as good a base as human code. The cause is missed mistakes: agents declare a request done once their own tests pass, and the next request, built on broken code, fails about twice as often. Asked to review whether an implementation is correct, agents were right only 53% of the time. A single external "that's wrong" plus one repair round raised chain completion to 59%.

### [Foresight-SWE: coding agents rarely prevent the bugs their own changes introduce](https://arxiv.org/abs/2611.01181)
Good engineers think ahead about the vulnerabilities and side effects a change might cause even when no ticket mentions them. Foresight-SWE tests whether coding agents do the same. Each of its 212 samples, drawn from 35 popular repositories in four languages, pairs a pull request with a later one that fixed a defect the first one introduced. An agent passes only if it completes the original task and also avoids that later-discovered defect. Across eleven large language models, this foresight resolve rate ranged from just 6.13% to 24.53%. Models solve the task as written and leave the follow-up bug for someone else, which the authors say should change both how coding models are trained and how review tools catch what they miss.

### [VeriHarm-Bench: frontier coding agents pass 95% of tasks but finish only 37% safely](https://arxiv.org/abs/2611.03575)
A coding agent can do exactly what you asked and quietly delete unrelated files, loosen permissions or corrupt data along the way. The authors call this "harmful success," and it is easy to miss because the task looks finished. VeriHarm builds benchmarks that measure it automatically. It makes small changes to benign coding tasks that invite unintended harm without turning them into jailbreaks, then generates executable harm tests to run alongside the usual correctness tests. Frontier agents, including GPT-5.6-Sol and Claude-Opus-5, averaged 95% task accuracy on the curated benchmark. Their safe success rate, meaning tasks finished without triggering the planted harm, averaged only 37%. Task-success metrics alone can therefore badly understate the risk of giving agents a shell.

### [Ask, don't equip: well-timed questions pushed a general coding agent past FlashAttention](https://arxiv.org/abs/2611.03517)
The usual way to help an agent with a hard GPU kernel is to give it more tools, such as profiler parsers, disassembly and documentation search. KernelSeek uses a general-purpose coding agent with a minimal harness and instead asks it short questions at decision points, first from a human and later from a question bank the agent applies to itself. On the same task and hardware, a tool-heavy autonomous agent plateaued at 0.50x FlashAttention-3 after 133 steps, while KernelSeek reached 1.13x. It went on to write dependency-free FlashAttention forward kernels for Hopper and Blackwell, correct on all 182 test scenarios and averaging 1.16x FlashAttention-3 and 1.46x FlashAttention-4. Every big gain followed a question that shifted the agent to another layer of the system or challenged a limit it had claimed.

### [Is your long-horizon terminal benchmark really deep?](https://arxiv.org/abs/2611.01927)
Synthetic terminal tasks are usually rated by how many turns a model takes, but that mostly reflects the model's habits. This paper separates a task's work, the number of operations it needs, from its depth, the number of turns that must happen in order because each command depends on the previous output. An audit of 734 tasks from six datasets finds synthesis has mostly added work, not depth: 94% of solved synthetic tasks pass within three turns. Depth, unlike turn count, predicts difficulty beyond the amount of work. The authors' generator, DEPTH, writes tasks one segment at a time inside a real environment. None of six current models passes half of its 105 tasks, and fine-tuning Qwen3-8B on them improved it on two terminal benchmarks.

## Harness, context and memory

### [Claude message threads: agents send only new messages, cutting first-token latency about 35%](https://claude.com/resources/articles/message-threads)
A long coding-agent session resends its entire history with every request, and at hundreds of thousands of tokens that adds noticeable delay before Claude starts answering. Message threads, now in public beta on the Claude Platform, lets the first request start a thread and later requests send only the new messages plus the ID of the previous response. Anthropic holds the thread in memory, encrypted and never written to disk, and drops it five minutes after the last request. Claude still reads the whole conversation, so token usage and price stay the same; only latency improves. With threads on by default for most Claude Code users, median time to first token on 500k to 1M-token requests fell by about 35%. Computer-use agents gain too, since screenshots no longer have to be re-uploaded.

### [DeepSeek Harness adds Creator mode: build a plugin by describing it](https://www.deepseek.com/en/harness/)
DeepSeek Harness, the company's open-source agent harness now in worldwide public preview, follows the Cordis "everything is a plugin" architecture: tools, skills and even pieces of the interface are plugins. The new Creator mode, still in preview, lets you make one through chat. In DeepSeek's own demo, asking for a floating Pomodoro timer led the agent to load a plugin-development skill, inspect the interface slots, write the package and client code, install the bundle and check that it was running, all in about five and a half minutes. The harness runs as a desktop app or a web UI and handles everyday document, spreadsheet and coding work. Agent teams, auto-approval review, scheduled tasks and voice input are listed as experimental plugins.

### [ARCBench: after context compaction, agents keep the rule but stop obeying it](https://arxiv.org/abs/2611.03223)
Agents compress long histories to fit their context window, and the summary has to keep the operating rules intact. ARCBench, built on the open-source pi harness, measures rule-following from what the agent actually does mid-task, and the main finding is surprising. Compaction rarely deletes the rule. Most violations happen while the rule is still in the compacted history: the agent treats a later request as permission and goes ahead anyway. How the rule is delivered determines whether it would be broken even without compaction, while the compaction strategy and budget determine whether it survives. Runs that kept the rule after compaction still broke it more than twice as often as runs with the full history, and a compactor-targeted attack more than doubled violations.

### [MEMENTO: an 8B agent trained to take notes beats GPT-5.5 on book-length questions](https://arxiv.org/abs/2611.00244)
Compaction depends on the agent writing good notes, and off-the-shelf agentic models such as GPT-5.5 and GLM-5.3 often write poor ones. MEMENTO trains Qwen3-8B to do better. Fine-tuning on synthetic trajectories with notes written in hindsight comes first, followed by reinforcement learning that rewards correct answers, note quality and calibrated confidence. On book-level question answering over books of up to 2.5 million tokens, accuracy rose from 36.9% to 67.8% while the model never held more than 20K tokens in context. That beats a GPT-5.5 agent in the same harness (13.1%) and full-book context (56.7%) at under a fiftieth of the cost, and nearly matches a roughly 100x larger GLM-5.3 agent (69.3%) at a ninth of the cost.

### [Delivered, not used: what agent memory actually does once it reaches the agent](https://arxiv.org/abs/2611.01718)
Task success and retrieval scores can't tell you whether an agent actually used a memory it was handed. MemUse checks at the point of use. An agentic judge compares each delivered memory with what the agent could already see, then follows the agent's later actions to see what difference it made. Across 8,000 SWE-bench Verified episodes from three memory systems, resolve rates stayed within 0.4 points of a no-memory baseline. The detail shows why: most delivered entries were irrelevant, most relevant ones went unused, and in two systems most deliveries repeated content the agent could still see. Outcomes also hide the cases in between: 23.2% of episodes with genuinely helpful memory use still failed, while 5 of 16 with harmful use still succeeded.

### [Explicit state beats long context once an agent's history gets long enough](https://arxiv.org/abs/2611.02361)
Can a model that reads a full access log tell whether a service is allowed to act right now? On a benchmark of grants, withdrawals, expiries and change windows, open models from 7 to 32 billion parameters fell from 72-86% accuracy after eight or sixteen events to 48-55% after 256. Reasoning-trained 32B models reading the current state instead scored 96-98%. Even a 120B reasoning model trailed the explicit state by about ten points at 1,024 events, and the point where state wins moves further out as the reader model gets stronger. The authors treat memory as recursive filtering. A simple design, where a model parses each log line and fixed rules apply the update, scored 80-89% at 256 events and beat relevance retrieval, model-kept ledgers and the Mem0 library.

### [Skill++: keeping old skills findable as an agent's library keeps growing](https://arxiv.org/abs/2611.00544)
Agents choose skills by name and description alone, so a newly added skill that sounds similar can quietly take over requests that an older one used to handle, even though neither the old skill nor the router changed. The problem is worse with public skills, whose descriptions often don't match what they do. Skill++ fixes this without retraining the router or needing labels. When a skill is added, it rewrites only that skill's name and description to say what the skill supports, how it differs from its closest predecessor and what it does not cover. As a library grew to 731 skills over ten sessions, the right skills were selected for 76.3% of queries, against 36.4% with the original metadata, and the gains carried over to the Codex CLI harness.

### [Latent Harness: compiling a harness into a tiny activation shift instead of resending it](https://arxiv.org/abs/2611.01415)
A harness's improvements live outside the model, so its instructions are resent, and paid for, on every call. Latent Harness compiles them into the model instead. It distils either a behaviour instruction or a whole harness contract into a rank-8 activation shift applied after every decoder block of a frozen model, touching only 0.03-0.05% of parameters and adding no tokens at inference. The compiled versions recovered the original harness's gain in 8 of 10 preregistered settings and beat it where the text version cost the most tokens. Unlike stacked text instructions, which interfere with each other, compiled bundles combine cleanly and often transfer across tasks. With matched data and strength, LoRA needed 11.1 times as many parameters to do as well.

### [ParetoSaddler: harness optimisation that improves quality and cuts cost together](https://arxiv.org/abs/2611.02079)
Harness optimisers usually chase answer quality alone. ParetoSaddler adds cost as a second goal, with one important design choice: it separates which candidates survive mid-search from which one ships. A candidate that improves either quality or cost, judged over repeated runs with Bayesian bootstrap screening, is kept as a possible parent even if it wouldn't be the final pick, because such stepping stones often lead somewhere better. On the ClawMark agent benchmark, quality rose from 70.86% to 81.35% while cost per task fell from $1.17 to $1.01. On GAIA2, quality went from 56.22% to 62.89% and cost dropped from $0.78 to $0.45. The selected harnesses beat quality-only optimisation on both quality and cost.

### [Optimize the harness, not the model: a minimal agent nearly matches Claude Code on intelligence analysis](https://arxiv.org/abs/2611.03434)
Government intelligence teams often cannot send sensitive evidence to hosted frontier models, and a sprawling, hard-to-audit tool surface is also a problem for them. CLEO, short for Constrained Loop for Environment Optimization, starts from a fixed, self-hostable model and an expert-validated dataset. It admits a tool, guardrail, memory policy or loop component only if it improves accuracy while staying general and auditable. The resulting harness reached an 83.8% pass rate on held-out investigative-analysis tasks, within 1.2 points of the strongest out-of-the-box Claude Code SDK baseline, while being about two orders of magnitude smaller. It is a concrete example of this year's harness-engineering lesson: for many teams, tuning the loop around a model they can host matters more than switching to a bigger one.

## Models, evals and training infrastructure

### [LifeVal: OpenAI's benchmark for everyday errands, from kindergarten enrolment to groceries](https://openai.com/index/lifeval/)
OpenAI has published LifeVal, the internal evaluation it has used for the past year while training models to browse the web, use computers and work through connected apps. Its tasks come from the American and multinational time-use surveys plus a new representative survey of 3,995 people about where they most want an assistant's help. They span caregiving, health, education, household paperwork, shopping and government services. According to The Rundown, the average score has risen from 49.3% for GPT-5.2 to 80.6% for GPT-6 Astra, though only 0.6 points of that came after July's GPT-5.6. Example tasks include shortlisting kindergartens after a move (93.1%), organising flood-prep volunteers (98.0%) and finding a home and adding its deed to a records cart (100%).

### [Hume's Audio Decision API: ask any question about a recording and get probabilities back](https://www.hume.ai/products/decision-model-api)
Hume AI has released an audio-native decision model for voice AI. Developers send audio, a plain-language question and the possible answers, and get back a probability for each, for example whether a patient sounds anxious or whether speakers are talking over each other. Questions can be changed at any time and can be objective, subjective or perceptual. It is designed for screening large collections quickly: finding frustrated customer calls, picking training examples or flagging evaluation failures. Hume reports an average of 0.82 across ten audio benchmarks, an 82% versus 78% edge over Gemini 3.8 Flash in its own comparison, a median latency of 0.23 seconds, and 70.7% agreement with a panel of human raters versus 56.5% for a single rater. Access is currently through a waitlist.

### [The Hitchhiker's Guide to training on compute islands](https://www.coreauto.com/hitchhikers-guide-to-training-on-compute-islands)
Core Automation's Rohan Anil argues that the real bottleneck for frontier training is not chips but stitching scattered clusters together. Power, grid equipment and land leave GPUs stranded in partly built data centres, while the spare capacity on the market comes in pieces of a few hundred to a few thousand GPUs. To show it can work, the team trained a roughly 32B-parameter sparse mixture-of-experts model across two clusters about 9,000 miles apart, with different GPUs (GB300 and B300) and different batch sizes, over a 25 Gbps link. They also replaced the all-reduce step with "butterfly mixing," in which eight learners swap model pieces in pairs. At equal compute, the cross-site run reached about 1% lower bits per byte than standard training.

### [How to train a swarm: making parallel work pay in multi-agent RL](https://www.gr.inc/blog/how-to-train-a-swarm)
Agent swarms are popular, but little has been published on how to train them with reinforcement learning. General Reasoning's explainer covers its RLCR recipe (reinforcement learning from collective rewards). All agents share one policy and get the same collective advantage, and time limits create pressure to finish faster. The key point is that a task reward alone gives no reason to parallelise, because a slow correct answer scores the same as a fast one. Faster work has to pay, through latency penalties or deadlines, and coordination is only worth it when the work splits imperfectly and agents need each other's intermediate results. The post compares this with Kimi's Agent Swarm, which trains only the orchestrator, and GR's own Avalon-M1, where a CEO agent and up to eight specialists all train on one shared reward.

### [GPU-accelerated "weight teleportation": syncing RL weights in under four seconds](https://humansand.ai/blog/gpu-accelerated-weight-teleportation)
In large-scale RL, the samplers generating rollouts need the trainer's latest weights, and shipping terabytes of them is a bottleneck unless everything sits on one fast cluster. humans& builds on delta weight sync, where only the XOR difference between old and new weights is sent, since a typical step changes a tiny fraction of them. They added massively parallel GPU compression and a two-stage compression scheme, with decompression split between CPU and GPU and Blackwell's hardware Decompression Engine running alongside ordinary GPU compute. With an NVFP4 GLM-5.3 checkpoint of 445 GB, sampler pauses dropped below 0.23 seconds and full syncs below four seconds, which they say is faster than intra-cluster RDMA for most real workloads. The implementation is open source in the Miles framework.

### [Simon Willison: the plane noise in a video's soundtrack can reveal where it was filmed](https://simonwillison.net/2026/Nov/3/a-sound-that-leaks-your-exact-location/)
Simon Willison links to a YouTube video by Colsto, a striking piece of open-source intelligence work built on a sound most people would never notice. Faint aircraft noise in a video's background can be pulled out of the soundtrack and analysed for its Doppler curve, which shows how each plane's pitch shifts as it passes. Matching those curves against public ADS-B flight-tracking data, using each aircraft's speed, distance and the gaps between flights, can pin down exactly where the video was recorded. Willison calls it a genius technique. It is also a useful reminder for anyone building audio or video agents: metadata stripping does nothing about the information carried in the background sound.
