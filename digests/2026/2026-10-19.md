## Agent memory

### [TEM: Temporal State Tracking Memory for Large Language Model Agents](https://arxiv.org/abs/2610.21900)

Memory that stores only the latest fact fails the moment a user says they moved house, because the old address still matters when someone asks where they lived last year. Temporal State Tracking Memory, or TEM, is a training-free answer: it keeps facts as versioned records linked to their sources, retrieves the relevant versions, puts them in source order and labels the older ones as historical before the answer model sees them. On 420 questions drawn from 600 sessions with 60 personas, key-entity hit rates reached 75.7 to 97.6 percent across four open-weight models, and simply adding the historical labels lifted overall hits by 17 to 56 points while using roughly half the tokens of session-aware RAG.

### [Memorilla: Latent Semantic Memory for LLMs](https://arxiv.org/abs/2610.21375)

Mem0 and MemoRAG are the usual yardsticks for agent memory, and Memorilla claims to beat both while spending almost nothing in the prompt. Instead of pasting retrieved text, it encodes documents once into reusable embeddings and then learns to gather query-specific information into just 16 'memory tokens' placed directly in a frozen model's input embedding space. It tops the baselines on five of eight benchmarks spanning personalization, long documents and knowledge-heavy questions; on FactKG it reaches 84.3 percent against 80.4 for full-context inference with 108 times fewer tokens for the source documents. In a TextWorld agent, it also curbed the habit of wandering back into rooms already explored.

### [Rethinking the Role of Tool Graph Memory in Multi-Turn Tool Use](https://arxiv.org/abs/2610.21571)

Tool graph memory sounds sensible: record which tool tends to follow which, and let past experience steer the next call. A careful evaluation on nine models and two benchmarks finds that it seldom beats baselines by a significant margin, and where it does, the gain costs more than twice the LLM calls. The unflattering discovery is that random guidance or none at all keeps most of the benefit, so the lift appears to come from extra computation rather than from memory, and even a correct suggestion often fails because the agent gives up without calling anything. Storing the same experience as plain textual insights does better with almost no extra calls, suggesting memory works best as a soft prior, not a script.

### [Same Context, Different Agents: A Behavioral Study of Semantic Layers, Orchestration and Compaction in Data Agents](https://arxiv.org/abs/2610.20959)

Data agents are often handed three context-engineering tricks at once: a semantic layer that describes the data, orchestration that splits work across agents, and compaction that condenses history. This study runs them alone and combined across seven models and 1,514 long-horizon tasks, and finds that agents without any of them fall into three behavioral types: investigators, premature answerers who never inspect the data, and early stoppers who give up. Each technique delivers its advertised benefit, but only turns it into accuracy for the group it matches. Orchestration helps premature answerers, yet makes some agents overconfident and costs five points, while compaction makes them repeat steps. The practical advice is to choose techniques by behavior, not by habit.

### [Writability and the Pathway: A Controlled Study of Knowledge Injection into Addressed Memory](https://arxiv.org/abs/2610.21553)

Writing new knowledge into a model's addressed memory is tempting because it offers a local, post-hoc edit surface, but a successful write need not generalize or leave unrelated behavior alone. This controlled study starts with frozen GPT-2 and moves on to production-scale Qwen and DeepSeek models, testing row-only against row-plus-projection updates, with and without anchoring. Projection updates raise natural-question target hits from about 5 percent to 22 or 29 percent, and anchoring reduces drift, yet strict answer scores stay at zero and lexical hits do not prove the memory is retrieving the right entity. Gradient writes can promote a designated first answer token, but zero-order variants barely manage it, so the evidence supports only bounded writing feasibility.

### [Learning from Interaction Experience via Localized Context Distillation](https://arxiv.org/abs/2610.21427)

Teaching a deployed model from its own experience is awkward because the lessons live in privileged context the student never sees at test time. Context distillation tries to bridge that gap, but off-policy versions train on teacher trajectories and suffer from exposure bias, while on-policy ones use student rollouts whose states often say nothing about behaviors the student cannot yet produce. Localized Context Distillation splits the difference: it finds the critical spans of a student trajectory that need revision, has the teacher regenerate only those spans from the student's own prefix, and trains on the rewritten segments. The result concentrates learning on the most informative states while keeping exposure bias low.

### [From Long Context to Selective Memory:A Survey of Memory-Centric Compression for Large Language Models](https://arxiv.org/abs/2610.21165)

Long context windows keep growing, yet this survey argues that the underlying pressure never leaves: every token still costs compute, storage and a decision about what to keep. It reframes prompt compression, KV-cache management, retrieval and agent memory as one memory-management problem, separating compute-active memory that takes part in the model's computation from compute-inactive memory that is stored, retrieved, updated or forgotten outside it. Offloaded and persistent KV caches sit in between as intermediate states. On that footing it lays out a vocabulary of operations, including writing, offloading, recall, eviction, consolidation and forgetting, giving a shared map for systems that are usually discussed in isolation.

## Agent harnesses, skills and context

### [ToolBottleneckBench: Measuring Tool-Agent Performance under Controlled Pressures and Fixed Harness Budgets](https://arxiv.org/abs/2610.21098)

A tool agent's score reflects its model and the harness running it, and ToolBottleneckBench tries to separate the two by holding synthetic enterprise tasks fixed while varying one pressure at a time: the tool catalog, the visible menu, the certified workflow or the encoding of returned records. Across 21 configurations, only the visible menu imposes a large penalty on the model, and that penalty tracks truncation at the completion cap; raising the cap sixteenfold erases most of it. Most failures end at a harness limit, and the failure record identifies the assigned pressure no better than a tool-call count does. The authors urge reporting pressure effects together with the budgets under which they were measured.

### [HPCAgent-Bench: A Framework for Sound Benchmarking of Code-Optimizing Agents, Harnesses, and Skills](https://arxiv.org/abs/2610.20673)

Coding agents are being asked to optimize code, yet most benchmarks fix one accelerator, language or harness, which makes it impossible to tell whether an added skill or tool repays its cost. HPCAgent-Bench offers 689 kernels across loop-level challenges, real HPC code and machine-learning models, each specified once in NumPy with C and Fortran references and judged externally on hidden fuzzed inputs to close the loopholes agents exploit. Its two new metrics, intervention efficacy and weighted token cost, compare paired runs. Agents reach up to 4.2 times speedup over automatic parallelization, but across 40 matched setups, interventions significantly change speedup only twice while changing token cost by up to three times.

### [OPRD: On-Policy Reminder Distillation for Long-Horizon Coding Agents](https://arxiv.org/abs/2610.21496)

Coding agents often fail not for lack of ability but because they ignore information already sitting in context, such as a constraint stated earlier or feedback from a tool. On-Policy Reminder Distillation tackles that by letting a teacher re-evaluate the student's own failed rollouts with reminders: a global one built from final-test diagnostics and turn-local ones that apply only to the next decision. Successful rollouts become self-imitation targets, while failures receive reverse-KL supervision from the reminded teacher. At inference the student runs with no reminders at all. On SWE-bench Verified, Pro and Multilingual, the approach lifts the average resolution rate of a Qwen3.5-4B base model by 11.3 points.

### [The Role of Agentic Instruction Categories for Code Generation: A Study of Five Python Libraries](https://arxiv.org/abs/2610.21421)

Files like AGENTS.md are now standard for telling coding agents about a project, but nobody has measured which kinds of instructions actually help. This study tests five categories, namely repository overview, function description, implementation detail, testing and reconstruction steps, across all 31 combinations, using Gemma 4 and GPT-5.4 on five human-written Python libraries. More instructions do not reliably mean more tokens, and although most generated libraries compiled, functional correctness stayed low: no Gemma 4 variant passed every test, while 12.99 percent of GPT-5.4 variants did. Function descriptions gave Gemma its best partial-pass rate, whereas reconstruction steps gave GPT-5.4 its best full-pass rate, so the right instructions depend on the model.

### [CausalEvo: Causal Skill Self-Evolution for Health LLM Agents](https://arxiv.org/abs/2610.21016)

Health agents that accumulate reusable text skills, such as calculation criteria and formula units, face a quiet danger: a faulty generalization that gets retained will propagate errors. CausalEvo treats skill retention as a causal question, swapping skills in and out against shared background rules, scoring each swap on the same feedback cases and using least squares to turn the differences into relative skill values, with incumbents favored on ties. On six MedCalc-Bench-Verified tasks with 120 held-out cases it reaches 60.0 percent accuracy, against 55.8 for SkillOpt and 51.7 with no skills, while consuming 55.6 percent fewer training tokens across the recorded configurations.

### [ExecWeave: Cross-Layer Execution Provenance for Observable Agentic Software](https://arxiv.org/abs/2610.21146)

When an agent launches a process or touches a file, application traces say what it meant to do while operating-system telemetry says what the machine did, and joining them risks pinning an effect on the wrong principal. ExecWeave is a local-first system that builds a typed execution graph from both sources, keeping separate artifacts and recording attribution, inference and causal status for every link. Its optional correlator proposes a command-to-process bridge only when a bounded search finds exactly one compatible process, and the authors are careful to say that uniqueness is not proof of causation. The design points toward agent observability that is honest about what it actually knows.

### [Probe-and-Resume: When and How to Evaluate Agent Execution](https://arxiv.org/abs/2610.21088)

Test-time search is supposed to help agents by exploring alternatives and letting a critic pick promising branches, but in terminal-based computer-use environments the authors find that the Monte Carlo tree search configuration they tried does not significantly improve success. The critic is the weak link: observations omit state needed for judging, and intermediate states say little about eventual success, so critics rank continuations only slightly better than chance. Probe-and-Resume therefore invokes the critic only at nodes the agent believes are final, and gives it read, write and execute access to a fork of the computer's current and initial state so it can probe and verify by actually running things.

## AI security

### [From Detection to Decision: Calibration and Deferral for Prompt-Injection Detection](https://arxiv.org/abs/2610.20907)

Prompt-injection defenses are usually scored as binary detectors, yet deployed applications must decide whether to allow, block or escalate. This evaluation of a probabilistic decision model, two Llama Prompt Guard 2 classifiers and an LLM judge on 47,611 held-out examples finds the judge strongest overall with an AUROC of 0.897, followed by 0.871 for the decision model and 0.757 and 0.714 for the Prompt Guard variants. The model's native probabilities do not consistently beat post-hoc calibrated classifier scores, and temperature scaling improves calibration without improving discrimination. At a one percent false-negative target, every gate-reviewer system escalates over 91.8 percent of inputs, so calibrated confidence alone does not make a reliable security decision.

### [Matoi: Selective Revalidation of Consequence Evidence for Agent Authorization](https://arxiv.org/abs/2610.21394)

Authorizing an agent's actions repeatedly can be expensive, and Matoi explores when previously checked evidence can safely be reused. It separates reusable consequence evidence from current execution authority and from durable occurrence history, so signed requests, live grants, quotas and uncertain outcomes remain separate obligations that must still be satisfied. In a 1,440-cell study, reuse trimmed complete lifecycle cost by 3.49 percent in JavaScript and 1.79 percent in Python, with larger savings when combined with compact representation. On a frozen AgentDojo Banking mapping, the governed strategies kept five benign transfers exact and refused the reused attack-plan cases, though the tools are scripted synthetic ones, not autonomous agents or a real bank.

### [PROBE: Learning to Audit Policy Compliance in Tool-Using LLM Agents](https://arxiv.org/abs/2610.22124)

Capability benchmarks measure what agents can do and red-teaming measures harmful text, but neither checks whether a tool-using agent follows the policies it was given on pricing, privacy, confirmation or safety. PROBE trains LLM auditors that play realistic users, interact with a deployed agent through multi-turn tool-mediated dialogue and hunt for policy violations whose effects may emerge only after several turns or surface in downstream systems. The authors formalize auditing as a two-player Markov game with a composite reward that balances finding violations against exploring efficiently. It treats compliance as something to test adversarially, which matters as agents move into consequential settings.

### [Context Injection and Long-Horizon Reliability: Separating Duplicate Recognition, Local Processing, and Counter Tracking](https://arxiv.org/abs/2610.20633)

Long-horizon failures are usually reported as end-task success, but this study scores three components of a 400-step ledger task step by step while the model's own answers are re-injected into context. On Qwen3-8B, duplicate-recognition errors rise late in the episode, from 0.0019 to 0.011 per step across step 200, while a counter makes no mistake in 8,000 steps and local processing stays stable. The striking result comes when a block of irrelevant content is inserted before each step: the counter then fails in all 20 seeds on each machine, against none without it. Reliability decay, in other words, depends on which sub-skill is stressed and on what the context contains.

### [AgentPerturb: Evaluating LLM Agent Robustness under Controlled Interaction Perturbations](https://arxiv.org/abs/2610.21624)

Real-world agent tasks are noisy, so AgentPerturb sorts perturbations along two axes, what is altered and how, and applies them on APEX-Agents and Toolathlon to frontier models. Perturbations consistently degrade performance, with the dominant weakness varying by environment. Trajectory analysis shows that agents rarely notice altered inputs and often carry corrupted information forward without verification, and successful perturbed runs can cost substantially more compute. The authors conclude that training should cover diverse noise and reward verification, uncertainty awareness and recovery, and they release a benchmark-construction pipeline. It is a useful lens on tool-output poisoning, even though the perturbations are not framed as attacks.

### [StepSafe: Learning Timely Intervention with Context-Aware Safety Reasoning](https://arxiv.org/abs/2610.20960)

Agent safety is sequential: whether an action is safe depends on earlier actions, tool outputs and disclosures. StepSafe trains step-level guardrails to intervene at the right moment, using a method that compares responses sampled at the same prefix and rewards the action that fits the stage: continuing before risk is visible, asking while clarification can still avert harm, and stopping before harm becomes irreversible. A self-distillation stage additionally credits the reasoning behind each decision, with the model acting as its own teacher that sees step annotations and mined rules. The focus on timing, not just whether a trajectory is eventually unsafe, is what distinguishes it from post-hoc guards.

## Engineering blogs

### [Simon Willison: Inline rendering with document.currentScript](https://simonwillison.net/2026/Oct/17/document-currentscript/)

Simon Willison points to a small browser trick from Lean Rada that leans on the document.currentScript property: drop a tiny inline script into the page and it replaces itself with its own output once the page loads, so a script that writes the current year simply becomes the number 2026. Define a shortcut function that wraps the same call and you effectively get a tiny template language with no build step or framework. It is a neat bit of minimalism that fits the recent run of single-file tools Willison has been building.

### [Simon Willison: llm-echo 0.5](https://simonwillison.net/2026/Oct/18/llm-echo/)

With a new LLM release in the works and pull requests to test, Willison revisited llm-echo, a debug plugin that provides a fake model which involves no LLM at all and simply repeats the prompts fed to it. The new version makes the simulated token usage counts account for tool calls, system prompts and reasoning tokens, so it can stand in for a real model when testing usage reporting. A one-line uvx command shows it echoing a prompt with a thinking option and printing token counts of 2 input and 24 output.
