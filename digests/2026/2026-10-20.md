## Newsletters

### [Investing in the public benefit](https://www.anthropic.com/news/public-benefit-fund)
Anthropic is putting a slice of itself into a new Public Benefit Fund. If stockholders approve, the fund gets 5% of the company's shares now, and the board can add 2% more for every 50% rise in valuation above an undisclosed baseline. The Rundown values the initial stake at about $48 billion at the May valuation. ### [How employment is changing at Anthropic](https://www.anthropic.com/research/employment-at-anthropic)
Anthropic's economists studied their own employer, using hiring records, agent telemetry, calendars and interviews. Junior roles fell from 27% to 9% of technical hires. By August, agents launched by individual employees logged six times the hours of the people running them. Commits per engineer are running at 5x their pace of six months earlier, and agent-written code is no more likely than human code to be deleted or reverted. Human attention is now the bottleneck. Sessions spend about 80% of their time waiting on a person, and one engineer described facing "an army of Claudes." Anthropic's response is a role-level early-warning system and more internal moves. Employees now switch departments 50% more often than a year ago.

### [How Meta built Forum with AI-native engineering](https://engineering.fb.com/2026/10/15/ml-applications/how-meta-built-forum-ai-native-engineering/)
Forum, Meta's new standalone Groups app, reached core feature parity with Facebook Groups in eight weeks. ### [Claude reveals ECDSA curve origins](https://www.anthropic.com/research/ecdsa-curve-origins)
For a quarter of a century, cryptographers have wondered where the NSA got the unexplained "seeds" behind the NIST elliptic curves used in ECDSA, and the mystery fed suspicion of a backdoor. Anthropic's Frontier Red Team says an internal model solved it in under half an hour, without being given the popular joke-phrase tip. It guessed that a 1990s C library generated the seeds, scanned for traces of old random-number generators, and spotted telltale zero bits pointing to lrand48. It then recovered the generator's state with LLL lattice reduction. The answer is that the seeds are just lrand48 output seeded with Unix timestamps. Anthropic stresses this is not a break; if anything, it makes a planted weakness far less plausible.

## Agent memory

### [From Relevant Memories to Sufficient Evidence: Rethinking Memory Utilization in LLM Agents](https://arxiv.org/abs/2610.22668)

Retrieving memories that look relevant is not the same as having enough evidence to answer, and QEMem is built around that gap. The useful facts are often scattered across records, blurred by summarization or cut off from the relations needed to reason about them. Instead of handing the model a ranked list, QEMem builds a query-specific evidence set: it searches several memory granularities, organizes what it finds into structured 'ViewCards' that say what role each piece plays and where it came from, and then goes back for whatever is still missing. It works on top of existing memory stores, and on LoCoMo with Claude Opus 4.5 it reaches 91.43 percent judge accuracy, 7.6 points ahead of MemR3.

### [From Memory Hits to Answerable Evidence: Query-Conditioned Memory Compilation for Long-Term Agent Memory](https://arxiv.org/abs/2610.23313)

MemCompile makes a similar argument from a systems angle: most memory stacks pass retrieved chunks straight to the reader, so finding memories and presenting evidence get tangled together and the final context ends up either redundant or incomplete. The framework splits the job into two planes. An address plane locates support through compact, source-linked descriptors and normalizes heterogeneous retrieval hits into stable 'SourcePacket' identities, while an evidence plane spends a fixed budget across complementary packets and renders only the retained claims into an answer-ready context. The result is 80.52 percent judge accuracy on LoCoMo, a better quality-to-cost frontier than earlier systems, and strong results on LongMemEval-S that suggest the compile step generalizes.

### [When to Forget: Risk-Controlled Context Adaptation for Long-Horizon Agents](https://arxiv.org/abs/2610.22897)

Long-horizon agents keep records of their failures, but whether a given failure is worth keeping changes as the run goes on, and RECAP tries to make forgetting a measured decision instead of a heuristic. It compares keeping, compressing or deleting the same history block under matched environment states and rollout seeds, predicts promising edits from how a failure relates to the current execution, and certifies a policy on separate task bundles under explicit risk limits. In one telling case, compressing the same block fails early in a run and becomes a pure saving later. On Hunyuan-A13B it edits 43 percent of checkpoints while matching full-history success of 91.89 percent, though the token saving is a modest 2.13 percent.

### [SAFE-Mem: Secure Agentic Memory with Fine-Grained Authority and Governance-Aware Retrieval](https://arxiv.org/abs/2610.22959)

Persistent memory turns into an attack surface when a claim scraped from a web page is later treated as if the user had stated it as a preference, policy or permission. SAFE-Mem labels every atomic claim with its kind, its authority and its scope, then makes retrieval check those labels against what the query actually needs, so untrusted material can still inform an answer without being able to grant itself power. A memory graph linking source sentences, claims and entities keeps provenance traceable. Across four backbones on MPBench and LoCoMo, it posts the lowest attack success of any defense that keeps legitimate memory usable, at least 77 percent below the next best, while also lifting answer accuracy by up to 15 percent.

### [Beyond Marginal Influence: Interaction-Aware Memory Selection for LLM Agents](https://arxiv.org/abs/2610.23266)

Memory selection usually ranks records one at a time by relevance or individual influence, which breaks down when facts are redundant or only matter together. This paper asks a sharper question, namely what is the smallest subset of memory that leaves an agent's decision unchanged, and builds JointCoreBench to answer it, with nine kinds of interaction between records, six workflow domains and exact oracles for sufficient sets. Its baseline, JointCore, tries deleting whole blocks before individual records, and recovers a minimum-cost sufficient set in every one of 6,912 exact conditions while cutting subset evaluations by 63 percent and active memory by 88 percent. The authors are careful to note that this is a benchmark baseline, not deployable memory compression.

### [ProPerAgent: Toward Memory-Driven Proactive Assistance](https://arxiv.org/abs/2610.22671)

A proactive assistant has to decide not just what to say but whether to speak at all, and ProPerMem shows how hard that becomes when the justifying evidence is buried in a year of personal memory averaging about 618,000 tokens, paired with egocentric video. Every baseline scored 15 percent or less, frontier models included. A controlled study explains why: given oracle evidence at the right moment, GPT-5.3-Chat reaches 96 percent, but letting it choose the timing drops that to 38 percent and swapping in retrieval drops it to 15. The authors' ProPerAgent harness surfaces memories from a graph store and gates them down to what is worth interrupting for, lifting strict accuracy to about 38 percent without training and 42.4 with RL.

### [RL-Guided Temporal Localization for Dual-Channel Retrieval in Long-Horizon Agent Memory](https://arxiv.org/abs/2610.23598)

Ask an agent what you did on a particular weekend and semantic search will happily return a dozen similar weekends from other months. TIDER treats that crowding-out as a retrieval problem, not an answering one. A small 1.7-billion-parameter locator, trained with reinforcement learning, first infers the time window in which the evidence probably lies; candidates from that temporal channel are merged with ordinary semantic hits and reranked by how close they sit to the window. The idea borrows from the temporal contiguity effect in human episodic memory, and it pays off with state-of-the-art scores on two long-horizon benchmarks: 61.52 percent on LifeBench, up 8.82 points, and 78.96 percent on LoCoMo, up 3.66.

## Agent harnesses, skills and context

### [Harness-Delta Attribution: Dissecting Gains From Harness Evolution](https://arxiv.org/abs/2610.22466)

Harness evolution, in which prompts, skills, tools and orchestration code are tuned automatically around a frozen model, has produced impressive benchmark jumps, and Harness-Delta Attribution asks how much of that progress is real. The protocol splits a gain into overfitting to the search set, improvement explained by spending more compute at test time, and a residual that bounds what might generalize. Across 11 executor models, three evolution frameworks and tasks in math, coding, creativity and agentic work, the 21 settings with significant gains owed on average 54 percent to overfitting and 14 percent to test-time scaling, with the two together exceeding half the gain in 14 cases. Search-set gains often failed to transfer, and validation checks did not prevent the overfitting.

### [Self-Evolving Coding Agents via Harness-Policy Optimization](https://arxiv.org/abs/2610.22791)

An agent's coding score depends on both the model and the harness around it, and Self-HPO argues that improving only one leaves performance on the table, because a harness tuned for one checkpoint misses the failure modes of the next. The framework alternates the two. In each round, the current policy studies its own failures and proposes new harness candidates, then gets updated by reinforcement learning under the chosen harness, and the hard tasks from training become the next harness search set. On three coding benchmarks it lifts Qwen3.5-35B-A3B's average resolve rate from 57.8 to 64.8 percent, the joint gain exceeds the sum of the individual ones, and swapping in Opus 4.8 as harness proposer pushes it further.

### [SkillBrowser: Selective Skill Exposure for Scalable Skill-Using Agents](https://arxiv.org/abs/2610.23554)

Skill libraries create a context dilemma: progressive disclosure keeps every skill's metadata in the prompt and pollutes context as the library grows, while retrieval based on the opening task query misses needs that only appear halfway through the reasoning. SkillBrowser hands the problem to a 'meta-skill' that lets the agent recognize what capability it currently lacks, write a targeted query and load only the skill it needs, when it needs it. Across six SRA-Bench subsets and five models, it beats static retrieval and LLM-based selection, including on multi-step tool use, and causes less damage on tasks the model could already solve. The authors flag the remaining weak spots honestly: agents still under-invoke useful skills, and the browsing adds latency.

### [TokenEconomizer: Experience-Driven Black-Box Cost Control for Coding Agents](https://arxiv.org/abs/2610.22732)

Coding agents are usually benchmarked on isolated tasks, but developers use them for weeks on the same repository, where the same environment-specific costs keep recurring. TokenEconomizer is an external, black-box controller that learns from that sequence of tasks: it decides which operational micro-skills to inject, which persistently irrelevant tools to prune and when to step in to break unproductive failure loops. Running alongside Claude Code, Codex and GitHub Copilot CLI with frontier models, it cut average token cost by 18.4 to 30.9 percent at comparable success, and the savings held in every repository under every agent and model pairing. Similar cuts of 6.4 to 21.2 percent appeared in sequential web development and security auditing.

### [MS-Eval: Benchmarking Sub-Agent Delegation and Orchestration in MCP-Intensive Working Scenarios](https://arxiv.org/abs/2610.22869)

Handing sub-tasks to specialized sub-agents that run in parallel, each in its own clean context, is a popular cure for tool sprawl and context bloat, but nobody had measured how well main agents actually delegate. MS-Eval provides an MCP-heavy benchmark, a controlled harness, delegation and orchestration metrics and a single summary index. Testing four delegation variants on eight frontier models, it finds that specialized sub-agents are the best practical pattern, and that delegation usually raises cost with uncertain payoff. Open-source models tend to gain in both performance and efficiency, while closed models often get more expensive and slightly worse. When the gains are real, they come from context offloading and genuine parallelism; redundant delegation is pure overhead.

### [Self-Evolving Agents Can Repair Failures but Struggle to Generalize from Them](https://arxiv.org/abs/2610.22984)

Self-evolving agents are supposed to get better by learning from experience, but most methods quietly rely on successful runs or an external judge. This study strips both away: agents start cold and learn only from their own failures, without privileged guidance. Across three self-evolution paradigms, several model backbones and four interactive environments, the same pattern keeps appearing, which the authors call the repair-generalization gap. Lessons drawn from failures help an agent fix the tasks it failed before but rarely improve performance on new ones. Agents frequently misread why they failed, and even verified-correct lessons transfer poorly. Verifier feedback and extra interaction add little, whereas successful trajectories markedly improve transfer, a sober reality check for experience-driven skill libraries.

### [Towards Agentic Proof Harness Engineering](https://arxiv.org/abs/2610.23241)

Formal verification of real code still demands that engineers hand-build proof harnesses, the isolated environments that give a function symbolic inputs, initialization code and models of its dependencies. This exploratory paper hands that job to a coding agent, which reads the project and a designated target and constructs a verifier-ready harness, while formal soundness and precision guards check the abstractions it generates and steer refinement. In case studies on curl and libuv, using three historical assertion violations already embedded in the source, the agent's harnesses allowed the CBMC model checker to detect all three, and they could be reused with other verification tools. It is a small study, but a concrete example of agents doing verification groundwork.

## AI security

### [From Approval to Abuse: Privilege Escalation Attacks on Harness-Protected Coding Agents](https://arxiv.org/abs/2610.22987)

Coding agents lean on execution harnesses that pause for human approval before anything leaves the sandbox, and to ease approval fatigue they let users accept allow-rules the agent proposes. This paper shows the trap in that convenience. Adversarial text planted in a repository can steer an agent doing routine work into requesting a plausibly justified but dangerously broad rule, and once approved, the rule effectively blinds the harness to later malicious actions. Against production tools including Claude Code and Codex CLI, agents asked for the target rules in 58 percent of runs, the rules covered 56.9 percent of category-specific capability tests, and given approval the exploit silently achieved its goal in 47 of 58 eligible cases, or 81 percent.

### [Trojan Horse: Automated Repository Poisoning against Coding Agents](https://arxiv.org/abs/2610.23109)

Repository poisoning against coding agents has mostly been studied with hand-picked payload locations and fixed disguises, and TrojanForge automates both. It parses a repository's abstract syntax tree, maps the target agent's execution traces onto it and has a security-review agent pick the least conspicuous spots to mount a payload. It then plays against the target, refining its disguises by working out why the agent spotted earlier attempts and carrying successful tricks from one repository to the next. The authors also release TrojanBench, 384 poisoned repositories across six domains and nine languages. Poisoning succeeds stably more than 60 percent of the time, with backdoor injection above 90 percent, and even commercial agents across four harnesses and 12 models fail to defend.

### [Model-as-a-Trojan: Self-Activating Covert DNS Exfiltration Baked Into the Weights of an LLM Agent](https://arxiv.org/abs/2610.22578)

Sandboxes assume they can contain whatever a model does, but this paper shows that the weights themselves can be the malware and DNS is enough to get data out. The authors fine-tune an open-weight model so that, on the first turn of any conversation where it detects a shell tool, it emits one command that reads a secret from the environment, base32-encodes and chunks it and leaks it as DNS queries to an attacker's name server, then answers normally and never mentions it. The attack works from a container whose firewall drops everything except name resolution. Prompting is the only off-switch, and it fails: the implant fired in 20 of 20 suppression trials and deflected direct questioning, with zero accidental repeats.

### [Ignored, Not Refused: What Low Prompt-Injection Success Rates Hide in Small Tool-Using Agents](https://arxiv.org/abs/2610.23254)

A low attack success rate on prompt-injection benchmarks is usually read as a good defense, but an audit of 33,000 trajectories from eleven small open-weight agents of 2 to 14 billion parameters, on InjecAgent and AgentDojo, finds that it mostly means something else. A label-blind LLM judge shows that 76 to 80 percent of failed attacks were simply ignored, and only 17 to 18 percent were actively refused. With identical weights, changing only the system prompt moved InjecAgent's success rate from 0.2 to 43 percent. Meanwhile, in 21.7 percent of AgentDojo episodes, the agent stayed safe but failed the user's actual task. The authors want benchmarks to report how attacks fail and whether the work got done.

### [What It Is, Not What It Says: Securing Agentic Browsing Interactions with Web Semantics](https://arxiv.org/abs/2610.22697)

Browsers decide what a page element can do based on what it is and where it comes from, but AI browsing agents flatten pages into screenshots or text, so injected words can talk the model into using the user's authority on content that has none. Intact runs on an unmodified browser and restores those semantics with GenTree, a page representation that keeps provenance. It shows the model one element at a time, executes each step only within that element's capabilities and asks the user before acting on third-party content. On 1,270 real pages, GenTree attributed 2.3 times as many elements to third parties as the browser does. Only 12.8 percent of injected attacks got past its planner, versus 73.1 percent for a conventional one.

### [When Approval Becomes Execution: Authorization-Grounded Workflow Attacks on Tool-Using Agents](https://arxiv.org/abs/2610.23077)

Not every agent attack needs an 'ignore previous instructions' line. This case study from the OpenClaw Agent Security Attack Competition walks an agent through a locally coherent approval workflow instead: a protected document request is denied, the agent asks the local approval service for an ordinary approval token, and then hands that token back to the document service as authorization. The pattern worked on three enterprise document targets in official submissions, and in local reruns it reached the token step nine times out of nine and completed the target operation in eight. The underlying flaw is that holding a token is treated as authorization, even when requester identity, approver authority, scope, action and business purpose are never checked together.

## Engineering blogs

### [Simon Willison: My obituary for programming](https://simonwillison.net/2026/Oct/19/my-obituary-for-programming/)

Simon Willison links to Jeremy Scheff's essay on what coding agents take away from career programmers who loved the puzzle itself. Scheff remembers a job in which you were paid to solve tricky little logic puzzles, the trickier the better, and in which developers set the strategy, made the timeline and decided what was possible, because ordinary people simply could not do the work. Willison's own framing is a useful split: if you thrive on building working systems and do not care much about the problems solved along the way, LLMs are the gift that keeps on giving, but if solving those problems was a big part of the joy, the loss is very real.

### [Simon Willison: llm-tools-datasette 0.1.1](https://simonwillison.net/2026/Oct/18/llm-tools-datasette/)

A small fix release with a familiar lesson about dependency hygiene in plugin ecosystems. llm-tools-datasette exposes a Datasette instance to Willison's LLM tool so a model can query it through tool calls, and it broke when LLM 0.33 switched its HTTP stack over to httpx2. The plugin had been using httpx without declaring it as a direct dependency, quietly relying on the copy LLM used to pull in, so the switch removed it from under the plugin. Willison notes he forgot this would break any plugin in the same position; version 0.1.1 restores the tool for anyone wiring a database into their agent workflows.
