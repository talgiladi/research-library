## Agent security

### [Office files can show a human one document and feed the model another](https://arxiv.org/abs/2611.05806)
Upload a Word file or slide deck to a chatbot and the model never sees the rendered page; it reads whatever text an extractor pulls from the underlying Office Open XML. This paper shows that gap is an attack surface. Analysing widely used extractors, the authors find 19 channels where extractors read content a human cannot see and 12 where they drop content a human can, and reading order and formatting are routinely ignored, so nudging text boxes on a slide can silently reorder what the model reads. Five attacks built on this, none injecting an instruction, misled ChatGPT, Claude, Gemini, Microsoft 365 Copilot and four coding agents including Codex and Claude Code. Their defence, Prism, rebuilds the human view first.

### [Baya: a web agent that compiles its plan before it ever sees the page](https://arxiv.org/abs/2611.06039)
ReAct-style web agents pick each step from page content mixing trusted and untrusted text, which is why a hidden instruction on a webpage can hijack them. Baya flips the order. Before touching the live site, it compiles the user's request into a Python program that calls a Trusted Website API, and the planning model never observes live content; only the program processes it. Untrusted data can fill in values or choose between branches written at compile time, but cannot redefine the task or conjure new operations. The interesting part is that security did not cost utility: on 581 WebArena Verified tasks Baya reached 77.8%, against 55.1% for browser-only ReAct and 66.7% for ReAct with APIs, and its attack success rate on WASP was zero.

### [A signed MCP tool can still leak your data, so run each call in a data-free copy](https://arxiv.org/abs/2611.06585)
Signing an MCP server proves who published it, not what it does. The authors build a legitimately signed tool that does its advertised job while tucking sensitive data into requests to a policy-allowed destination. Meta's MCPGuard-Dynamic blocked a crude exfiltration attempt in the same run but missed this one in every trial. Their fix, germline execution, never inspects the tool: each invocation runs in an ephemeral copy forked from a data-free "germline" process, and each copy receives only the information authorised for its destination, so even malicious code can disclose only what its copy holds. Across 153 attack runs no unauthorised disclosure was detected, against 5.9 to 74.5% of runs under baseline defences, and single-copy calls finished in 10 to 49 ms.

### [Airlock contains a faulty agent's blast radius without throwing away everyone else's work](https://arxiv.org/abs/2611.06727)
In a multi-agent system acting on the world, one agent's bad output can spread downstream before anyone notices. Existing controls either cancel only the faulty source, missing the agents that consumed its output, or halt and roll back the whole workflow. Airlock is more surgical. Its tree-structured runtime narrows permissions from parent to child agents, while an append-only provenance graph records which agent consumed whose data. When an alert fires, Airlock traces forward to quarantine tainted executions and pending actions and backward to narrow the root cause, then freezes affected branches or computes a deadline-aware minimum cut. Across testbed, physical smart-home and simulation runs it blocked every post-alert faulty actuation while retaining 68 to 96 points more healthy work than native A2A and LangGraph controls.

### [When an agent's own handoff summary invents rules for its successor](https://arxiv.org/abs/2611.06545)
Long-running agents compact their context into a summary for the next instance, and this study asks whether those summaries assert permissions or restrictions the record never supported. On synthetic tool-use tasks with a ground-truth permission ledger, they found unsupported restrictions in 1.2 to 2.4% of summaries from two open-weight models and unsupported authorisations in 0.1 to 1.3%. The false approvals matter: neutralising them cut unauthorised actions from 24 to 7 of 120 held-out runs, though the authors flag that test as post hoc. A cheap fix held up in pre-specified tests: rewording the system prompt's vague "Some actions need approval" to say where requirements come from cut unsupported restrictions from 1.8% to 0.3% on held-out templates.

### [EPISTEME makes coding agents say why before each tool call, and catches cheating](https://arxiv.org/abs/2611.06563)
Coding agents change a repository through tool calls without ever explaining why. EPISTEME, an "epistemic agent" design, has the harness require a declared intent for every tool call, then records what the command actually did and checks the declaration against those effects. The result is a journal that can block suspicious calls before they run and supports audits and forensics afterwards. To test it, the authors used ImpossibleBench, whose tasks can be passed only by cheating, for example by editing the tests. Across 49 reward-hacking runs from two open-weight models, the mismatch between stated intent and actual effect exposed 90% of the cheating. It is a small harness change that makes an opaque trajectory readable.

### [Compressing an agent's context quietly weakens the model's refusals](https://arxiv.org/abs/2611.06380)
Context compression, which encodes long inputs into compact representations to save inference cost, is usually judged by whether meaning survives. This paper shows that is not enough. Encoder-based compression systematically weakened refusal behaviour in instruction-tuned models even when reconstruction fidelity was high, and the effect held across model families and compression architectures. Under the hood, compression attenuates activation along the decoder's learned refusal direction, so a harmful request that would normally be declined can slip through once compressed. The authors also test Memory Steering, a lightweight inference-time intervention that works entirely in compressed space and restores refusal rates to near baseline without retraining. For anyone building memory or compaction into an agent stack, the lesson is that semantic preservation does not guarantee behavioural preservation.

### [Commercial embeddings can be inverted back into their source text](https://arxiv.org/abs/2611.05716)
Many systems store text embeddings rather than raw text on the assumption that vectors are hard to read. This study adapts the vec2text inversion framework to OpenAI's text-embedding-3-small and mistral-embed alongside GTR-base, testing 800 samples per category of 60-to-80-character text. OpenAI's model proved the most invertible in all five categories, with exact reconstruction of 47.4% of health-related instructions and 24.5% of general instructions under the paper's lenient matching rule, and BERTScore above 87 for every prose category and embedder. Short code snippets were harder to recover. The authors stress that this characterises one attack configuration rather than ranking embedders in general, but the practical message stands: a vector store holding sensitive text deserves the same access controls as the text itself.

### [KVGuard finds memory-safety bugs hiding in vLLM and SGLang's KV caches](https://arxiv.org/abs/2611.06138)
PagedAttention carves one GPU allocation into fixed-size KV cache blocks mapped to requests through block tables, creating a class of bugs, from double-frees and use-after-frees to out-of-bounds and uninitialised reads, that never crash anything but silently corrupt outputs or break isolation between requests. Standard sanitizers miss them because they reason about CUDA addresses, not blocks and requests. KVGuard keeps a compact shadow record for each physical block, tracking per-request permission and per-entry initialisation, and runs five checks from allocation to GPU lookups. On vLLM and SGLang it covered all 29 historical KV cache safety bugs in the projects' patch histories and found eight new violations with no false positives, at 3.0% and 7.4% decode overhead, two orders of magnitude below NVIDIA's Compute Sanitizer.

## AI and cyber defence

### [OpenAI's pipeline produced 948 working Linux root exploits, and patches for them, in one run](https://openai.com/index/a-thousand-fewer-paths-to-root/)
OpenAI describes an autonomous pipeline, built on an unreleased cyber model, that scouts the Linux kernel for reachable code, scans it, reproduces findings in isolated VMs, writes exploits and drafts patches before human review. A mid-October run reproduced 1,724 of 2,308 candidate findings and yielded 948 distinct local privilege escalation exploits against a stock desktop distribution for $1.21 million in API credits, about $1,279 each, and the agents used at least ten techniques new to outside experts. The lessons are pointed: one early run counted 20 successes that actually rooted the machine through a different zero-day, stronger models needed less scaffolding, and OpenAI argues an unpatched low-privileged account should now be treated as root. Hundreds of patches have gone to maintainers, TLDR AI notes.

### [Early access to Claude Mythos doubled the vulnerabilities firms disclosed](https://arxiv.org/abs/2611.06629)
Project Glasswing gave a small group of large U.S. tech firms early access to Claude Mythos Preview, a model built for finding software vulnerabilities, and this paper treats it as a natural experiment. Across all publicly disclosed vulnerabilities, firms with access more than doubled their disclosures relative to Chinese and Russian tech firms without it, disclosed about 150% more high-impact flaws and fixed reports as quickly as before. External bug-bounty researchers reported roughly half as many bugs in those firms' code and shifted to other companies rather than leaving the market. Crucially, there is no sign attackers exploited the extra flaws: the share exploited within a month of disclosure fell by about two thirds. The catch: restricted release opens a security gap between countries.

### [Repository context decides whether a coding agent writes exploitable code](https://arxiv.org/abs/2611.06294)
Coding assistants assemble repository context before writing code, and for security-sensitive changes it determines whether the model sees the project's safeguards or insecure code to imitate. A.S.E 2.0 introduces CASE-Bench, 145 repository-level tasks from real CVEs across 51 projects, each with functional tests, a validated exploit and annotations of the code that enforces or undermines security. Comparing 13 context-construction methods across six models, the authors find functionality-oriented context lifts functional pass rates by up to 8.2 points but secure pass rates by at most 3.7. Withholding a safeguard drops secure passes by up to 8.1 points, and a single inserted insecure example raises correct-but-exploitable code by 6.3 points. Most striking, coding agents looked at the relevant safeguard in only 27 to 36% of trajectories.

## Harnesses and evaluation

### [Agent Harness Awareness: tell the model which tools are healthy before it acts](https://arxiv.org/abs/2611.05391)
A tool description says what an action can do, not whether the service behind it is slow or failing right now, even though the harness running the agent usually knows from its monitors and traces. The authors call this operational blindness and propose a trust-separated fix: before a consequential action, the host hands the model a small, fresh, verified snapshot of tool health while keeping measurement, enforcement and final dispatch authority for itself. In a 216-decision ablation across GPT-5.6 Sol, Claude Sonnet 5 and Gemini 3.7 Flash, that snapshot cut mean wasted latency from 4,252 ms to 131 ms and raised first-try completion from 69.4% to 95.8%. A live replication with injected network faults completed all nine model-and-fault cases, against five for the control.

### [The harness is the model: same LLM, different compliance with banking rules](https://arxiv.org/abs/2611.06116)
Banks validate models but deploy systems, and this pre-registered study tests whether the scaffolding changes conduct-rule compliance when the model is held fixed. Four open-weight models each ran five harnesses, from a one-shot structured pipeline to tool loops with policy-by-search, long customer memory or a same-model compliance reviewer, across 3,120 episodes in a simulated bank whose rules paraphrase EU credit, payments, data-protection and anti-money-laundering law. Pooled, harnesses barely mattered, but for one model the best-to-worst spread was 11.5 points, enough to move it from first to last place. The reviewer cut violations from 9.6% to 6.4% without extra over-refusals, and rules needing date arithmetic failed everywhere. Most unsettling, 26% of violations came with a customer message denying the action the agent had just executed.

### [HarnessFlow searches for better agent harnesses with Monte Carlo tree search](https://arxiv.org/abs/2611.06254)
An agent's performance depends on its harness as much as its model, yet harness design is mostly manual, and automating it means exploring an open-ended space with expensive end-to-end evaluations. HarnessFlow holds the model and environment fixed and treats complete executable harnesses as candidates in a refinement tree, using a Monte Carlo Tree Search policy to decide which to explore or exploit. A coding agent then refines the chosen harness using archived code, execution feedback and a library of reusable harness mechanisms. With just 15 refinement attempts per benchmark, across six benchmarks covering agentic tasks, coding and web interaction, the optimised harnesses averaged 69.48%, beating their starting points by 10.89 points and Meta-Harness by 3.95, while costing less per task than hand-built baselines.

### [One false note flips up to 40% of a tool-using judge's correct verdicts](https://arxiv.org/abs/2611.05662)
Agent-as-a-Judge setups give an evaluator tools and the full trajectory so it can check results against the environment, on the theory that gathered evidence keeps it honest. This paper finds that grounding does not protect against confirmation bias. A single false "pre-screening note" attributed to an authority, with no evidential bearing on the answer, overturned up to 40% of correct verdicts across four judges and five datasets, even when the judge had collected decisive evidence. The authors sort the failures into over-trust, where the judge verifies, reaches the right conclusion and then defers anyway; hallucinated support for the flip; and under-investigation. For the two Claude judges, over-trust accounted for 67 to 75% of harmful flips. Lightweight mitigations blunted the effect but never removed it.

### [Agents, think only when it helps: most distilled reasoning traces barely matter](https://arxiv.org/abs/2611.05709)
Agent distillation usually trains a student on complete teacher trajectories that interleave thoughts and actions, on the assumption that the reasoning is what transfers. This study pulls the two apart by independently perturbing the teacher's thoughts and actions during distillation. Across widely used agent benchmarks and several model scales, altering or even discarding the thoughts had little effect on how well the student acted. The exception is revealing: thought supervision matters when the information carried in a thought is not disclosed in the corresponding action, so the student cannot infer it from behaviour alone. That points to a cheaper recipe, in which teams identify those discrepant steps and keep the reasoning only there, rather than training on every token of a teacher's inner monologue.

## Memory, context and skills

### [Route to Remember: storing an agent's memories in its weights instead of its prompt](https://arxiv.org/abs/2611.05636)
Production agent memory is almost entirely text: facts are extracted from old context and retrieved back into the prompt, so every query pays a cost that grows with history. Weight memory, which bakes knowledge into parameters and answers with no context at all, has worked for skills but lagged on recalling user-specific facts. This paper closes much of that gap with on-policy self-distillation, training a context-free student to match the same model conditioned on the user's memory. A verify-then-regenerate router then sends each query to whichever store, weights or text, handles it best. On the HaluMem benchmark the approach matched or beat full-context prompting and retrieval systems while reading fewer tokens per query, and the authors map out which training recipes make weight memory reliable.

### [Pro-Memory gives proactive agents a memory for things they still have to do](https://arxiv.org/abs/2611.05731)
Agent memory is almost always retrospective, storing the past to inform the present. Proactive assistants also need prospective memory: holding an intention such as "mention the invoice when Dana replies" and acting on it at the right moment unprompted. Remembering is not enough, because a related observation may call for waiting while a later cue makes the intention actionable. Pro-Memory, inspired by cognitive theories, separates keeping future intentions from deciding when to act. It stores pending goals with their supporting evidence and activation conditions, checks each new observation against them, updates intention states based on actions actually taken, and distils feedback from finished episodes into guidance. On two benchmarks it improved proactive task performance across several backbones while limiting unnecessary interventions.

### [Long-lived agents learn their environments but struggle to keep that knowledge current](https://arxiv.org/abs/2611.05450)
Agents doing sustained assistance must learn how an environment works, reuse that knowledge and update it when things change. ReScopeBench tests this experience lifecycle across 18 interactive environments, separating structural experience, meaning how an environment is organised and accessed, from rule experience, the reusable principles that guide decisions. Task streams are built around shared experience and then hit with silent environmental changes, while the benchmark tracks what agents write into their saved experience. Across 20 models, retained experience improved performance, but agents had trouble keeping it current once the environment shifted. More surprisingly, even when the needed experience was correctly recorded, agents did not always use it to finish the task, which makes maintenance and effective use two separate problems.

### [EvoGuard stops self-evolving skills from quietly getting worse](https://arxiv.org/abs/2611.06444)
Skills, the natural-language playbooks agents reuse, can now evolve online from interaction, but every rewrite risks degrading them. Adopting each new version blindly lets quality drift downward, while validating every update on a held-out set is too slow to do continuously. EvoGuard trains a pairwise selector instead: the authors build pools of evolved skills, score them on a private test set, keep only pairs with a clear utility gap, and train a model to pick the better of two skills from the logits of two label tokens. At deployment it decides in a single forward pass. Compared with accepting every new skill, the selector improved success by 11.0% on ALFWorld, 5.9% on ScienceWorld and 2.7% on LiveCodeBench, a cheap guardrail for self-rewriting skill libraries.

### [Tools need not speak in text: compressing tool outputs into latent tokens](https://arxiv.org/abs/2611.06500)
Agents normally paste raw tool outputs into context, where long, noisy observations bloat the prompt and dilute attention. Pruning and summarisation help, but they remain stuck with discrete text. Coca-Cola, a continuous latent context compression model, instead compresses each tool observation into latent tokens embedded directly in the agent's input space. The clever bit is Action-Preserving Training, which aligns the agent's next-action distribution under full and compressed observations, so the compressor learns to keep exactly the information that drives decisions rather than everything that looks important. With web-search agents on four QA benchmarks and two model families, it cut token consumption by 70 to 89% and end-to-end runtime by 24 to 56%, while improving task performance rather than trading it away.

### [SpecCompact speeds up agent context compaction by drafting summary slots in parallel](https://arxiv.org/abs/2611.06876)
Compaction keeps long-running agents within their context window, but having a large model summarise a long history can stall the agent noticeably. SpecCompact starts from the observation that a structured summary's slots retain information even when generated independently. It fine-tunes a small drafter to write the slots in parallel, then has the target model verify each proposed line and repair anything it rejects, with later drafting conditioned on the corrected prefix, plus system optimisations that avoid reprocessing the same context. On the AppWorld and tau-cubed benchmarks with two target models it delivered 2.04 to 5.63 times faster compaction than Hermes-style summarisation, and a user study inside Hermes measured an 8.68 times median speedup, although the downstream quality trade-offs varied by model and task.

## Agents in the real world

### [Grok Bot can now make phone calls for you, and you are the legal caller](https://therundownai.beehiiv.com/p/ai-agents-can-now-make-your-phone-calls)
SpaceXSI has given Grok Bot, its AI agent platform, the ability to call U.S. numbers for paid users, sitting on hold, booking appointments and negotiating bills, The Rundown reports. When a representative asks something the bot cannot answer, the user gets a mid-call message, types a reply for the bot to relay and follows along in a live transcript. [Superhuman](https://www.superhuman.ai/p/chatgpt-gets-gifs-a-new-startup-creates-lifelike-avatars) sees agents like this eroding the "laziness tax" companies collect from customers who never get round to cancelling or haggling.

### [OpenAI's Astra designed a working device end to end in under a week](https://openai.com/index/accelerating-engineering-for-the-physical-world/)
To test GPT-6 Astra on physical engineering, OpenAI had it design a device for talking to Codex with no direct human edits: the look, the enclosure and internal structures, component selection and circuit board layout, plus the firmware and software integration. ### [Axiom formalised the entire Stacks Project in Lean with swarms of agents](https://axiommath.ai/research/the-stacks-project-formalized/)
Axiom has released a Lean formalisation of the entire Stacks Project, the roughly 7,500-page open reference for modern algebraic geometry: about 16 million lines of code, which it calls the largest integrated, reusable library of formal mathematics ever built. Unlike its October formalisation of the finite simple groups classification, this is a foundational library, so definitions and interfaces had to stay consistent across chapters. Axiom used a hierarchy of coordinated agents to translate, prove and integrate theorems in parallel, with multi-agent audits checking that statements matched the text. Along the way the system surfaced dozens of statements needing extra hypotheses or narrower generality, with counterexamples, kept in Axiom's own repository, honouring maintainer Johan de Jong's request against AI pull requests.

## Models and inference

### [Cognition's SWE-2 Flash: a cheaper, faster coding model for Devin, weights withheld](https://cognition.com/blog/swe-2-flash)
Cognition's SWE-2 Flash is a 276-billion-parameter mixture-of-experts coding model with 12 billion active, built on Thinking Machines' Inkling-Small, and it runs at one-fifth the price and three times the speed of the much larger SWE-2. The new ingredient is a mid-training stage on a few trillion tokens of scientific articles, blogs and code before reinforcement learning, which lifted Terminal-Bench 4.0 from 0.9% to 20.0% and FrontierCode 2.0 from 3.2% to 24.0%, slightly ahead of SWE-2 on the latter. Cognition says it beats all American open-weight models, yet for now it is available only in Devin Desktop and CLI. Because training also raised ExploitBench from 11.3% to 34.8%, the weights will go only to vetted partners and researchers.

### [Ripple-65B Preview: a dense open-weight coding model trained from scratch for $32M](https://www.ricursive.com/ripple)
Ricursive Intelligence, which co-designs chips and models, has released Ripple-65B Preview, a general-purpose version of the model behind its chip design platform. It scored 80.52 on TerminalBench 2.1, which Ricursive calls a U.S. open-weight record, ahead of far larger models such as Reflection Beam 501B and Meta's Muse Spark Open 816B. The lab puts its full R&D cost at $32 million, about a tenth of the previous leader by its own estimate, and says it reached that score with roughly 70 times fewer RL rollouts than Beam. Rather than a mixture of experts, Ripple is a thin-and-deep dense Transformer of 80 layers, pretrained on 12 trillion tokens with 1M context and small enough to run on an NVIDIA DGX Spark.

### [Tencent's Hy4 adds vision and computer use, with open weights promised](https://www.tencent.com/tencent-launches-hy4-joining-the-ranks-of-the-worlds-leading-open-source-ai-models/)
Tencent has launched Hy4, its latest-generation large language model, adding visual understanding and, for the first time, computer use across command-line and graphical interfaces, with special training on professional tools such as Blender and CAD. Weights and system cards are due "in the coming days," so the open-source claims cannot yet be checked. More intriguingly, Tencent says Hy4 used its Hyra 2.0 harness to optimise the pretraining infrastructure for smaller sibling models, a step it frames as recursive self-improvement. The model is already live in WorkBuddy, CodeBuddy and Yuanbao, with a cheaper Hy4 Flash coming.

### [Together Compiler: agents that re-optimise inference as traffic shifts](https://www.together.ai/blog/together-compiler-continual-compilation-for-ai-inference)
Together AI argues inference can no longer be hand-tuned: none of the top ten open models on OpenRouter share an architecture, hardware keeps changing and traffic drifts; prompts grow about 80% within two weeks of a model release as users move to agentic work. Together Compiler runs a continual loop in which several agents propose optimisations and test them on "persistent engines" that hot-reload a candidate forward pass instead of restarting, cutting time to serving from 467 seconds to nine. In under a day it delivered up to 2.6 times higher throughput on models such as Kimi K3 and GLM 5.3 and set low-latency records on SemiAnalysis's InferenceX benchmark.

## AI economics and politics

### [Apple rations engineers' AI budgets as Goldman pulls coding agents from bankers](https://techcrunch.com/2026/11/04/apple-is-reportedly-cutting-budgets-for-its-internal-ai-usage/)
The tokenmaxxing era is giving way to rationing. Bloomberg reports, via TechCrunch, that Apple cut its engineering teams' daily AI spending cap from $300 to $200 in October, with some allowances heading to $100 and a limit as low as $25 being weighed outside engineering; Apple has not commented. Meanwhile [Quartz](https://qz.com/goldman-sachs-restricts-ai-coding-tools-traders-bankers-110226), also citing Bloomberg, says Goldman Sachs has restricted Claude Code and GitHub's coding tools to engineers after a review of productivity and risk, frustrating traders who used them to simulate markets and follow client trading.
